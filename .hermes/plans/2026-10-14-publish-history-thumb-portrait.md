## 一、需求与验收

**需求原文**：应用的发布页，发布记录列表的缩略图，目前是横版尺寸，改成竖屏的尺寸显示（3:4比例）。

**验收判据**（全部可机械断言）：

1. 发布记录页**四个断面**的缩略图宽高比均为 3:4：列表视图、网格视图、720px 窄屏、460px 窄屏；
2. 比例不靠"某个整数看起来对"成立，而由 `width === height × 3/4` 推导成立；
3. 窄容器下 flex 收缩不得把比例漂回横版（`flex-basis === width`）；
4. 回归锁在实现被退回横版时**必须**变红；
5. 明暗双通道像素基线刷新，且刷新前完成归属取证与人工审核。

## 三、技术决策

### 决策 1：四处断面各写一组数值，而不是抽成变量

**选择**：四处各写 `width/height/flex-basis` 三个值，比例由注释标明推导关系。

**理由**：本组件已有大量硬编码尺寸（`.record-preview`、`.record-stats`、`.selection-summary`
等都是字面量），引入一个 `--thumb-w/--thumb-h` 变量会与既有风格不一致（P3 pragmatic）；
且四个断面分处普通规则 / `.grid-view` 覆盖 / 两个 media query，变量在 media query 里还得再覆盖
一次，收益接近零。真正的保障是回归锁。

**放弃的替代**：CSS 自定义属性 + `calc()`。它能做到"改一处全断面生效"，但本任务的诉求是
"四处都得是 3:4"，而变量方案在 media query 内仍需逐个覆盖 —— 复杂性换了更少的机械可断言性。

### 决策 2：宽度由高度推导，而不是高度由宽度推导

**选择**：`width = height × 3/4`，即先把高度定为"看起来合适的高度"，再算宽度。

**理由**：竖版改造的视觉锚点是**高度**（卡片纵向节奏由缩略图高度决定），高度定了宽度才是
被导出的量。反过来（宽度定、高度算）会让高度出现 133.33 这类非整数值，渲染出亚像素模糊边。

**放弃的替代**：直接写"比例对就行"的近似值（如 150×196）。近似值在某次只调高度时会静默
漂成非 3:4，而这种漂移在视觉上几乎看不出来——这正是要避免的失效模式。

### 决策 3：显式写 `flex-basis`，不用 `flex: 0 0 150px` 简写

**选择**：在 `flex: 0 0 150px` 之外**再写一行** `flex-basis: 150px`。

**理由**：窄容器下 `flex-shrink` 会让实际可用宽度小于 `width`，此时若 `flex-basis` 与
`width` 不一致，实际比例就漂了。简写形态下"basis 与 width 是否一致"无法被机械断言
（要解析简写再拆三项）；显式声明后测试可以直接读 `flex-basis` 与 `width` 比对。

### 决策 4：回归锁读 CSS 原文，不量渲染结果

**选择**：测试用 `fs.readFileSync` 读组件自身的 scoped CSS，正则提取 `.record-preview { ... }`
的声明体，再断言 `width/height` 比值。

**理由**：jsdom **不布局**——`getComputedStyle` 对 `width`/`height` 返回的是空串或 `auto`，
去量渲染结果等于什么都没量，还会给出"测试通过"的假信号。

**放弃的替代**：Playwright 真实浏览器量 `boundingBox()`。那才是终极判据，但它把一条纯 CSS
断言拖进需要 dev server 的端到端链；本任务的正确分工是：**比例契约**用 CSS 原文锁（快、可机械断言），
**渲染结果**由 QM-4 像素门禁兜（已跑，明暗双通道）。

### 决策 5：额外加一条"补集"断言

**选择**：除四条正向比例断言外，再加一条扫全部 `.record-preview` 规则、断言
`width <= height`（即"不得出现横版"）的用例。

**理由**：只断言"四处是 3:4"挡不住有人在响应式块里**另起一条** `.record-preview { width: 300px; height: 100px }`
覆盖——那会让四条正向断言全绿而实际渲染仍是横版。补集断言把"别处有横版规则"也变成红。

## 四、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 竖版缩略图让卡片更高，长列表一屏条数变少 | 视觉密度下降 | 列表视图高度 200px（原横版 112px），卡片 `min-height: 156px` 本就低于此值 ⇒ 卡片高度由缩略图主导，原横版下卡片是被 `min-height` 撑高的，竖版实际增高约 44px。已人工看渲染确认可接受 |
| 封面多为横版原图，竖版容器下 `object-fit: cover` 会裁掉左右 | 封面主体可能被裁 | 这是**既有裁切语义**，本次只改容器比例不改裁切方式；若后续要"完整展示"需另立任务（并会与"填满容器"诉求冲突，属产品决策） |
| 像素基线刷新掩盖了真实回归 | 假绿 | 三步取证：干净基线对照证明非既有红 → 人工看差异图确认差异只在缩略图区 → 人工看新渲染确认确为竖版 |
| 窄屏下 54×72 仍偏大 | 小屏拥挤 | 720px/460px 两档同步改，且都保持 3:4；已人工看渲染 |
