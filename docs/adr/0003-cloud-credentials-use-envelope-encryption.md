# 云端凭证用信封加密存储，主密钥托管服务端 KMS 抽象层

每条凭证由随机数据密钥（DK）以 AES-256-GCM 加密，DK 再由按登录身份隔离的主密钥（MK）加密后与密文同存；MK 在服务端 KMS 抽象层之后。选它是因为同时满足两个硬约束：换设备免扫码（服务端必须能重新解出凭证）与"库被拖走不是明文钥匙"。

## 备选方案

- 密钥由 Logto sub 派生（HKDF）：省掉独立密钥表，但服务端 salt 一旦泄露即全量可解，且用户身份主体变更就永久解不开。
- 零知识口令加密：服务端不可读，合规最好，但要求用户换设备先输口令。
- 不加密（蚁小二形态）：实现最省、后台可直接取用钥匙，本项目的数据敏感度不接受。

## 后果

KMS 是不可逆的基础设施依赖：真部署需在生产配置该抽象层的实现与密钥轮转策略，本 PR 只交付接口与本地实现，部署步骤写入 `docs/ops-center-ecs-deployment.md` 同级运维文档并如实登记未执行。
