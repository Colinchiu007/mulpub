# 同步入口由运营中心 feature flag 控制，默认关闭

【同步云端】按钮的可见性挂在既有 `runtime/bootstrap` 下发的 feature flag（建议键 `account_cloud_sync`）上，默认 `false`；服务端与 KMS 上线后由运营打开。理由：这个功能一开就是把用户全部平台登录钥匙交出去，若客户端先合并且入口常显，在端点尚未部署的窗口期用户一点就撞错，而这类错误会直接摧毁对"上云"的信任。桌面端已有消费先例（`ops-center-sync.js` 解析 featureFlags，上限 100 条；`CreateView.vue:2703` 读 `runtime.data?.featureFlags?.[KEY]`），不新建基建。

## 备选方案

- 按钮常显 + 友好报错：入口永远可见，但存在"点了必错"窗口期。
- 客户端探测端点可用性自动显隐：无需运营干预，代价是多一条探测链路，且"探测失败"与"同步失败"两种语义要分开维护。

## 后果

- 无网络或未同步过运营配置时，按默认关闭处理，即用户看不到入口。开发、CI、视觉基线都必须能提供该 flag 的夹具，否则新增 UI 的用例会因为入口缺失而假绿。
- 交互形态同期定死：弹窗只做**摘要确认**（"云端现有 xx 个账号" + 平台分布 + 是否同步），不提供逐账号勾选；点【同步】后在同一弹窗内切为过程区，展示逐条结果与完成汇总。选择粒度让位于"一键全量"，是为了与用户原始表述一致并压低实现面。
