# 合并语义：状态本机自证、墓碑只阻止复活、凭证冲突由实测裁决

一次同步里三条会破坏数据的判定，各自定死：

1. **登录态不跨设备传播。** 云端可以镜像 `status`/`last_validated` 供展示，但写回本机时 `status` 一律强制 `unverified`、`last_validated` 记本机写入时刻且不参与超龄计算，随后自动排队一次本机检测。理由：真源改写受单向证据规则约束（#2433 刚为此终结过 active ↔ unverified 振荡），"有 Cookie"在本仓定义里不等于已登录；且带着旧设备时间戳进来会让 7 天超龄兜底在新设备上立刻把可用账号判成失效。
2. **墓碑只阻止复活，不反向删除本机。** 本机删除账号时向云端写 `(platform, uid)` 墓碑，后续同步遇到就不拉回；但"云端有墓碑"绝不触发删本机账号或本机凭证。理由：本机凭证删除不可恢复，若合并键判错，反向删除会把可用账号跨设备抹掉。
3. **凭证冲突取较新者并先实测。** 本机与云端凭证指纹不同时，先按时间戳取较新的一份做一次登录检测，有效才采纳；无效再试另一份；两份都无效则保留本机原凭证并标"凭证已失效，需重新登录"。理由：纯时间戳 LWW（蚁小二的 `cookieMd5 !== Content-Md5` → 整体覆盖，`index.cjs:263`）会用一份看起来更新但实际失效的钥匙覆盖本机刚刷新的有效钥匙，且用户无从得知是同步干的。

## 备选方案

- 状态也同步（云端 LWW）：换机直接显示"已登录"，体验最好，但与 #2433 契约直接冲突，被否决。
- 删除双向完全镜像：语义最完整，风险是不可恢复的跨设备误删。
- 冲突一律本机优先：当前设备永不被同步弄坏，但换设备恢复到的始终是旧钥匙，与免扫码目标不符。

## 后果

第 3 条让同步在有冲突时需要一次真实网络检测。该检测必须打平台接口，不能在本机回环夹具之外新增真实出站——测试侧要遵守 #2450 引入的 `network-egress-guard` 与 `check-test-microtask-spin` 门禁。
