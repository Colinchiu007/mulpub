# 账号凭证（cookie/localStorage）全量上云，换取换设备免扫码

本决定推翻了此前"凭证不出本机"的边界：为实现换设备免扫码恢复，桌面端把 `credential-store` 里的完整会话材料上传云端。代价是服务器一旦泄露即等于用户全部自媒体账号被接管，因此必须与 ADR-0003 的信封加密同时成立。

竞品取证支持这是唯一可行路径：蚁小二 `index.cjs:118248` 无条件 POST `cookie: JSON.stringify(cookies)`，localStorage 仅抖音保留全量、其余只存 `{__url__}`，凭证另存对象存储并按 `spaceId` 取回（`:263`），因此换设备可直接恢复、不需重新扫码。反过来"凭证不上云"必然要做重新扫码。

## 备选方案

- 只上元数据、恢复后要求重新登录：不触碰安全边界，但"跨设备恢复"只能得到不能发布的空壳，用户明确选择了免扫码，故否决。
- 端到端零知识（用户口令加密）：合规最干净，但换设备必须先输口令，与免扫码目标冲突，且需口令找回体系。

## 后果

- `python-backend` 的 `ACCOUNT_METADATA_ONLY`（`server.py:484`）**保持不变**——它管的是本地真源不收凭证，与云端镜像是两条独立通道；不要把它当本特性的门禁去改。
- AGENTS.md「凭证保留在主进程加密存储」条款需同步修订为"本机为主副本，云端为加密镜像"。
- 隐私声明与用户同意文案必须覆盖"登录钥匙离开本机"这一事实。
