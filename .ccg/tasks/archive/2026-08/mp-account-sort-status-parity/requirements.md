# 账号排序与状态可见性 parity 需求

## 背景

上一轮已合入发布/草稿/发布记录 parity，但账号页仍有两个可在本地完整闭环的差距：Store 已有排序状态而界面没有入口；已登录账号没有明确的正向状态徽章和最近检查信息。

## 本轮范围

1. 账号页提供稳定的排序字段和升降序交互：名称、平台、添加时间、粉丝数、登录状态。
2. 排序在搜索、状态、平台、分组、负责人/发布人筛选之后保持稳定且可预测；缺失/非法值不能把账号排序到不可解释位置。
3. 账号卡片统一展示“已登录/已过期/异常/暂无检查记录”状态，提供稳定 `data-testid`、`role=status` 和可访问标签。
4. 若存在最近登录检查时间或失败原因，按规范字段显示；未知字段保持诚实的“暂无检查记录”，不伪造第三方结果。
5. 补充 Store、Accounts.vue、AccountManagementCard.vue 的单元/组件回归测试及文档合同。

## 明确不在本轮

- 真实第三方验证码、手机号/密码、微信/QQ授权和 Cookie 重启恢复。
- 团队分享链接、成员权限、跨设备分组/收藏同步、owner/team 后端 API。
- 不能验证的参考产品线上数据不能用假数据替代。

## 验收标准

- `account-sort` 控件存在，具有稳定选项值、中文可见文案、ARIA 标签；切换字段和方向后结果顺序与 Store 输出一致。
- 名称、平台、日期、最后使用、粉丝数、状态排序覆盖大小写、数值字符串（逗号/万/w/k）、缺失值、非法日期和相同值稳定排序。
- `account-status-${id}` 节点在 active/online、inactive/offline/expired、error/failed/failure 与 unknown 状态都存在，文本、class、`aria-label` 与状态一致。
- 账号搜索/状态 tabs/平台/分组筛选和排序组合回归通过。
- `npm run build:vue`、账号聚焦 Vitest 和可用的视觉/功能回归通过；不能通过的既有环境门禁需记录具体证据。
