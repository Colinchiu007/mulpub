# 实施计划

## Phase 0：证据和边界

1. 盘点现有账号/发布布局、路由、composable、store、IPC 和测试。
2. 读取参考产品解包 renderer/main/preload、既有逆向文档和视觉基线。
3. 通过真实参考产品安装包确认主流程、字段、弹窗和反馈；记录截图与状态矩阵。
4. 汇总 antigravity/Claude 分析，冻结本轮可交付差异清单。

## Phase 1：设计与结构

1. 先补行为合同和页面状态测试骨架。
2. 收敛 AppNavbar/AppSidebar 与账号/发布工作区布局。
3. 抽取可复用的账号卡片、筛选条、发布编辑区、状态反馈和弹窗结构，避免重复实现。
4. 对齐账号和发布路由、字段命名、按钮文案、加载/错误/空态。

## Phase 2：实现

1. 按底层状态/composable/store → 页面 → 弹窗/动态内容的顺序实现。
2. 保持现有 IPC/API/租户隔离合同，必要时只增加适配层。
3. 对无法直接复用的参考产品行为，按逆向证据做最小等价实现。

## Phase 3：验证和交付

1. 运行定向单元、组件、路由、构建和完整测试。
2. 运行账号/发布视觉回归和 Electron 窗口验证；涉及主进程时执行打包门禁。
3. 双模型审查并修复 Critical/Major；写入 review.md。
4. 更新 PRD、逆向分析、测试用例和项目文档。
5. 命名路径提交、推送、创建 PR、确认后合并主分支，并写记忆更新说明。

## 已知边界

- 真实平台登录、验证码、第三方接口和线上 A/B 内容不一定可重复；此类差异必须标为“外部依赖未覆盖”，不能伪造通过。
- 如完整 100% 复刻超出当前迭代容量，优先交付账号/发布主路径和所有可观测状态，保留剩余差异清单而不声称全部完成。
