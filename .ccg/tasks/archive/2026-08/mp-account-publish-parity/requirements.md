# 账号管理与内容发布参考产品对齐需求

## 目标

在不破坏现有多租户、IPC 安全和发布能力的前提下，使 Multi-Publish 的“账号”和“发布”模块在布局、交互、字段、状态、提示、弹窗和流程上尽可能复用并对齐参考产品 4.0。对无法直接复用的代码，按已解包 renderer/main/preload 资源和真实操作行为实现等价克隆。

## 本轮范围

- 设计与代码分离盘点：确认账号、发布、发布历史及共享布局是否仍有遗漏，并补齐可复用设计 token/组件边界。
- 顶部导航和左侧区域：按参考产品真实页面收敛为账号/发布工作区需要的布局，移除无对应价值的导航噪声。
- 账号模块：主列表、搜索/筛选、账号卡片、登录/授权、代理、分组、批量操作、空态、错误态、加载态和二级弹窗。
- 发布模块：单篇/批量发布、平台/账号选择、编辑字段、媒体/文本、草稿、定时、模板、提交、进度、失败重试和反馈提示。
- 发布历史/草稿：作为发布模块的二级页面，保留筛选、视图、分页、导出、批量选择和状态反馈，并与参考产品命名和字段对齐。
- 测试与文档：新增行为合同、组件/路由测试、视觉回归场景和逆向资料更新。

## 约束

- 所有改动只发生在本隔离工作树和新分支。
- 不能把“进程存活”当成 Electron 可用 UI；涉及主进程/preload 的改动必须打包并真实窗口验证。
- 不能把开发环境变量当作打包状态判断；不能放宽现有租户隔离、IPC sender 校验、参数纯 JSON 序列化或路径安全合同。
- 不能用测试 mock 掩盖真实参考产品行为差异；对关键流程至少保留一条真实 renderer/IPC/API 链路测试。
- “100% 一致”仅能按已观测的参考产品版本、逆向资源和可复现流程验收；不可观测或受外部平台限制的行为必须在报告中明确标记。

## 验收标准

1. 账号和发布主界面、二级/三级页面及弹窗均有对照矩阵，明确状态、字段、按钮、提示、路由和数据来源。
2. 顶部/左侧布局不再显示参考产品没有的导航噪声，账号与发布的主路径可从同一工作区完成。
3. 账号与发布的核心正常、空、加载、错误、重复提交和权限受限状态均有实现和回归测试。
4. 关键 Vue 组件通过模板编译、导出完整性和路由行为测试；视觉基线覆盖账号、发布、历史、登录/分组/定时等场景。
5. 现有账号 owner 隔离、IPC 参数序列化和发布 API 契约测试继续通过。
6. 任务文档、PRD、逆向分析和测试用例记录新增差异、决策、已知限制和复现步骤。
7. 双模型审查无未解决 Critical；提交前完成规定的单元、构建、视觉、Electron/打包（如涉及）门禁。
