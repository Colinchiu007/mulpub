# 实施计划

## Phase 1：基线与合同
1. 对照逆向工程报告、PRD 和当前组件，固定字段/文案/状态合同。
2. 先补单元与路由测试，锁定账号卡片字段、代理入口、query tab、工具按钮和草稿 tab。

## Phase 2：账号模块
1. 已复核并保留现有账号字段归一化显示函数，覆盖粉丝数、负责人、运营人、代理和空值。
2. 已复核代理配置动作、分组筛选、收藏空态和分享服务边界，避免重复实现。
3. 将外部团队分享明确标记为“未接入服务”，不伪造链接或成员数据。

## Phase 3：发布模块与设计分层
1. 使草稿 query tab 驱动独立草稿工作区，支持返回发布、继续编辑和删除入口。
2. 将本轮新增视觉样式落到模块级样式/token，避免继续扩散 inline style。
3. 为顶部工具按钮接入可验证的本地面板，并对暂未接入的外部能力诚实提示。
4. 补齐发布记录批量删除的 renderer → preload → IPC → JSONL owner 隔离链路。

## Phase 4：验证与交付
1. 运行定向 Vitest、路由/集成 E2E、像素视觉测试和完整桌面测试。
2. 运行双模型代码审查、质量门禁和差距文档同步。
3. 创建 PR、等待门禁、实际合入 main、确认 origin/main，并归档任务与更新记忆。
