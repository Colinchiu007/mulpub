# 需求增强说明

## 目标
在不伪造真实第三方能力的前提下，收口账号管理与内容发布模块中已确认的参考产品交互差距；保留已有本地合同和外部能力边界。

## 本轮范围
- 账号卡片字段：粉丝数、负责人、运营人、代理配置入口，缺失值显示明确空态。
- 账号页二级页签：账号管理、分组管理、分享链接、收藏分组；各页签不得误显示账号列表。
- 顶部工具按钮：移动端预览、客服支持、使用指南、通知必须有真实本地行为或明确的未接入状态。
- 草稿箱 query 页签：从发布页内嵌状态升级为可直接进入的独立页签语义，支持空态、返回发布、删除/编辑入口合同。
- 稳定 testid、单元测试、路由/集成回归与视觉回归。
- 补充设计与代码分层说明、外部能力边界和差距审计。

## 不在本轮承诺
- 真实第三方登录、上传、发布、审核、配额、团队分享、跨设备同步；这些仍需真实服务验收。
- 重新编写参考产品运行时 bundle；仅复用其字段、状态、交互和本地可验证合同。

## 验收标准
1. 账号卡片对完整/缺失字段均稳定渲染，点击代理按钮可打开现有代理弹窗并保存/清除。
2. `/accounts?tab=groups|share|favorites` 显示对应主体、空态或外部服务边界；账号管理 tab 保持原列表。
3. 顶部工具按钮不再是无行为静态占位，所有状态有可验证文案和 testid。
4. `/publish?tab=drafts` 首屏直接进入草稿页签，不依赖用户再次点击内嵌按钮；发布页仍可返回。
5. 相关单元测试、路由 E2E、集成流、视觉测试和现有全量回归不退化。
6. 质量审查、PRD、差距报告、任务归档和分支合并均有证据。
