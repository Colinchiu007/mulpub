# task-051 接手需求

## 目标

1. 用真实 Electron + 独立 debug profile 验证快手扫码登录态、账号恢复和视频发布链路，记录可复核证据。
2. 收口当前分支已经暴露的测试/契约失败，禁止用更新基线掩盖行为变化。
3. 落地一批范围明确的参考产品 UE 改进：发布页固定主操作区、账号页连接状态使用真实状态来源、快手扫码回归测试和相关响应式行为。
4. 同步中英文用户文案、PRD/CHANGELOG，并完成 QM-1、审查、PR 和归档闭环。

## 不在本次范围

- 团队分享、跨设备同步、负责人/运营人后端数据、第三方服务审核/配额接口。
- 伪造真实平台成功结果；真实发布必须以页面结果、日志和时间线为证据。
- 在共享主目录修改运行时代码。

## 验收标准

- [ ] 快手账号在独立 profile 中可保持登录，重启后仍可识别。
- [ ] 已打开快手创作者中心时启动二维码登录，页面仅显示一个全屏 auth-login 虚拟标签；成功、取消或超时后恢复原创作者中心标签。
- [ ] D:\01.mp4 在快手发布表单中完成文件/标题/描述/封面填充，并由人工确认后发布；成功或失败均保存阶段证据。
- [x] 百家号与快手的发布结果不从历史 localStorage、页面 URL、旧链接或页面正文推断；网络诊断不携带原始响应、query、token 或用户正文。
- [ ] 相关单测和契约测试通过，或每个剩余失败有明确根因和独立跟踪项。
- [ ] 发布页主操作区在长表单滚动时保持可见，移动宽度不产生横向溢出。
- [ ] 账号页“已连接”语义来自真实 bridge/登录状态，不继续固定显示成功。
- [ ] 中英文 locale 成对更新，CJK 门禁通过。
- [ ] Electron 打包、启动和受影响 IPC 验证通过。
