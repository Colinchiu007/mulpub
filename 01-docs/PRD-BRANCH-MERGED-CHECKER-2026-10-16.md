- 变更类型：`scripts/` 工具脚本 ⇒ 按 AGENTS.md 分层判据属**混合 PR**（不走 docs-only 快速通道）
- 来源：issue #3674 的结案遗留（判据本体已由 PR #3741 落进 AGENTS.md，本切片把它从散文变成可执行工具）

## 1. 问题与第一性原因

AGENTS.md「收尾链上的已知假失败」现在用**文字**规定：squash 合并后删本地分支前，必须证明「分支内容已完整进主干」，
且给出的口径是「改动集收敛 → 普通文件逐字节比 blob → 多会话共用写面走双向行级多重集 → 取不到读数一律按未证实」。

问题不在这段话写错，而在**它没有执行体**：每一轮清理都要会话临时手写一个探针来跑它（本轮用的
`.tools/tmp/gate75/probe-merge-criterion.cjs` 就是这种一次性玩具）。文字判据挡不住两类事故：

1. **判据本体写错**。旧口径「`git diff --stat <branch-tip> <merge-SHA>` 输出为空 ⇒ 内容已完整进主干」从未被证伪过就入库，
   在共享根并发写的现实里 5 例中 3 例假阳性。
2. **判据非空时人照样删**。本轮真实发生一次：按旧文字判出差量 52 / 10 / 5 行，仍把 `mp-gate12c-ledger-round9` 删了——
   因为差量明明不是 0，而手上没有任何东西拦这一步，只有「应该停下来」的自我要求。

⇒ 第一性原因：**「删分支前的落地证明」这一决策没有机械闸门**，全靠会话临场自觉，而自觉已被证明不可靠。

|---|---|---|---|
| A | `git diff --stat <tip> <mergeSHA>`（全树） | **3/5**（差异 52 / 10 / 5 行，逐行核对全是别人的文件） | 照字面执行只能得出「分支永不可删」，或逼人在判据非空时照样删 |
| B | 同上加 `-- $FILES`（缩到本 PR 文件集） | **2/5** | #3674 提议的那一行改法，仍不够 |

## 3. 本切片要一并解决的第二落点：归类不得靠手抄名单

AGENTS.md 把「多会话共用写面」列成 5 个文件名（`CHANGELOG.md`、`01-docs/learnings.md`、`.quality-gates.md`、
`scripts/gate-record-debt-ledger.json`、`scripts/doc-abs-paths-baseline.json`）。这是一份**手抄枚举**：

- 第 6 个热写面出现，或某个文件改名 ⇒ 它被当普通文件逐字节比 ⇒ **当场复刻 B 档假阳性**；
- 名单只能靠人记得更新，而「记得更新」正是本切片要消灭的那类防线。

**正解：不设名单，按「差异是否需要归因」分流**（工具的判据本体，逐文件）：

1. 先比 blob：`git rev-parse <tip>:<f>` 与 `git rev-parse <mergeSHA>:<f>` 相等 ⇒ `IDENTICAL`（普通文件的强判据，零成本）。
2. 不等时**既不得直接判丢失，也不得直接放行**，必须同时成立两条才判 `DRIFT-ATTRIBUTED`：
   - **(a) 双向行级多重集**：
     我的**新增行**（`git diff --unified=0 <base> <tip> -- <f>` 的 `+` 侧）逐条要求在 `<mergeSHA>:<f>` 中出现次数 ≥ 我给的次数；
     **（⚠️ v2 修正：这里的 `<mergeSHA>` 应为 `--against`（默认 `origin/main`）——参考系钉在 merge 快照会在 re-sync 型分支上大面积假报丢失，机制与读数见 §8）**
     我的**删除行**（去重、去空白、`trim` 后）逐条要求在 `<mergeSHA>:<f>` 中出现次数 **恰为 0**。
     单向只证「我的东西都在」，证不出「我删掉的那一行被后续合并带回来了」。
   - **(b) 具名归因提交**：`<mergeSHA> -- <f>` 的历史里，除本次合并自身外**至少还有 1 个提交**碰过该文件，并把它的
     `%h|%s` 打印出来。没有归因对象的 blob 不等，说明「差异来自谁」说不清——那正是本轮把 52 行别人的文件读成自己丢失的形状。
3. 不等且 (a) 或 (b) 任一不成立 ⇒ `LOST` / `UNATTRIBUTED` ⇒ 退出码 1，**禁止删分支**。
4. 判据**自身**读不到数（blob 取不到、`merge-base` 取不到、git 命令失败、改动集非空而文件集为空）⇒ 退出码 2，
   与「发现问题」的 1 分档。把工具的失明读成结论，是本仓「装饰性门禁」的同型。

这样普通文件保持强判据、热写面自动降级为行级，而**降级必须带归因提交**。它比名单更强：分类错误会**变红**，不会静默放行。

## 4. CLI 合同

```
node scripts/check-branch-merged.js --ref <branch|sha|retire/tag> --merge <sha>[,<sha>...] [--against origin/main] [--base <ref>] [--json] [--root <path>]
```

- `--ref` 必填；缺省、未知旗标、非法取值一律退出码 2（参数不得静默忽略）。
- `--merge` **必填**，但 v2 起它只是**归因排除集**（告诉判据"哪几笔是这些 PR 自己"，别把它们当他人差异）。
  上一版这里写的「缺省时按 `git log origin/main --grep='(#NNNN)$'` 从分支名反查」**从未实现**——反查要引入 `gh`
  依赖与网络调用，与本片"离线可跑"的约束冲突；实现与文档在 #3749 的记录里已按"仍由人传"承认过一次，
  本次把这句不实的 CLI 描述一并改掉，不留第二处。
- `--against`（v2 新增）= **判定域**。默认按 `origin/main` → `main` 解析；显式传入而取不到 ⇒ 退出码 2（不得静默退回 merge 快照，
  那等于把"判据没跑"伪装成"分支干净"）。回落是允许的，但每次运行都在末行打印 `against=<name>@<sha>`，让落点可核对。
- 逐项输出 `<f> IDENTICAL | DRIFT-ATTRIBUTED(<归因提交>) | LOST | UNATTRIBUTED | JUDGE_ERROR`，
  末行 `[BRANCH-MERGED] ref= against=<name>@<sha> merges= files= identical= drift= lost= unattributed= judge_error=`。
- 差量为空分两档，方向相反，不得合并：`ref == against` ⇒ 参数误用 ⇒ **2**；差量为空而两者不同 ⇒ **通过**并打印明说（见 §8）。
- 退出码：**0** 全部落地（可删）/ **1** 存在 `LOST` 或 `UNATTRIBUTED`（禁止删）/ **2** 判据自身故障（fail-closed，同样禁止据此删）。
- 只读：本工具**不**执行任何 git 写、不删分支、不建标签；它只回答「删之前该不该停」。

## 8. 上线当天被自己的清理任务否证 —— 判定域必须从 merge 快照换成「主干现在」（2026-10-17 v2）

第 3 节写的 (a) 半句「要求在 `<mergeSHA>:<f>` 中出现次数 ≥ 我给的次数」是**错的参考系**，本确整片把它改成 `--against`（默认 `origin/main`）。
上面 2–3 节的口径保留不改写，因为「双向行级 + 具名归因」这套机制本身是对的，错的只是它比的是哪棵树。

**否证读数（当场，非推算）**：`toutiao-ms-token`（tip `b0df701cf`，7 个已合并 PR）被 v1 报 `lost=65 files=66`，耗时 48 s。
拿判据本体自己的导出函数（`compareAddedLines` / `splitLines`）逐行问「那些被点名缺失的行在不在当前 `origin/main`」得：
**`named_lines=3628 present_on_current_main=3369 ABSENT=259`** —— 93% 的"丢失"是判据自己造出来的。

**机制（两个缺陷叠在一起，缺一不可解释现场）**：

| 缺陷 | 形状 | 为什么必然逐份红 |
|---|---|---|
| D1 差量口径 | 分支 re-sync 过 main ⇒ `merge-base(ref, merge)` 退化成 **merge 自己** | `diff base..ref` 于是包含**别人后来合进主干的行**，而那份快照按定义还没有它们 |
| D2 多 PR 聚合 | 一个文件被同分支的多个 PR 分别改 | 每份快照只含其中一部分 ⇒ **逐份 LOST** ⇒ 跨 merge 取 best 仍是 LOST |

**修法（v2）**：判定域 = `--against`（默认 `origin/main`，取不到回落 `main`，落点一律打印，显式传入取不到即退出码 2）；
差量起点 = `merge-base(ref, against)`，别人的行天然进不了判定域；`--merge` 降级为**归因排除集**（哪笔是本次合并自身）。
删除行的复现改为按主干现状判，并新增**逐行**归因：一条又出现在主干上的删除行，必须由 `base..against` 里某笔具体提交
`git log -S<该行>` 指认出来才放行，指认不到仍算 `LOST`（把「归因类别」当放行依据是本仓的老错型）。

**顺带纠正的一条自伤**：v1 把「改动集为空」一律判成判据故障。在 v2 的参考系下，一个已完全落地（且 re-sync 吸收了后续 main）
的分支相对主干就是**无差量**——那是通过态。把它做成红灯，等于每清一个干净分支都要先撞一次闸门，而"红了就停手"这条规矩本身是对的，
于是训练出来的行为是绕过闸门。v2 分成两档：`ref == against` ⇒ 参数误用 ⇒ 退出码 2；差量为空而两者不同 ⇒ 通过并打印明说。

**T6 的契约随之改变**（原先断言「漏传第二个 merge 必须红」）：那条断言测的是判据参考系太窄，不是"内容没进主干"。
v2 起 `--merge` 少传只影响归因，不影响放行，故把它改写为显式的新契约（少传**不得**造假红）。这是一次**放宽**，
但放宽的是判据自己的参数耦合，不是判定强度：判定域从"几份快照"扩到"主干"，可证明的内容反而变多了。

## 9. v2 上线当天又被真实清理否证 —— 「出现过即违规」在重复行上是假阳性（2026-10-17 v3）

v2 把参考系修对之后，`bf520a13c` 等 8 个真实分支的读数仍有一类解释不了：分支的删除侧只要那行**在主干出现过**就判 LOST。
三类假阳性都是当场实测（合成夹具 `multiplicity-probe.cjs` + 真实仓 A/B），不是推演：

| 类别 | 形状 | 实测 | 后果 |
|---|---|---|---|
| A 重复行份数 | 同名行有 N 份、我只删 1 份、且逐字落了地 | `base=dup/dup/tail`、`tip=dup/tail`、合并产物=`dup/tail/OTHER` ⇒ `verdict=LOST rc=1` | 杀伤面恰好是本判据专为其特征的那两张热写面：origin/main 上 `CHANGELOG.md` 有 **3348** 个重复行键（单键最多 **286** 份）、`01-docs/learnings.md` **4104** 个（最多 **333** 份）|
| B 落地后被删 | 我的合并正常落地，之后他人**按设计**整份删掉该文件 | 真实样本 `openspec/records/_exempt/backfill-2767-2768-records.md`（PR #2780，merge `8e90984bd`）| v2 的 `fileAbsentOnMain` 短路成 LOST 且不做归因 ⇒ 分支 `backfill-2767-2768-records` 至今删不掉 |
| C 我删的文件 | tip 与主干两侧都**不存在**该文件 | v2 第一道判据写作 `tipBlob !== null && tipBlob === againstBlob` | 删除落地被判 MISSING_FILE ⇒ 任何"删文件"的 PR 都删不掉自己的分支 |

**新增方向也有洞（同一次改造里顺手补）**：v2 新增侧是"主干份数 ≥ 我新增的条数"。`base=dup×2`、我加第 3 份、产物只落 2 份时
`need=1 ≤ have=2` ⇒ 不报违规，只剩一句 blob 不等（报成 UNATTRIBUTED）——**说不清到底丢了哪一份**。v3 起它点名缺失键并给份数。

### 判据本体（v3）：份数 + 可解释容量

```
缺口   tip(k) − main(k) > 0  ⇒ 用"他人对该键的净删除容量"解释；
                                若 tip(k) > base(k)（这份份数是我带来的）再叠一道血统前提：
                                该行须随本次合并落地过（mergedCopies），否则不得被救走
超出   main(k) − tip(k) > 0  ⇒ 用"他人净新增容量"解释；解释不了时按我是否净删除分流：
                                净删除 ⇒ LOST（我的删除被合并丢了）；我从没写过它 ⇒ UNATTRIBUTED（不许据此删，但不谎报丢失）
```

`violations[]` 逐键带 `base/tip/main/capacity/landedWithMerge`，plain 与 `--json` 两条出口都打——
"为什么这条被拦"必须能被复核，不接受只报一个结论词。

### 一次我自己的错判，和它被否证的过程（这一段是本页最有用的部分）

v3 第一版把上面写成了一条**加法等式**：`main(k) = tip(k) + Σ(区间内他人对 k 的净增减)`，并用"该行须随我的合并落地过"
作 rescue 前提。跑真实仓 A/B 时它把 `bf520a13c` 的 `CHANGELOG.md` 与 `scripts/dep-audit-baseline.json`
从 DRIFT 判成 **LOST**（比 v2 更严）。我当时给出的解释是"两条分支交出逐字相同的一行时主干只会出现一份，等式把幂等合并读成丢失"，
并把这句话写进了文件头 —— **那是推断，我没量过**。

换一条与判据无关的取法（`git grep -na` 直接数主干）复核，实测读数是
`base=2 / tip=2 / main=0 / 他人删除容量本可解释 / landedWithMerge=0`：
那两行是 **fork 时就存在的存量**（不是我带来的），主干后来把行内的一个 BEL 控制字节改掉了。
所以真正的机制是**血统前提被无条件套用**——对继承来的存量要求"随我的合并落地过"，等于把容量压成 0。
处置：血统前提收窄为只对 `tip > base` 的键生效；等式**降级为自检**（`assertChainCloses`）不再产出结论。
文件头里那句 dedup 解释已按上述实测改写。口径：**"更严格"不是"更正确"的证据**，方向变化必须逐条独立复核。

### 恒等式自检当夜抓到我自己两处解析错（这才是它的位置）

| 缺陷 | 现场读数 | 修法 |
|---|---|---|
| 段落头按 `startsWith('---')` 判定 | 删除一行 `---` 在补丁里长成 `----`，被当文件头整行吃掉 ⇒ `learnings`/`CHANGELOG` 的删除侧净数被少算 | 只在**本文件段落第一个 `@@` 之前**认段落头；hunk 内一切 `+`/`-` 都是内容行（`\ No newline` 单列排除）|
| `git log -p` 对合并提交不给补丁 | `fix-toutiao-submit-chain` 的区间 1050 笔里有 **27** 个真合并提交 ⇒ 求和少算，`---` 被演成 `short=1885` | 走 `--first-parent --diff-merges=first-parent`；修后同键缺口 **0** |

两处都不是靠眼看发现的，是靠"链上求和必须等于 `main − base`"这条断言响出来的。
它自己在真实仓上**总是闭合**，所以没有现场夹具能反证 ⇒ 已抽成独立函数并配**正/负控直接锁** + 一条
"调用点必须存在"的结构锁（否则它是"只会在出事时响、却没人证明过它会响"的装饰代码）。

### 二进制文件的落点

git 对二进制不给补丁 ⇒ 份数根本数不出来。若不单列，每个含 PNG 的分支都会被自检判成 rc=2（那是工具失明，不是严格）。
v3 的处理：认出二进制（blob 含 NUL 或链上出现 `Binary files … differ`）后**只问一件事**——我那份字节是否随本次合并进过主干；
进了且后来有人动过 ⇒ DRIFT，没进 ⇒ LOST，并在输出里打 `(二进制，行级判据不适用)`。

## 10. v3 上线后被真实清理任务第三次否证 —— 「落地那版本来就不是我这版」（2026-10-19 增量）

**动因（现场，非推演）**：清理 44 个孤儿分支时，两条 CI 探针分支（`ci-trigger-probe` / `ci-probe-2`，tip 是 #3733 那条 `cjk-font-selfcontained` 的旧切片）在 main 判据下报 `files=21 identical=7 drift=2 lost=12 rc=1`。
我先给出一句归因（「因为我多传了一份 merge SHA，把删除提交从他人净删除容量里排除了」）并据此**保留了分支**。随后 A/B 实测把它否证：
只传属主 PR #3733 的 merge SHA 与同时传 #3733+#3769，读数**逐字相同**（`files=21 identical=7 drift=2 lost=12`）。真正的成因是第三种形态。

**真成因**：探针分支切在 **QM-6 评审修正之前**，而 squash 落地的是修正**之后**那一版。按文件比 blob 取证：`tip:f` 与 `110c3aabb:f` 对 `font-resolver.js`（+99 / −8）、`font-resolver.test.js`（+172 / −22）、`asset-generator.js`、`local-cover-generator.js`、`story2video-compose-engine.js`、`bundled-font-packaging.test.js`、该 PRD **全部不等**，
且差异内容里明写着「QM-6 评审 i2」的 `warnFontFallback` / `buildDrawtextFontOption` 收敛，以及 Gate 12c 要求的「安装目录示例路径 → 尖括号占位符」改写（原文是一条 Windows 绝对路径，按 Gate 12c 不在本文重述）。也就是说这 12 条 LOST 的语义是**我这旧版没被采纳**，不是**工作丢了**。

**为什么 v3 看不见这一格**：v3 问的是"我这行在不在主干现状里"＋"缺口能不能被他人净删除容量解释"。上面两种答案都是"不解释"，于是判 LOST，且判据不会说"落地那份根本不是你这版"。
而操作者在这个形态下的正确动作（比 blob）当时只能手工做——这正是我今天连续两次写下错误归因的土壤。

**本片只加读数，不改判据宽严。** 新增 `classifyRevision(mergeBlob, tipBlob, baseBlob)`，按**三**分而不是两分：

| 产物 blob 与 | 归类 | 含义 |
|---|---|---|
| `== tip` | `carried` | 原样带上我那版 |
| `== base` | `not-carried` | **我的改动根本没带上** ⇒ 真丢失 |
| 两者都不等 | `different` | 产物既不是我这版也不是起点 ⇒ **只知道"这笔落地的不是我当前这版"，不知道方向**：可能是评审改了产物再落地，也可能是分支在这笔之后自己前进 |

三分是本片的全部要点：只比 `tip` 与 `merge` 会把 `not-carried` 和 `different` 合成一格，
于是"根本没带上"可以被读成"被修订"——那是**替真丢失作保**的方向，比原盲区更糟。`different` 还带 `onlyInMerge` / `onlyInTip` 双向规模（按行多重集，与判定本体同口径）；读数本身**只说"版本不同"、不说方向**，要定性必须自己比 blob。

出口两条都要有（`T31` 接线锁）：plain 在判定行尾打 ` 落地版本=版本不同@<sha>(主干独有P行/我这版独有M行)`，末行汇总打 ` 落地版本不同=<n> 没带上=<n>`；`--json` 的文件对象带 `revisionsAtMerge`。
只在一个出口存在等于没有——这条与本片 v2 那次"只还原了 plain 的 latin1"是同一课。

**退出码不变**：`carried / different / not-carried` 一律不参与判定，`lost>0` 仍返回 1。
「因为只是被取代，所以允许删分支」是一次**把守门判据改宽**的动作，需要单独授权，不属本片；本片只保证下一个读到这里的人不必再靠手工比 blob、也不必再猜。

**遗留（不假装已闭合）**
- `different` 是否应把该文件从 LOST 降级为一个新的可删档位——**未做，需人工裁决**（同 §9 遗留里"份数偏宽松"那条的处置方式：先点名，不先放行）。
  **本格的初稿把它印成「修订@…」、并写成"我这旧版没被采纳"——那是在替一个没实测的因果背书**：QM-6 后端轴 B1 指出「同一分支被两笔 PR 用过时，早期那笔合法落地的版本也会落进这一格」，本地复现（`repro-b1.cjs`）证实为 `carried:1, different:[merge1]`。故分类名与出口文案一并改为中性 `different` / `版本不同@`，方向由人比 blob 定；回归锁 `T33`（断言读数里不得出现"修订/旧版"），变异 M9 专打这一格退化。
- `describeRevisions` 只打前 2 笔；`lineDiffScale` 对**热写面**（`CHANGELOG.md` 那种重复键极多的文件）会把"我这份拷贝没落"和"整段被改写"报成同一规模，读数须与 `份数=` 一起看，不能单独作结论。
- 真实仓现场两格各点名一例（同一 tip 一次跑齐）：`font-resolver.js` 走 `版本不同@110c3aabb(主干独有95行/我这版独有8行)`，
  `.ccg/reviews/4e34763ec…json` 走 `根本没带上@110c3aabb`。`not-carried` 的其余形态仍靠 `T29` 夹具锁。

## 11. 「放宽 default」被现场读数否证 —— 改成显式 opt-in（2026-10-20 增量）

§10 的遗留第一条写的是「`different` 是否应把该文件从 LOST 降级为可删档位——未做，需人工裁决」。
2026-10-20 得到人工授权后先去量它，**量出来的结论是：那句话的前提不成立**，于是本片做的不是"放宽默认档"，
而是"加一个必须由人当面声明的放宽开关"。

### 现场读数（用 §10 落地的判据本体，root=共享根，against=origin/main）

| 分支 / 属主 PR | 读数 | LOST 行的 `落地版本=` |
| --- | --- | --- |
| `fix-rewrite-paragraph-preserve` / #2842 | `files=16 identical=3 drift=12 lost=1 … 落地版本不同=1 没带上=1` | LOST 那行是 `版本不同@1292b6555(主干独有0行/我这版独有1行)`；另有**一行 DRIFT 是 `根本没带上@1292b6555`** |
| `fix-tab-title-url-placeholder` / #2847 | `files=15 identical=1 drift=13 lost=1 … 落地版本不同=2 没带上=0` | LOST 那行是 `.quality-gates.md`（二进制，行级判据不适用）`版本不同@7be77e5c9(主干独有1行/我这版独有1行)` |
| `fix-toutiao-submit-chain` / #2729 | `files=8 identical=1 drift=3 lost=4 … 落地版本不同=5 没带上=0` | 4 行 LOST 全是 `版本不同@eeeb3f01e` |

三行的 rc 都是 1，且 **LOST 行的类别 100% 是 `different`** —— 看起来"降这一格就解锁三条分支"。

### 但 `different` 不是一个安全属性（这是本片真正的设计输入）

同一个类别里装着两种方向相反的东西，逐条比 blob 才分得开：

1. **`rpa-selector-utils.js`（#2729）**：我这版注释写 `「_s 是 :has-text 之前的部分」`，主干那份是
   `「⚠️ 2026-09-30 外审更正（finding #1）：_s 是完整选择器 …」`。**落地的是更正确的版本** ⇒ 报"我这版没落"确实只是旧版未采纳。
2. **`rpa-view-navigation-helpers.js`（#2729）**：判据报 `我这版独有 228 行 / 主干独有 21 行`，`份数 short 16(base=20 tip=30 main=14)`。
   而我要找的那句话在主干**同一个文件**里原样存在：`origin/main:apps/desktop/electron/services/rpa-view-navigation-helpers.js:194`。
   ⇒ 缺口是热写面**重复键的份数**，不是内容丢失。若默认档只看类别就放行，这一行会被"合法地"放行，
   而它之所以无害是我读了 blob 才知道的——判据本身不知道。
3. **`CHANGELOG.md`（#2842）**：类别是 `different`，可同一分支另一行是 `根本没带上` ⇒ 默认档一旦放宽，
   下一次读到 `放行` 的人会把"整条分支都可删"当成结论，而 `没带上` 那一格正是本片唯一不许被洗掉的方向。

结论写死：**`different` 是线索（"这笔落地的不是我当前这版"），不是许可**。
把许可做成默认值，等于让最有杀伤力的那一格（没带上）在文案上获得一件可借的外衣 —— 与
`T29` 那条反洗白锁的初衷相反。

### 落地的形态

  `rev` 取不到按不合格（未证实 ≠ 合格）。**carried 单独挡一刀**：逐字节带过我这版、主干现在却没有 ⇒ 那是"落地之后被删"，方向与"被修订"相反，不得借同一格过关。
