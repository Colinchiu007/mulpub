# PRD 切片：Gate 12c 的占位符豁免收紧 + 按文件存量基线（gate-abs-path-scope，2026-10-14）

## 1. 问题（第一性原因）

`scripts/check-doc-abs-paths.js`（CI 的 Gate 12c，检查受管文档里的**本机绝对路径是否还存在**）在行循环开头写着：

```js
if (PLACEHOLDER_RE.test(line)) continue;
const PLACEHOLDER_RE = /<[^>]*>|\$\{[^}]*\}|\$[A-Za-z_]\w*|\*|\.\.\./;
```

豁免词表里有一条**裸星号**，而这个判断作用在**整行**上。Markdown 的加粗就是星号，于是：

> 一行只要用了 `**…**`，这一行里所有绝对路径都静态"无法判定"，整行免于检查。

这不是理论缺口。同一轮工作里我自己的执行记录有两处失效路径，所在的行都带加粗，门禁对我报
`PASS（改动集 …6 个受管文件，无失效的本机绝对路径）`——**我一度把这句 PASS 读成"路径没问题"**，
读判据源码才发现豁免原因根本不是路径。

## 2. 当场实测（数字，不是形容词）

| 量 | 值 | 取法 |
| --- | --- | --- |
| 受管文件（门禁自己的 SCAN_ROOTS/SCAN_EXTS） | 3077 | `--all` 输出头 |
| 含 Windows 绝对路径的行 | 961 | 探针（复用门禁正则） |
| 这些行里命中 `*` 记号的 | 281 | 同上 |
| **仅因 `*` 被豁免、且行内路径确实不存在** | **179** | 同上 |
| 全量报错项（现状，收紧前） | **539** | `--all` 现场 |
| 全量报错项（收紧后） | **861** | 同一条命令改后复跑 |
| 净新增 / 涉及文件数 | **276 / 168** | 两次输出按 `文件 :: 路径` 求差 |
| 落在高频被碰文件上的净新增 | 112 处 / 63 个文件（`01-docs/learnings.md` 独占 26） | 同上按文件聚合 |
| **落账后的账本规模** | **429 个文件 / 861 处**（`learnings.md` 现值 34；磁盘上缺失的登记项 0 个；被并入扫描域的文本量 10.4 MB） | `node -e` 逐条 `statSync` 账本键 |

⇒ 并入基线在 CI 口径上净增约 **1.4 s**（418 → 1812 ms），可承受；`--all` 只在生成账本和活体锁里跑。

## 3. 为什么"收紧"和"不挡别人"必须同时做

日常阻断口径是 `--base=<merge-base> --head=HEAD`，而它的扫描粒度是**改动集里的整份文件**。
这个粗粒度是有价值的：本轮 re-sync 把我的占位符改动**悄悄退回**成裸路径时，正是"整份文件重扫"
把它抓出来的（逐行口径看不见，因为那一行不是我"新写的行"）。

但如果只收紧不处理存量：任何会话碰 `learnings.md` 都会被 26 条**别人写下的历史行**判红。
这是把守门成本转嫁给所有人，不能这么落地。

⇒ 本 PR 同时做两件事：**豁免判据收紧到路径自身** + **按文件存量基线（只能缩小）**。

## 4. 方案

### 4.1 豁免判据：从"整行"改到"路径词元"

对每个匹配出的路径片段，取其**所在词元** = 从片段起点延伸到下一个空白为止的那一串，
再用 `PLACEHOLDER_RE` 判定。**不能只看提取到的片段本身**：`*`、`<...>`、`${}` 这些记号根本不在
提取器的字符集 `SEG` 里，片段会在它们之前被截断——只看片段会把 `D:\...\mp-*\apps`
这类通配路径判成失效（实测：两条既有豁免用例当场红）。词元保留了这些被截断的后续字符，
因此既能放行真占位符，又不再被同行的加粗劫持。

### 4.2 存量基线：`scripts/doc-abs-paths-baseline.json`

```json
{ "note": "…只能缩小，不得为容忍新增而调大", "generated": "2026-10-14",
  "reason": "PLACEHOLDER_RE 由整行收紧到路径词元后新暴露的存量（2026-10-14 实测 539→861）",
  "files": { "01-docs/learnings.md": 34, "…": 0 } }
```

实测落账规模：**429 个文件 / 861 处**（其中 168 个文件是本轮收紧新增的登记项）。

判定（逐文件计数 `count` vs 基线 `base`）：

| 情形 | 结论 |
| --- | --- |
| `count > base` | FAIL：超出存量基线（新增失效路径，必须改文档或改指现存目录） |
| `count < base` | FAIL：基线须收紧（改小了必须同步把基线改小，否则基线变成永久豁免） |
| 基线里的文件**磁盘上已不存在** | FAIL：陈旧登记（成因写"文件已不存在"，修法是删掉该条登记，不是把数改小） |
| 基线里的文件还在、但**已移出受管范围**（移入归档 / 改了扩展名） | FAIL：陈旧登记（成因写"不再受管"） |
| 基线文件读不到 / JSON 非法 / 结构不符 | **退出码 2**（自身故障，与"发现引信"的 1 分开）——不得读成"没有问题"，也不得读成"有问题" |

扫描域 = **改动集文件 ∪（账本里"仍受管且磁盘上存在"的文件）**。并入基线文件是**让"变少也要收紧"和
"陈旧登记"在每个 PR 上都真实生效**——否则这两条只有跑 `--all` 时才看得见，而 CI 里没有 `--all`，等于没锁。

**并入时必须带 `existsSync`**（这条是反证跑出来的，见 §4.4）：账本里的文件若已被删除，让它进扫描域
会得到 `count = 0 < base`，于是被判成"改少了把账本改小"——**成因写反**，而"陈旧登记"那一类对删除
永远走不到，等于两类 FAIL 里的一类是死代码。两类修法不同（收紧数 vs 删掉条目），诊断不得合并。

### 4.3 既有测试的迁移

`当前仓库全量审计：报错项必须全部可归因` 原来锁的是「`--all` 必须 FAIL」（防止有人把判定改成恒 0 命中）。
基线落地后全量新增为 0 ⇒ 该断言前提消失。改成**更强的等式锁**：全量审计的逐文件计数必须与基线
**逐文件相等**（既不许多也不许少），从而同时挡住"悄悄恒 0"和"悄悄漏扫"。

### 4.4 反证跑出来的第二条缺陷：`陈旧登记` 那条锁是装饰性的

第一条变异（N3：把 `if (!domain.has(f)) stale.push(...)` 摘成 `if (false)`）**没有让行为锁
「基线里的文件已不在扫描域 ⇒ 陈旧登记必须红」变红**——只有纯函数锁红了。逐条排查后确认不是注入失效：

- 该夹具的 `01-docs/deleted.md` 因为"账本键无条件并入扫描域"而**在域内**，计数得 0、基线 4，
  于是红是由 **shrink** 提供的，`stale` 整条摘掉照样 exit 1；
- 而两条断言 `assert.match(/陈旧/)` 与 `/deleted\.md/` 命中的位置分别是**固定修法文案**
  （`- 变少了 / 陈旧登记：账本只能缩小。…`）和那条 shrink 明细行——**匹配到了词，没匹配到成因**。

⇒ 这是本仓反复出现的「装饰性断言」形态（AGENTS.md 里已有"断言恒真""记录性断言"两条同源教训）：
**用"消息里出现了这个词"代替"这一类结论是被这个成因产出的"**。
修法两条同时落地：① 实现按 §4.2 加 `existsSync`，让"已删除"真正落到 `stale` 分支；
② 断言改成按成因——FAIL 头的分类计数（`—— … 陈旧登记 1 个`）+ 明细行的专属句式，
并补两条**负断言**（`doesNotMatch /低于基线待收紧/`、`doesNotMatch /deleted\.md：0 处/`），
使"由别的成因顶替"不可能通过。另新增一条夹具（归档目录里**磁盘上存在**但不再受管的文件），
把 `v.why` 的两个分支都钉住——否则把两支写反不会有任何锁变红（N7 实测：两支反转 ⇒ 两条陈旧锁同时红）。

## 5. 非目标

- 不改判定域（SCAN_ROOTS / SCAN_EXTS / 归档豁免）——那是另一维，未证有问题。
- 不清理 276 处存量（多是已删除 worktree / 他人机会话的历史留痕，改写它们等于篡改当时的观测）。
- 不动 CI 分支保护、不动 `CI_IGNORED_PATHS`（`scripts/**` 不在白名单内，基线文件天然每次都参与判定）。

## 6. 验收标准

1. 新增两条行为锁：加粗行里的失效路径必须照报；同一行既有加粗、路径自身又含通配/变量/尖括号时必须放行（成对写，防止"把豁免整条删掉"这种反向失守）。
2. 基线三种 FAIL 情形各有用例；基线不可读走退出码 2 且**不**被读成 PASS。
3. "按文件"而非"按总数"：构造一个 A 文件变差、B 文件变好、总数恰好相等的夹具，必须判红（否则汇总口径就能互相抵账）。
4. 全量审计与基线逐文件相等的活体锁。
5. 变异反证逐条实跑且红集互不相同（至少：退回整行豁免 / 比较恒真 / 去掉陈旧检测 / 缺基线读成空允许 / 逐文件改成了全局总数）。
6. `check-unwired-tests` 无新增欠账；Gate 12c 在 `changes` job 里的接线不变。
7. 真仓库现场（不是夹具）：临时新增一份受管文档、内含 1 条失效绝对路径 ⇒ `--all` 必须 exit 1 并
   **点名该文件、且分类计数只有"超出存量基线 1 个"**；删掉后必须回到 exit 0。这条是"账本不会把新增一起豁免掉"的唯一直接证据。

## 7. 风险与代价

- 基线是**数据文件**：以后谁把某条路径修没了，必须顺手改小基线，否则红——这是设计意图（防豁免永久化），代价是多一次编辑。
- 基线里 429 个文件的计数不含行号（按 `文件 → 处数`），不会被别人插行漂移；但**含行尾/编码无关性**要靠
  `git add` 后索引 blob 自证，不靠"应该没问题"。
- 全量重扫基线文件让 Gate 12c 的 PR 侧耗时净增约 **1.4 s**（实测同一条 changeset 命令：无账本下限 418 ms、
  带 429 文件并入 1812 ms；`--all` 为 2.8–3.2 s）。此前写的"约 0.2 s"是没量过的估计，已按实测更正。
- 陈旧登记的两类成因（已删除 / 不再受管）靠 `existsSync` 分流；如果以后有人把判据改成"账本键无条件并入域"，
  "已删除"那一类会退化并被 shrink 顶替——N8 就是这条的反证，红集恰好只有那一条陈旧锁，说明它现在由成因钉住。
- 本 PR 不新增豁免通道；判据只可能变严，不会变松。
