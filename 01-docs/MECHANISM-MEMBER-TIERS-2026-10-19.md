## 0. 结论速览（TL;DR）

1. **维持三档（free / standard / pro），不加第四档。** 16 个竞品样本（国内 7 + 国际 9）中，
   12 个采用「免费 + 2~3 个付费档」结构；头部产品加超高端（可灵黑金、HeyGen Enterprise）服务重度商用，
   但那需要团队协作/SLA 支撑，本项目现阶段无对应能力（DESIGN-MEMBER-CENTER §1.3 明确非目标），加了就是超卖。
2. **档位差异必须从「单轴」升级为「双轴」**：
   - **额度轴（量）**：平台数、日发布、并发、月生成次数——现在已有，继续按档拉开；
   - **功能轴（质与权）**：工作流自动化、产出质量控制、商业化授权、审计与导出——现在几乎全空
     （三档 features 数组仅 `video_create`/`schedule_batch`/`dashboard_full` 三处布尔差异，
     standard 与 pro 的 features **逐字节相同**，2026-10-19 会员中心审计 P1-10 已实锤）。
3. **机制定型为五层权益栈**（§4）：平台能力层 → 工作流自动化层 → 产出质量层 → 商业化层 → 治理层。
   每层给「该层卖什么、哪一档解锁、为什么这么划线」，并给落地优先级（P0 直接可用 / P1 短期 / P2 需新开发）。
4. **机制规则**（§5）：梯度不倒挂、-1 语义只许三处、features 是唯一门禁出口、
   新增维度必须走 `plan-matrix` 契约（NUMERIC_KEYS + 校验 + 测试）——全部对齐既有代码约束。
5. **对外总表**（§6）：一张 40+ 行的「会员套餐内容总表」，可直接用于会员中心价目页与销售物料
   （数值均与 `plan-matrix.js` 现状或本文建议值一一对应，标 ⚠️ 处为未落地、宣传前必须先实现）。

## 1. 现状盘点（代码事实，2026-10-19）

### 1.1 现有三档矩阵（`plan-matrix.js` 逐项）

| 能力 | free | standard | pro |
|---|---|---|---|
| 支持平台数 `maxPlatforms` | 5 | 15 | 不限（-1） |
| 每日发布 `dailyPublish` | 5 | 50 | 1000（非 -1） |
| AI 写稿月额度 `aiWriteMonthly` | 200 | 不限*（自有 Key 前提） | 12000 |
| 视频创作 `videoMonthly` | ✗（0） | 500/月 | 3000/月 |
| 定时/批量 `scheduleBatch` | ✗ | ✓ | ✓ |
| 数据看板 `dashboard` | basic | full | full |
| 官方积分 `officialCreditMonthly` | 30 体验 | 1600/月 | 2200/月 |
| 并发任务 `concurrentTasks` | 1 | 3 | 10 |
| 月付 / 年付 | ¥0 | ¥59 / ¥499 | ¥79 / ¥699 |

### 1.2 三个结构性缺口（本机制要解决的根因）

1. **standard 与 pro 的 features 数组逐字节相同**（`plan-matrix.js:150-153` 派生逻辑只含布尔条件，
   两档全命中）。升级 Pro 在「功能」上买不到任何新东西，只买到额度放大——这解释了为什么审计
   （`01-docs/AUDIT-MEMBER-CENTER-IA-2026-10-19.md` P1-10）发现前端只能靠 `plan !== 'pro'` 硬判档位。
2. **总表里一半是「承诺了但没落地」的行**：`UpgradeModal.vue` 还挂着「API 开放平台」这类
   未实现条目；`pricing-strategy.md` §6 与会员中心审计都记录过「7 天试用无实现」「企业版不存在」。
   本机制明确把每一行标成 **已落地 / 半落地 / 未落地**，杜绝再出现「表格先于代码」。
3. **-1（不限）语义已经出现两处含义不同**（maxPlatforms 真·不限 vs aiWriteMonthly 有 BYOK 前提），
   新增维度如果不立规则，第三处 -1 迟早变成超卖事故。§5 规则 2 直接封掉。

### 1.3 积分体系现状（引用，不展开）

积分是「用量货币」，机制已由两份文档定案：`DEEP-ANALYSIS-CREDIT-PRICING-2026-10-08.md`（定价/赠送量/换算）
与 `DESIGN-COMPUTE-BILLING-MODEL-2026-10-11.md`（三层分离，用户侧单一积分模型）。
心智模型一句话：**会员费买平台能力，积分买 AI 用量**——本机制全部围绕「平台能力」这一侧展开。

## 2. 竞品调研摘要（16 个产品，逐产品官网核实）

> 完整逐产品数据（含出处 URL 与「待核实」标注）见 §附录；本节只摘与「档位机制设计」直接相关的结论。
> 两个调研子代理报告全文已存档：国内 7 家（可灵 / 即梦 / 剪映 / 秘塔写作猫 / 参考产品 / 壹伴 / 通义万相）、
> 国际 9 家（HeyGen / Synthesia / Runway / Midjourney / Jasper / Copy.ai / ElevenLabs / Buffer / Pictory）。

### 2.1 与本项目同赛道的两个最直接对标

- **Buffer（社媒多平台发布，国际）**：Free 3 频道 + 10 条定时帖/频道；Essentials 无限定时帖 +
  高级分析（全历史 + 报告导出 + 自定义 UTM）+ 3 个 API key；Team 无限用户 + 审批工作流 +
  按人分频道权限 + 5 个 API key。**计价单位是「频道数」（1 个社媒账号 = 1 频道），超 10 频道音量折扣。**
- **参考产品（多平台一键分发，国内；域名字面见调研原文，不落库）**：免费版 5 账号点数 / 1 成员 / 500MB 素材库 / **每日 3 次发布**；
  VIP（¥59/月）20 账号点数 / 10 成员 / 5GB / APP 端发布 / 发布次数无限；超 20 账号需买多个权益包。
  **账号数是分发工具的核心定价轴**——两家中外对标产品给出同一结论。

### 2.2 档位结构规律（16 样本）

| 规律 | 证据 |
|---|---|
| 免费档普遍存在但削到「最小可用」 | 16 家中 13 家有免费层；免费额度极小（HeyGen 3 条视频/月、Runway 125 一次性 credits、万相登录赠 100 积分、参考产品每日 3 次发布） |
| 双轨付费：积分管「用量」，档位管「质与权」 | 可灵/即梦/万相：同一生成功能人人可用积分跑，但 1080P/4K、去水印、优先队列、商用授权由档位决定 |
| 分辨率与水印是最低档两大枷锁 | HeyGen Free 带水印、即梦免费档带水印 720P、Synthesia Basic 不可下载；去水印是最强单点付费理由 |
| 商用授权是 B2C 付费分界线 | ElevenLabs Starter 起才有商用授权；即梦标准档起给商用授权；Midjourney 年收入 >$100 万公司强制 Pro/Mega（ToS 条款） |
| 团队协作集中在最高 1-2 档 | 审批流/权限/品牌模板库/SSO 清一色最高档或企业档；个人档卖「产能」，团队档卖「管控」 |
| 加购包「不过期」本身是付费特权 | Runway 加购永不过期、ElevenLabs 加购独立于滚存、可灵充值灵感值 2 年有效——而会员赠积分普遍月清零 |
| 滚存与否是隐性分层手段 | 低档月清零（Runway Standard/Pro、Synthesia）、高档滚存（HeyGen 年付累积、ElevenLabs 滚存 2 个月封顶 3 倍月额） |
| 高频功能按日限额、生产功能按量计费 | 秘塔 8000 字/天 vs 6 万字/天；参考产品 3 次/日 vs 无限；AI 生成按积分/秒、积分/张 |
| 档位间积分差距约 2-5 倍跳档，功能呈阶梯解锁 | 可灵 660/3000/8000/26000；每升一档解锁 1-3 个关键功能，而非全量平移 |
| 计费粒度透明化 + 失败不扣费建立信任 | Synthesia「重生成 3 秒只扣 3 秒」、Pictory「仅导出扣分钟」；可灵官方规则明写「生成失败退回」 |

### 2.3 对本项目的三条直接启示

1. **账号数/平台数就是本项目版的「Buffer 频道数」**——它已经是第一分档轴（5/15/不限），
   保持并继续作为价格锚点。
2. **免费档给「每日小额 + 带限制」**是对的（现有 free 档每日 5 篇 + 30 积分体验额度符合行业惯例），
   不需要改方向；需要补的是**免费档的产出枷锁**（见 §4.3 产出质量层）。
3. **标准版与专业版之间必须插入「质变」而非「量变」**——竞品一致用「商用授权 / 去水印 / 高分辨率 /
   自动化」做分界，这些恰好是本项目已有或近期能力，成本几乎为零。

## 3. 档位框架决策

### 3.1 为什么是三档，不是四档或两档

- **不加第四档（团队/企业）**：竞品团队档的实质内容是席位管理、审批流、SSO、集中计费——
  本项目当前无多用户体系（单账号单设备语义，DESIGN-MEMBER-CENTER §1.3 非目标）。
  加一档「团队版」而没有任何团队功能 = 重复「企业版 v1.0 空头承诺」错误（pricing-strategy §6）。
- **不减为两档**：standard 与 pro 的年付差价 ¥200、积分差 600/月，之间还能承载
  「自动化 + 质量控制 + 商业化」三组功能差异（§4），三档的价格梯度刚好支撑。
- **命名维持 free / standard / pro**：与代码 PLAN_IDS、前端 labels、marketing 全组一致；
  改名是纯 churn，无收益。

### 3.2 档位定位一句话（对齐 01-docs/marketing/03 客群结论）

| 档位 | 一句话定位 | 目标人群 |
|---|---|---|
| free | 「先拿两个号试试，跑得通再放大」 | 个人创作者试用、轻度用户 |
| standard | 「日更五平台的全自动工作台」 | 自媒体运营（5-10 平台、日更 3-5 篇） |
| pro | 「矩阵号的产能与合规天花板」 | 矩阵小团队 / 代运营单人操盘 |

## 4. 五层权益栈（机制核心）

> 设计原则：**每一档相对上一档，至少解锁一个「质变」能力，同时量上保持 3~10 倍梯度。**
> 竞品验证：只有量变没有质变的升档（如 Copy.ai Growth→Expansion，仅席位与 credits 变化）
> 是最弱的升档理由；最强升档理由永远是「解锁了我原来根本做不了的事」（去水印、商用授权、自动化）。

### 4.1 L1 平台能力层（额度轴，现状已有）

| 维度 | free | standard | pro | 划线逻辑 |
|---|---|---|---|---|
| 平台数 | 5 | 15 | 不限 | 对标 Buffer 频道计价：账号数即价值单位；5 够「试错」（marketing/03 S-64），15 覆盖国内主力平台，不限锚定矩阵用户 |
| 日发布 | 5 | 50 | 1000 | 免费档「每日小额」行业惯例（参考产品 3 次/日）；标准档覆盖日更 5 平台；pro 1000 是防除零的高上限而非「无限」（代码注释已明写） |
| 并发任务 | 1 | 3 | 10 | 并发=产能倍率；1 是「串行试用」，3 是「日更工作台」，10 是矩阵批量 |
| 数据看板 | 基础 | 完整 | 完整 | 看「自己发了什么」是免费需求；趋势/绩效/平台分布（dashboard_full 三面板）是运营需求 |

**P0 状态**：全部已实现（`consumeFeature` 扣减 + `requireEntitlement` 门禁在 `cloud_publish` 上已接线）。

### 4.2 L2 工作流自动化层（标准档解锁）

| 维度 | free | standard | pro | 划线逻辑 |
|---|---|---|---|---|
| 定时发布 | ✗ | ✓ | ✓ | 现有 `schedule_batch`，已实现；定时是「挂机」需求，免费档手动发够用 |
| 批量发布 | 单篇 | 批量（≤10 篇/次） | 批量（不限） | **本机制新增的细分**：现状 scheduleBatch 是布尔；建议拆成 `batchSizeMonthly` 数值，标准档给够日更批量，pro 给矩阵批量 |
| 自动流水线（全自动成片→发布） | ✗ | ✗ | ✓ | **P2 新开发**：对标 Copy.ai 的「Chat vs Workflow」分界——自动化工作流是天然的高档墙。现有 AutoPipeline 视图已存在，未接档位门禁 |
| 定时批量上限 | — | 50/月 | 1000/月 | 挂在 dailyPublish 派生额上，无需新字段 |

**P0 / P2 状态**：定时批量已实现；批量细分与自动流水线门禁未实现（见 §7 路线图）。

### 4.3 L3 产出质量层（低成本高感知，竞品验证的最强付费理由）

| 维度 | free | standard | pro | 划线逻辑 |
|---|---|---|---|---|
| 视频生成 | ✗（仅 30 积分体验） | ✓ 500/月 | ✓ 3000/月 | 现有 `videoMonthly`；免费档不给 feature 只给体验积分，与研究报告 §11-7 一致 |
| 视频分辨率 | — | 720P | 1080P/4K | **本机制新增**：对标 HeyGen Creator 1080p→Pro 4K、即梦免费 720P/付费 1080P。实现载体是积分费率（高分辨率高积分）+ `tier_access`（研究报告 §1 已建议：低成本模型全档开放，高成本模型仅 pro） |
| 去水印 / 品牌水印 | 平台水印 | 无水印 | 无水印 + 自定义水印 | **P2 评估**：本项目是分发工具非生成工具，水印语义弱于生成类产品；若 Story2Video/成片导出加水印则按此分层。**先按 P2 搁置，不进总表承诺** |
| 高级模型（高成本档） | ✗ | 标准模型 | 全部模型（含 4K/Pro 档） | 与上一行同机制：`tier_access` 分层，研究报告 §1 第 1 条的「有条件成立」即指此项 |

**划线逻辑**：分辨率/模型档不是「功能开关」而是「费率档」——它通过 ModelPriceCard 的 spec 维度
（`DESIGN-COMPUTE-BILLING-MODEL` 三层分离 L2）与积分消耗自然实现，不需要新 entitlement 字段；
档位约束落在 `tier_access`（pro 才可选高成本 spec）。

### 4.4 L4 商业化层（内容资产归属与用途）

| 维度 | free | standard | pro | 划线逻辑 |
|---|---|---|---|---|
| 内容商用授权 | 仅个人非商用 | ✓ 商用 | ✓ 商用 | **本机制新增**：对标 ElevenLabs Starter 商用授权、即梦标准档商用。这是「质变」分界里成本最低、感知最强的一张牌；免费档产出仅限个人学习/非商用 |
| 内容导出 | 本地查看 | 本地导出 | 本地导出 + 数据回收统计 | 数据回收/绩效统计挂在 dashboard_full；导出本身全档可用（本地优先产品语义，不设门槛） |
| 多版本破查重 | ✗ | ✓（3 版本） | ✓（不限） | 现有 S-06 卖点未分层；按「版本数」分层是天然的量轴 |

**状态**：商用授权是**条款层**变更（ToS/服务协议 + 套餐页文案），代码几乎零成本；
多版本分层需在 rewrite 引擎加 `versions` 配额（P1）。

### 4.5 L5 治理层（最高档专属：管控、审计、优先级）

| 维度 | free | standard | pro | 划线逻辑 |
|---|---|---|---|---|
| 操作审计/发布日志 | 7 天 | 90 天 | 不限保留 | 对标 Buffer Free 基础 Insights（30 天）vs Essentials 全历史；发布历史保留期是纯存储成本，天然好分层 |
| 专属客服 | 社区/文档 | 工单 | 优先工单 | 对标剪映 SVIP「1 对 1 专属客服」、Synthesia Pro 优先客服；P2 建设客服体系后再承诺 |
| API 开放平台 | ✗ | ✗ | ✓（配额制） | **P2，明确标注未落地**：UpgradeModal 里的「API 开放平台」是唯一应该兑现的遗留条目——竞品一致把 API 放在最高档（Buffer Team 5 key、Jasper Business、参考产品 CLI 对接）。但必须先有 API 产品化（配额/计费/文档），才允许出现在任何套餐表 |
| 团队席位/SSO | ✗ | ✗ | ✗ | **明确不提供**（无多用户体系）；三档总表里这一行写「—」，防止前端再出现「API 开放平台」式空头行 |

**状态**：审计保留期 = P1（加 TTL 即可）；API = P2 立项后才准上表。

## 5. 机制规则（保证表格不腐化的六条硬规则）

> 这些规则直接映射 `plan-matrix.js` 既有约束，新增维度必须走同一条路。

1. **单一真源**：所有档位数值只活在 `plan-matrix.js`；`GET /api/v1/plans` 下发，客户端禁止硬编码。
   本文档的总表每季度对照 `PLAN_MATRIX_VERSION` 核对一次，版本号不一致时以代码为准。
2. **-1（不限）白名单**：仅 `maxPlatforms` / `aiWriteMonthly` / `videoMonthly` / `officialCreditMonthly`
   四个键允许 -1（`UNLIMITED_ALLOWED`）。**新增的任何「不限」字段必须先加进该白名单并写明语义**，
   `dailyPublish` 永远不允许 -1（会击穿 `consumeFeature` 的 `limit >= 0` 校验）。
3. **features 是门禁唯一出口**：档位间的「质变」差异必须落成新 feature 名（如 `auto_pipeline`、
   `api_access`）进 features 数组，渲染层经 `entitlement-gate.hasFeatureOf()` 判定；
   禁止 `plan === 'pro'` 式硬判（entitlement-gate.js 注释已点名）。
4. **每档 features 必须可区分**：新增 feature 后跑契约测试断言
   `free.features ⊂ standard.features ⊂ pro.features` 且为真子集——修复「standard/pro 逐字节相同」
   的结构性缺陷（审计 P1-10）。
5. **数值键三关校验**：新数值键必须同步进 `NUMERIC_KEYS`（可 override）或明确加入不可覆盖清单，
   过 `validateNumericValue`（整数、≥-1、白名单 -1、MIN_ONE）。
6. **承诺与实现对齐**：总表任何一行在进对外物料前，必须满足三者之一：
   ① 代码已实现并测试；② 行内标注「规划中」；③ 从表中删除。「先写表后补码」被明确禁止
   （这是 UpgradeModal「API 开放平台」教训的机制化）。

## 8. 风险与边界

1. **不要在营销物料宣传 §4.2/§4.5 的 ⚠ 项**（自动流水线、API）直到落地；
   现有 `UpgradeModal.vue` 的「API 开放平台」一行应随最近一次 UI 批次删除（属 AUDIT-MEMBER-CENTER
   P0-6 冲突消解的一部分）。
2. **「不限」话术红线**（继承 pricing-strategy §7.3）：不说「专业版不限发布」（是 1000）、
   不说「标准版 AI 写稿不限」不带 BYOK 前提。
3. **年付数学**：若未来调整积分赠送量，必须重跑 DEEP-ANALYSIS §6.1b 的年付成本校验
   （¥199/年「月清零 + 月发」无法盈利的教训）。
4. **本机制不处理**：支付通道（P2-PAYMENT spec）、积分引擎实现（独立立项）、
   团队/企业能力（明确非目标）。

### A.3 竞品机制规律全表（两报告合并去重，16 条 → 保留 12 条）

1. 免费档最小可用化（13/16 有免费层）。
2. 双轨制：积分管用量、档位管质与权（国内三家 + 国际五家 credits 产品一致）。
3. 水印 + 分辨率是最低档两大枷锁。
4. 商用授权是 B2C 分界；收入门槛（Midjourney $1M）是 B2B 强制高档条款。
5. 团队协作（审批/权限/品牌库/SSO）集中最高 1-2 档。
6. 加购包不过期 vs 会员赠额月清零，是并行存在的两套时效。
7. 滚存与否是高低档隐性分层（Runway Max 1 月 / ElevenLabs 2 月封顶 3 倍）。
8. 高频功能按日限额、生产功能按量计费。
9. 档位间积分 2-5 倍跳档 + 每档解锁 1-3 个关键功能。
10. 年付改变额度结构（一次性发全年 / 滚存 / 折扣 17-40%），且定价页默认年付呈现。
11. 「频道数/账号数」是多账号分发工具的天然计价单位（Buffer 频道、参考产品账号点数）。
12. 计费粒度透明 + 失败不扣费是信任基建（Synthesia 按实际秒、Pictory 仅导出扣、可灵失败退回）。
