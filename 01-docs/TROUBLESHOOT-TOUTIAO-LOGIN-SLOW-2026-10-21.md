# 头条号登录慢排障手册 — 2026-10-21

> 场景：账号页「添加头条号账号」→ 新标签打开头条号登录页 → 填手机号 → 点「发送验证码」
> → 页面**灰显**（平台自己的遮罩）→ 等好几秒才弹出图形验证码窗口。
>
> 本手册分三段：**先分清是谁的锅**（实测结论）→ **立刻能用的绕行** → **怎么配**（方法与验证）。
>
> ⚠️ 具体要粘进 OpenClash 的**域清单**不在本文件里：它属于「本机网络配置」，
> 与本仓的公共文档混放会被外部评审判为泄露内部网络信息。清单见本 PR 的评论
> （PR #4237），或直接向维护者索取。

---

## 一、结论（2026-10-21 真机实测，不是推测）

**不是应用代码的锅。** 复现与归因链如下：

| 观测点 | 实测读数 |
| --- | --- |
| 应用日志（今天 10:11、10:15 两次复现） | 登录页 load 事件耗时 1.5s / 6.2s / **28.4s**；登录会话走 `DIRECT`（未走账号代理）；视图 `drawn=true` 未被后台节流 |
| 对照组：**完全无关的浏览器**（桌面端内嵌浏览器，独立 profile）加载同一个头条号登录页 | **23.8 秒**，症状一模一样 |
| 元凶：登录页引用的埋点脚本（字节自家静态 CDN 域） | 被**字节自己的边缘节点 504**，要挂 **9~17 秒**；Content-Type 是 `text/html`，所以被浏览器 ORB 拦掉 |
| 外部网络对照（让一个外部服务从它自己的服务器拉同一文件） | **同样 504** ⇒ 这是**字节侧在坏**，换台电脑也一样，规则救不了 |
| 图形验证码组件 | 风控 SDK 主包（~520KB）+ 验证码组件包（~784KB），冷下载各 ~1.1s ⇒ **「灰显几秒」就是它** |
| 顺带发现：登录页自带资源 | 43MB 背景视频（分段请求）+ ~10MB 图片 |

**本机网络侧的加成因素**：路由器上跑着 Clash/OpenClash（fake-ip 模式，DNS 全劫持，
显式查公共 DNS 也返回 `fake-ip 池地址段`；外部控制口需要密钥）。字节系域名因此走代理节点，
链路更不稳（实测验证码 SDK 冷下载 1.1~1.3s）。

## 二、立刻能用的绕行（按推荐顺序）

1. **头条号改用「扫码登录」**（账号页「添加账号」弹窗里选「扫码登录」）。
   扫码链路轮询 `sso.toutiao.com/check_qrconnect/`，实测 **80~600ms/次**，完全不走图形验证码组件。
2. **把字节系域名在 OpenClash 里放行直连**（下一节）。这是最直接的：让这些域走本地直连，
   不经代理节点。
3. **换线路/节点**试一次：同一个资源在别的出口可能不 504（字节的 504 是它自己边缘节点的行为，
   不同出口命中不同边缘集群）。

## 三、怎么配（方法与验证）

### 3.1 界面路径

OpenClash（LuCI 插件）→ **覆写设置**：

| 要改什么 | 在哪 |
| --- | --- |
| 规则（让字节系直连） | 覆写设置 → **自定义规则**（每行一条，会插到规则链最前） |
| DNS（让字节系拿真实 IP 而不是 fake-ip） | 覆写设置 → **DNS 覆写** → 找到 `fake-ip-filter` 段追加 |

> 改完必须点 **应用配置 / 保存并应用**，让 OpenClash 重写 `config.yaml` 并重载内核；不重载规则不生效。

### 3.2 规则的形状（**域清单见 PR #4237 的评论**）

规则是 Clash 的一行一条，形如：

```
DOMAIN-SUFFIX,<平台主域>,DIRECT
```

`DOMAIN-SUFFIX` 命中该域**及其所有子域**（`mp.<主域>`、`sso.<主域>` 都在内）。
把 PR 评论里那份头条号实测域清单逐条粘进「自定义规则」即可。

fake-ip 过滤器的形状（粘进 DNS 覆写的 `fake-ip-filter`）：

```
+.<平台主域>
```

`+.` 前缀表示「该域及其所有子域都不分配 fake-ip」，DNS 会直接返回真实 IP。
有些 OpenClash 版本写 `*.<主域>` 也认；两种都试一下，以 `nslookup` 的返回为准。

**别写 `REJECT`/`REJECT-DROP` 到整段静态 CDN 域**：那些域里除了坏掉的那一个埋点脚本，
还有登录页自己的资源，整段拒了可能连登录页都加载不出来。

### 3.3 可选加速：让那个 504 的埋点脚本**快速失败**

被 504 掉的那个埋点脚本会**挂 9~17 秒**才失败，把页面的 `load` 事件拖住。
可以给它加一条 hosts 覆写，让它**瞬间失败**（连接被拒），页面随即完成加载：

```
127.0.0.1 <那个埋点脚本的主机名>
```

该脚本只是统计埋点，登录流程不依赖它。
代价：若哪天字节修好了，这条会继续让它失败（影响仅限一个统计脚本）。
**这是可选项，不是默认动作**；先按 3.2 观察，不行再加。

### 3.4 怎么验证生效了

在电脑上（Windows PowerShell）：

```powershell
# ① DNS 不再返回 fake-ip（应看到真实公网 IP，而不是 fake-ip 池地址段）
nslookup mp.toutiao.com

# ② 关键资源的首包耗时（对比改动前后）
curl.exe -o NUL -w "ttfb=%{time_starttransfer} total=%{time_total}`n" <验证码 SDK 的 URL>
curl.exe -o NUL -w "ttfb=%{time_starttransfer} total=%{time_total}`n" https://mp.toutiao.com/
```

- ① 仍返回 `fake-ip 池地址段` ⇒ fake-ip 过滤器没生效（检查是否写在了 `fake-ip-filter` 段、是否重载了内核）。
- ② `ttfb` 明显变小 ⇒ 直连生效。
- 再看 OpenClash 的**连接面板**（地址与密钥在插件设置 →「外部控制面板」那一栏）：
  头条相关域名应当显示 **DIRECT**。

### 3.5 做完规则后仍然慢，怎么判断是哪一层

| 现象 | 结论 |
| --- | --- |
| `nslookup` 仍是 `fake-ip 池地址段`，连接面板显示走代理 | 规则/fake-ip 过滤器没生效（多半是没重载） |
| 资源直连也慢、`ttfb` 几秒 | 出口线路问题（换节点/换运营商） |
| 资源直连很快，但登录页仍要 20s+ | 页面在等那个 504 的埋点脚本（字节侧故障）⇒ 只能加 3.3 的 hosts 覆写或等字节修 |
| 只有图形验证码弹出慢 | 风控 SDK 冷下载（1.3MB）⇒ 应用侧已改为按平台复用分区，第二次起命中缓存（本仓 change `login-slot-reuse-and-toutiao-diagnostics`） |

## 四、别做的事

- **别把整个静态 CDN 域整段 REJECT**：同域还有别的资源。
- **别指望规则能修那个 504**：字节自己的边缘节点在坏，外部网络复现同样 504。
- **别在应用里注入脚本去改第三方登录页行为**：那是平台页面，注入既越界又易随平台改版失效。
- **别把「本地网络慢」当成唯一结论**：本次已用「无关浏览器 + 外部网络对照」两条证据
  把责任分到「字节侧故障」与「本机代理线路」两段。

---

## 五、应用侧已做的两件事（本仓 PR #4237）

1. **登录视图按平台复用分区**：同一平台复用同一分区目录（`auth-auth-<platform>-slot`），
   只清凭证、不清 HTTP 缓存 ⇒ 第三方登录页的静态资源与风控 SDK 第二次起命中缓存，
   「灰显几秒」显著缩短。
2. **头条号登录期网络观测**：头条的请求域进入登录诊断过滤面，并新增「慢请求」
   「验证码组件加载完成」「监测域请求失败」三类日志 ⇒ 下次复现时日志能直接给出时间线，
   不用再靠外部抓包倒推。

`openspec/changes/login-slot-reuse-and-toutiao-diagnostics/`。
