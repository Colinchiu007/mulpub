# PRD 切片：Gate 12c 的判据由「路径是否存在」改为「路径是否新增」（gate-12c-abs-path-ban，2026-10-14）

## 1. 问题（第一性原因）

上一条 PR（#3583）把占位符豁免从「整行」收紧到「路径词元」，并落了按文件存量基线。合入后拉 CI 现场日志
（run `38572799318` / job `115882369237` / step `Gate 12c - Doc abs-path validity (changes job)`）读到的是：

```
PASS（…扫描 438 个文件）… 现场存量 0 处已按文件对齐；…
本机无盘符 ⇒ 逐文件计数比较未执行（仅核对陈旧登记与账本放宽）；**无从判定 1094 条** Windows 绝对路径
```

读判据源码定位到第一性原因，**不是"CI 用了 Linux"，而是判据的输入选了文件系统**：

`scanFile()` 只在 `firstMissingSegment(frag, driveRoots)` 非空时才 push。`driveRoots` 是本机存在的盘符集合，
Linux runner 上 `C:`…`Z:` 全不存在 ⇒ 该函数对**每一条**路径返回 `null` ⇒ `findings` 恒空 ⇒ 现场计数恒 0。
一个恒 0 的量拿去和账本比大小，两个方向（超出 / 待收紧）都不可能红。

⇒ 只要判据是「这条路径还在不在」，它就必然要问一台**有那个盘**的机器；而 CI 的主力 runner 没有。
这不是配置问题，是**判据选错了可观测面**。

## 2. 为什么"改成数路径、不问存在"是更强的判据而不是更弱的

新判据：**受管文档里出现的、词元自身不含占位符的 Windows 绝对路径，按文件计数；计数只能等于或小于账本。**

三条收益，逐条都是旧判据做不到的：

| 判的东西 | 旧（存在性） | 新（计数） |
| --- | --- | --- |
| 需要访问文件系统 | 是（ ⇒ CI 恒 0） | **否**（Linux 上照判照红） |
| 挡住「写下时就已失效」的路径 | 能 | 能 |
| 挡住「写下时对、后来 worktree 被删才失效」 | **不能**（当场绿，之后才红；而这正是 870 处存量的主要来源） | **能**（新写的动作本身即违规） |
| 挡住「写新路径同时把账本调大」 | 靠 `judgeLedgerDrift`（不需盘符，这条保留） | 同左，两把互为补位 |

代价：**执行记录会失去一部分取证力**——规范本来就要求记「运行时在哪个 worktree、裸分支名是什么」。
出路是既有先例里已经在用的占位符（`mp-<task>`、`<user>`、`<buildTag>`），而豁免机制按**词元自身**生效，
所以「用占位符写现场」在新判据下依然合法、在旧判据下本来也合法。不新增约束形态，只把约束提前到写入时。

第 3 行是本 PR 立意的经验基础：**「新写一条死路径」不是罕见事故，是每几篇文档一篇的频率**，
而旧判据对它有一整个时间窗的失明（写的时候路径还活着）。

## 4. 方案

### 4.1 判据本体

`scanFile()` 无条件 push，带上 `missing` 字段（`null` = 存在性核对未给出否定结论，含无盘符情形）。

- **计数口径** = push 出来的全部（已经过词元占位符豁免），与 `driveRoots` 无关；
- **报告口径** 保持旧行为：`FAIL` 明细仍只列「磁盘上不存在」那些，且只有 `canJudge` 时才列；
- `judgeBaseline()` 的 `over` / `shrink` **不再受 `canJudge` 门控**（这是本次修的正是那一行门控）；
- `countUnjudged()` / `formatSkipNote()` 的措辞随之改写：无盘符时不再是「逐文件计数比较未执行」，
  而是「存在性核对未执行（N 条未核对），新增判定照常」。

### 4.2 账本口径换代必须显式，且只允许发生一次

新口径下每个文件的计数**只会不低于**旧口径（同一批命中，少一个过滤器），因此迁移那一次必然是「全表上升」。
而 `judgeLedgerDrift` 的设计恰恰是把上升判成「账本被放宽」。若直接放行，就留下
「想洗放宽就把 reason 改一改」的旁路；若直接拦，迁移 PR 又被自己的守卫打死。

做法是给账本一个**由判据代码持有的版本号**：

```js
const METRIC_VERSION = 'all_abs_paths_v2';   // 判据源码里的唯一真源
// 账本 JSON 增加 "metric" 字段；loadBaseline/parseBaselineText 校验
//   ledger.metric === METRIC_VERSION，否则报「账本口径与本判据版本不符」⇒ 退出码 2（自身故障档，不是结论）
// judgeLedgerDrift 增加一条：prev.metric !== next.metric ⇒ 跳过"放宽"判据、大声报
//   「账本口径换代 v1→v2，逐文件计数不可比」；但**仍然照报** tightened（缩小）与陈旧登记
```

为什么这个豁免是一次性的、不能反复用：换代之后 base 上的账本已带 `metric === METRIC_VERSION`，
下一个 PR 若想再走这条豁免，必须让 base 账本的 metric 与 head 不同——而 base 就是刚合入的这份，
于是它必须**先把账本改回旧值**再改回来，而那会在别的 PR 里先红。加上 `ledger.metric !== METRIC_VERSION
⇒ 退出码 2`，"改个字符串"拿不到放行。

### 4.3 `--write-baseline` 的 `!canJudge` 拒绝随之取消

原拒绝的理由是「无盘符时现场计数恒 0，重写会把账本写成空表并以 0 退出」（#3583 axis1c F1）。
新口径下计数与盘符无关，该前提不再成立 ⇒ 放松为只保留 `!all` 那条拒绝，并把这条变化写成一条锁
（否则"放松"本身没有回归保护）。

## 5. 测试计划

- 结构层：`scanFile` 命中集合在无盘符入参下**非空**（旧实现在这里恒空，正是本次要红的方向）；
- 判据层：`judgeBaseline({canJudge:false})` 仍能给 `over`（旧行为是两支清空）——**这条就是 #75 那个洞的锁**；
- 报告层：`canJudge:false` 时 FAIL 明细不得出现「磁盘上不存在」这类它没核对过的话，但计数违规照报；
- 换代层：`prev.metric !== next.metric` ⇒ 不报放宽但出声；`ledger.metric !== METRIC_VERSION` ⇒ 退出码 2；
- 迁移层：真实仓库上 `--all` 与 `--all` 重写后的账本逐文件满足 `new ≥ old` 且 `new - old` 的差**只来自被吞掉的"路径存在"那一类**（差集抽样人工核对，写成可重跑探针）；
- 反证：把 `over` 重新挂回 `canJudge` 必须让上面那条计数锁当场红（这条是"改判据而不是改说法"的落点）。

## 5.1 夹具的跨平台化（CI 二跑，2026-10-15 补）

判据与盘符无关 **不等于** 自测与盘符无关。第一轮 CI 红在"真实存在的路径"那批夹具（`os.tmpdir()` 在
 ubuntu 上是 POSIX 形状），修的是 `asWindowsShape()`；第二轮还红 2 条，红在**批量锁共用的另一只夹具出口**
`deadPaths()` / `missingPathUnderLocalDrive()`：它们用裸的盘符变量拼路径，无盘符档拼出一个**没有冒号的串**，
判据不报错、只是静默不计数 ⇒ 账本 1 / 现场 0 ⇒ 被自己的 `shrink` 判红。

三条落点（缺一不可，第 2、3 条是本轮真正的机制收获）：

1. **夹具盘符收敛为唯一出口** `fxDrive()`：有盘符用真的，无盘符用合成字母（运行时拼接，避免本文件被自己计数）。
   只改一处，17 条共用该出口的锁一起跨平台；逐条改断言必漏。
2. **测的是判据，验的必须是夹具**：已有的 A/B 锁用另一只出口（`anyAbsPath`）构造路径，对本次失效**完全免疫**。
   所以新增「夹具自检」锁，直接量那两只共用出口，并且**让门禁自己数一遍**（`counts=2`）——
   只断言"形状像 Windows 绝对路径"是必要条件不是充分条件；反向也配一条结构禁令（不得再出现裸盘符拼接），
   禁令自带正控与反失明断言（扫描域退化必须红，不许"0 命中"蒙过）。
3. **把只有 CI 能验的那一维搬回本机**：自测文件加 `MP_TEST_FORCE_NO_DRIVE=1`，等价于 ubuntu 的"无盘符"档。
   诚实边界：它模拟的是 `driveRoots` 为空 + `canJudge=false`，**不**改变 `os.tmpdir()` 的形状，
   所以第一轮的 8 红类型它抓不到，CI 仍是最终判据；两档本机全绿 ≠ 跨平台已证。

方法论一条（本 PR 的两个驱动缺陷都归到这里）：批量改写测试文件的脚本必须自带**不变量**，
而不是靠"跑一遍看看"。本轮实测：第一版把 `test(...)` 声明行连同门控一起删（16 条用例静默消失，
`node --test` 只在个别位置报错）；第二版把声明行与门控之间的说明注释整段吞掉。
正解是在驱动内断言 `^test(` 计数改前后**逐字相等**，并用 `git diff` 的删除行反查"除门控块外还删了什么"。


## 6. CI 侧

**不改任何 workflow**。这条判据今天已经接在 `quality-gate.yml` 的 `changes` job（`check-doc-abs-paths.test.js`
+ `--base --head`），换的只是它能不能判。因此不触发「改谁来守门」的人工过目条件；
`changes` 作业 29 s 的现状也不变（无盘符 ⇒ 少一批 `stat` 调用，实测只会更快）。

## 7. 不修（登记）

- 词元终点仍以**空白**切分：路径里合法含空格时会把后续内容吸进词元（#3583 已记 F4/F10/F12 同族，本次不扩面）。
- `exists` 标志不落进账本，账本只存计数：跨机不可复现的信息不进基线，避免"在我机器上是活的"变成豁免理由。
