一套面向「一份稿件投递到 14 个平台」的全流程界面图。核心主张：颜色 = 目的地（每个平台一个身份色），形状 + 图标 + 文案 = 状态（成功/失败/进行中不靠颜色区分）。外壳是靛蓝单色玻璃（浅底 + 渐变光斑 + 霜化层），工作区保持冷灰阶，让唯一的彩色层留给平台身份；签名元素是贯穿全应用的信号轨与Hero 系统——前者回答「这份内容现在到哪儿了」，后者用一条渐变横幅回答「这一屏现在是什么状态」。

01
主按钮用墨色，不用彩色。

全应用唯一的实心主按钮是 #15181F。任何带彩色的实心按钮，只允许出现在「按平台投递」这类颜色本身承载语义的位置。

02
外壳保持浅灰（#E9ECF1），层级靠明度差和发丝线撑。

侧边栏与标签栏是浅灰底，地址栏与激活页签是白底，选中导航项是白卡浮起（1px 描边 + 极轻投影），分隔靠 1px 发丝线。整窗明度接近，平台色才是画面里唯一的彩色层。

03
焦点环用墨色 + 2px 偏移，不用蓝。

避免与知乎蓝等平台色抢读；全应用统一一套，无需按深浅区域切换。

04
平台徽标用官方图标，不用彩色字母块。

图标本身已携带身份色（抖音黑底青粉、B站蓝、微信绿），色块只作底衬，避免重复着色导致失真。

05
平台色永不表示状态。

小红书红 ≠ 失败。状态一律由字形承担：● 进行中 / ✓ 已完成 / ! 失败 / ○ 待发。

06
色系相近的平台必须与官方图标同现。

小红书（#FF2442）与微博（#E6162D）同属红系，纯色块无法区分——所以日历图例、图表条、列表行一律用「图标 + 名称 + 颜色」三重编码，绝不出现无标签的裸色块。

07
语义色只做低饱和深色。

成功 #1E7A45 / 警告 #B4750E / 失败 #A8232B，与任何平台色不同调，且永远伴随字形与文案，不单独用颜色传递信息。

08
失败态在行内用左侧 3px 深红竖条标出。

这是全局唯一允许「红」的装饰性用法，用来在长列表里快速定位。
