# PRD — 桌面应用首页 UI 视觉优化落地（参考竞品风格迁移）

| 字段 | 内容 |
| --- | --- |
| 文档类型 | PRD / 落地方案 |
| 优先级 | P2（体验优化，不影响现有功能） |
| 影响面 | `apps/desktop/src`（渲染进程 UI 层） |
| 竞品名称处理 | 本文档中「参考产品」指代调研对象（蚁小二），文档内不直写竞品名以过品牌残留门禁 |

## 1. 背景与目标

对参考产品首页截图做了视觉分析（见会话记录 2026-10-12），其风格核心是：浅色中性底 + 白色圆角卡片 + 克制的品牌色 + 语义化告警色 + 右侧配额仪表栏。本方案把可迁移的设计内核落地到 Multi-Publish 桌面应用首页。

**目标**：
1. 首页视觉现代化：卡片化、留白、语义色，保持现有信息架构不破坏。
2. 抽取一组设计 token（颜色/圆角/阴影/间距），供后续页面复用，避免散落硬编码。
3. 新增「待处理提醒条」与「用量仪表卡」两个可复用组件模式。

**非目标**：
- 不改任何业务逻辑、IPC、主进程代码（纯渲染层）。
- 不引入第三方导流卡、客服二维码等竞品特有模块。
- 不做暗色主题（本期为浅色基线）。

## 2. 设计 Token（第一步，独立可交付）

新增 `apps/desktop/src/styles/tokens.css`（或注入既有全局样式入口），单一定义来源：

```css
:root {
  /* 品牌主色（紫蓝系） */
  --mp-brand-500: #6366f1;
  --mp-brand-600: #4f46e5;
  --mp-brand-100: #eef2ff;
  --mp-brand-50:  #f5f7ff;

  /* 语义色 */
  --mp-danger-500: #f04438;
  --mp-danger-50:  #fef3f2;
  --mp-warning-500: #f79009;
  --mp-warning-50:  #fffaeb;

  /* 中性 */
  --mp-bg-page: #f7f8fa;
  --mp-bg-card: #ffffff;
  --mp-text-primary: #1d2939;
  --mp-text-secondary: #667085;

  /* 形状与投影 */
  --mp-radius-card: 10px;
  --mp-radius-icon: 8px;
  --mp-shadow-card: 0 1px 3px rgba(16, 24, 40, 0.06), 0 1px 2px rgba(16, 24, 40, 0.04);
  --mp-shadow-card-hover: 0 4px 12px rgba(16, 24, 40, 0.10);

  /* 间距栅格 */
  --mp-space-2: 8px; --mp-space-3: 12px; --mp-space-4: 16px; --mp-space-6: 24px;
}
```

**约束**：
- 禁止散写 hex；新样式一律引用 token。
- 若项目已有 Element Plus 主题变量，优先映射到 Element 变量（`--el-color-primary` 等）而不是并行造一套——落地时以现状为准，取交集最小改动。

## 3. 首页布局改版

目标结构（自上而下）：

```
┌────────────────────────────────────────────────┐
│ 问候条：午安，<用户名> 👋   ·   团队/账号概览     │
├──────────────────────────────────────┬─────────┤
│ [主任务卡] 开始发布                    │ 右侧栏   │
│   大数字指标：连续发布 N 天            │ 用量仪表 │
│ [次任务卡] 授权账号 (+)               │ 卡       │
│ [提醒条]   登录失效 N 个账号待处理 →   │ 帮助入口 │
│ [常用入口网格] 2×3 图标卡             │         │
└──────────────────────────────────────┴─────────┘
```

### 3.1 问候条（P1）
- 文案按时段问候（早/午/晚），用户名取本地昵称；无昵称时降级为「你好」。
- 右侧展示一行概览：已授权账号数 / 待发布任务数（数据源复用现有首页已有统计，不新增 IPC）。

### 3.2 主任务卡「开始发布」（P0）
- 现有发布入口升级为大卡：图标方块（品牌色淡底）+ 标题 + 一句描述 + 右上角弧形淡紫渐变装饰（纯 CSS `background: radial-gradient` 或 `::before`）。
- 内嵌大数字指标「连续发布 N 天」：从本地发布历史统计（已有数据则复用；无数据源则本期显示占位「—」，不新增后端）。

### 3.3 待处理提醒条（P0，可复用组件）
- 结构：左告警图标 + 标题 + 计数徽章（`2 个账号待处理`）+ 说明文案 + 右侧描边按钮（如「批量授权」）。
- 场景：账号登录失效、发布失败待重试、配额将满。首期只接「登录失效」；组件 props 设计为通用（`severity / title / count / description / actionText / @action`）。
- 无待处理项时不渲染（不留空壳）。

### 3.4 常用入口网格（P2）
- 2 行 3 列卡片：图标 + 标题 + 一句描述，hover 抬升阴影。
- 内容按现有功能填（AI 创作、素材库、数据看板、投放等），低频入口仍走侧栏「更多」，不在首页重复展开。

### 3.5 右侧栏用量仪表卡（P1）
- 卡片头：当前套餐/许可证名称徽章。
- 列表行：`标签 ......... 已用 / 上限`（右对齐数值，等宽数字 `font-variant-numeric: tabular-nums`）。
- 行项：授权账号数、当月发布次数、素材容量（以现有可获取数据为准，取不到的行不显示）。
- 底部 CTA：仅在有升级/开通场景时显示，否则省略。

## 5. 技术约束（沿用项目既有门禁）

- 纯渲染层改动；**不新增 IPC、不新增用户可见中文字面量在非 locales 文件**——所有新文案写入 `apps/desktop/src/locales/zh.js` 与 `en.js` 成对提交（CI Gate 7 拦截）。
- 新组件落在 `apps/desktop/src/components/`（遵循现有目录惯例），组件测试同目录/同 test 惯例，TDD：先写组件测试（渲染分支：有无计数徽章、无数据降级、action 触发）。
- 新增模态/浮层不涉及本期；若 T2 的提醒条需要点击后弹确认，须走 `useEmbeddedViewSuspension` 合同——首期设计为跳转页面、不弹模态，规避该复杂度。
- 外部 URL（帮助文档链接）绑定 href 前过 `safe-http-url.browser.js`（渲染侧判据），不得新增第二份 `/^https?:/`。
- 打包验证：QM-1 需本地 `electron-builder --win` 打包 + 8 秒启动捕获 stderr（本次改渲染层，仍按门禁完整走一遍）。
- 视觉证据：QM-4 截图（改版前后对比）存 `openspec/records/<分支>.md`。

## 6. 验收标准

1. 首页三段式布局上线，浅色卡片风格与 token 一致（走查：无散落 hex）。
2. 登录失效时提醒条出现、计数正确、点击进入账号授权页；失效清零后提醒条消失。
3. 「连续发布 N 天」在有数据时正确显示、无数据时显示「—」不报错。
4. zh/en locale 成对通过 CI；`pnpm test` 相关组件测试全绿。
5. 打包后启动 8 秒 stderr 干净；前后截图对比落档。

## 7. 风险与取舍

| 风险 | 处置 |
| --- | --- |
| 现有首页结构耦合较深，改版面大 | 分 6 个小 PR 逐块落地，每块独立可回滚 |
| 用量数据可能没有现成 IPC | T5 数据源先盘点；取不到的行不显示，不为此新增主进程接口 |
| 「连续发布天数」无数据源 | 首期从本地历史统计或占位「—」，升级另行立项 |
| 竞品风格被指抄袭 | 只迁移「模式与 token」，不复制截图素材、图标、文案；文案全部自创并进 locales |
