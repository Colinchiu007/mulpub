## 三、公共发现

### 3.1 两平台共用签名服务

| 维度 | 快手 | 小红书 |
|------|------|--------|
| signCommand | "kuaishou" | "newxiaohongshu" |
| 输入 | MD5(bodyStr) | JSON([path,encodedBody]) |
| 输出 | sig3 string | JSON{X-s,X-t,a1} |
| 缓存 | 有 | 无 |
| 重试 | 1+1 | 3x port rotation |

### 3.2 本地公式关键发现

bundle 中 getSign$5 的输入是 MD5(bodyStr) 即整个请求 body 的 MD5。
而本地注册表 getKuaishouSign(body, apiPh) 的公式为 MD5(api_ph | JSON(body))。
两者输入格式不一致，S0 探针须验证本地公式是否被平台接受。

### 3.3 api_ph 提取器

regex = /kuaishou\.web\.cp\.api_ph=([a-z0-9]+)/
所有快手链函数依赖此正则从 cookie string 提取 api_ph。
缺失时 fallback 为 Guid.NewGuid().replace(/-/g,"") 新生成。

## 四、Spike S0 判据设计依据

S0 正确做法：对最低风险已认证查询端点(getUserInfoResponse$3)分别发：
1. 不带 __NS_sig3 -> 预期被拒
2. 带本地公式 sig3 -> 观察平台接受性
3. 带空字符串 sig3 -> 观察
