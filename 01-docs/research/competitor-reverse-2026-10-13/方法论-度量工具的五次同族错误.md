# 方法论：度量工具的五次同族错误与机械防线

> 记录时间：2026-10-13
> 性质：**工具方法论复盘**。源自 2026-10-13 单日内，我在分析度量工具中连续犯下的 5 次同型错误。
> 配套脚本：`measure-report-citations.cjs`、`verify-wemedia-c1-escape-bug.cjs`、`analyze-wemedia-taxonomy-v2.cjs`

---

## 0. 一句话

**一天之内，我在自己的度量/解析工具里犯了 5 次同一族的错误，两次据此得出了错误结论、并准备据此去「修」没问题的东西。**

根因只有两条：

1. **正则匹配不到 ⟹ 我判定它不存在**（把「我测不到」当成「它没有」）
2. **同一事实有两处实现 ⟹ 必然漂移**（改一处不生效，或两处判据不一致）

两者都**不靠临场自觉能避免** —— 只能把工具改成 **fail-loud**（测不到就报「未识别」，不报 0）。

---

## 1. 五次错误全记录

| # | 工具/场景 | 我的做法 | 漏掉的形态 | 由此得出的错误结论 |
|---|---|---|---|---|
| 1 | `verify-wemedia-c1-escape-bug.cjs` 提取 `escapeMap` 的键 | `/^\s*"(.)":/gm` | **单引号包裹的键** `'"': "&quot;"` | 「缺 `"` 和 `/` 两个键」（**实为只缺 `/`**）|
| 2 | 引用密度度量（内联 PowerShell） | `/\w+\.(js\|html\|css):\d+/` | **简写形态** `:51-61`（无文件名前缀） | 「xhs 报告证据密度只有 **16%**」（**实为 41%**），并准备据此「补强」一份**本来没问题**的报告 |
| 3 | `analyze-wemedia-taxonomy.cjs`（v1） | 假设分类映射只有 `{id,name,cates}` 一种形态 | `{code,text}`（抖音扁平）、`{child,...}`（百家嵌套）、`{childrenCate,level,parentCate,...}`（搜狐任意深度） | 节点数报 **3,838**（**实为 11,623，少算 67%**）|
| 4 | 同上，v2 首版 | 要求分类节点「有 name 字段」 | **「键即分类名」**形态 `{"一级":["二级",...]}` | 36 个 `*subcategort.txt` 判为「未识别」（实为可用）|
| 5 | 同上，v2 二版 | 值必须是数组或对象 | **值可以是 `null`**（`{"新闻资讯":null}`） | 剩余 14 个文件判为「异常」（实为正常）|

**共同点**：每一次，工具都**静默返回了一个偏小的数字**，而不是报错。错误的表现形式是**数字偏小**，不是**红灯**。

## 2. 派生出的 3 个工具自身 bug

在「给工具加防线」的过程中，又暴露出 3 个 bug —— **全部属于同两族**：

| # | bug | 后果 | 归属 |
|---|---|---|---|
| 6 | 改写时**弄丢了 `fail += alarm ? 1 : 0`** | **一个专防「静默放过」的工具，自己静默放过了** —— 明明报警，却打印「总判定: 全部通过」并 `exit 0` | 判据未接线到结论 |
| 7 | `NOT_CITATION` 数组是**死配置** —— 分类循环里硬编码了自己那三条判据 | 改这个数组**完全无效**，`9:16/16:9` 一直被误报为「未分类」 | 同一事实两处实现 |
| 8 | 交叉校验写成了**双向** | 在**成功复现缺陷**时中止 —— 把「发现」误判成「故障」 | 判据语义搞反 |

**#6 尤其值得记住**：它证明「加一条 fail-loud」这个动作本身**也需要被验证** —— 否则你只是多了一个**看起来在报警、实际不改变退出码**的装饰。

## 3. 机械防线（三层）

### 3.1 第一层：双界 + 形态归类（`measure-report-citations.cjs`）

不再用「一个正则数一个数」，而是**同时算松紧两界 + 逐处归类**：

```
松界（含 ':数字' 的行）      : 275   ← 上界，只会多算
下界（确定档命中行）          : 266   → 40%
上界（=下界 + 歧义档独有行）  : 273   → 41%
' : ' 出现处归类：确定 527  歧义 44  URL 2  时刻 0  比值 3  未分类 0
```

**设计要点**：
- **引用形态分两档**：「确定」（`file.ext:line`、裸 `:line`）计入下界；「歧义」（`标识符:数字`，与属性赋值 `type:3` 同形）**只进上界**。
  ⇒ 结论报成**区间**，不报单值。这不是含糊，而是**诚实的表达**。
- **未分类桶是唯一警报**：任何既非已登记形态、也非已排除项的 `:数字`，一律**点名列出并要求登记**，期间**禁止采信任何数字**。
- **非零退出**：有未分类 ⇒ `exit 1`。

### 3.2 第二层：去正则化（`verify-wemedia-c1-escape-bug.cjs`）

对最脆的两处取法，**彻底不用正则**：

| 要取的东西 | 旧做法（会漏形态） | 新做法（权威） |
|---|---|---|
| `escapeMap` 的**键集** | 正则提键 | **求值对象字面量** —— 键集由 JS 引擎给出 |
| 被转义的**字符集** | 正则提字符类 | **实测** —— 把 95 个可打印 ASCII 逐个喂进函数，看哪些真的变了 |

输出变成一条不依赖任何我写的正则的硬证据：

```
实测被改变的字符（共 6 个）:
  "\""→"&quot;"  "&"→"&amp;"  "'"→"&apos;"  "/"→"undefined"  "<"→"&lt;"  ">"→"&gt;"
escapeMap 的键（求值取得，共 5 个）: "&<>\"'"
★ 会被替换成字面量 undefined 的字符: "/"
```

**`"/"→"undefined"` 这一格就是缺陷本身。**

**交叉校验是单向的**（第 8 个 bug 的修正）：
- 键集里有「实测不会用到的键」⇒ **提取逻辑失效，中止**
- 实测里有「键集里没有的字符」⇒ **正是要找的缺陷，报出来**

把这两个方向都判成失败，就会在**成功复现缺陷时中止**。

### 3.3 第三层：未识别即非零退出（`analyze-wemedia-taxonomy-v2.cjs`）

形态无关遍历把所有无法归类的文件单列进 `unknown`，并在结尾：

```js
if (unknown.length) {
  console.error(`❌ 有 ${unknown.length} 个文件形态未识别 —— 上面的节点总数是**下界**，不得作为结论引用。`)
  process.exitCode = 1
} else {
  console.log('✅ 全部文件形态已识别，节点总数为完整计数')
}
```

**关键**：区分「**真的是 0**」与「**我没看懂**」。前者可以写进结论，后者不行。

## 4. 变异反证（证明防线在跑）

**只证「业务改动会变红」不能证明防线在跑** —— 必须做一次「**把防线本身改成 no-op，它必须立刻变红**」。

| 变异 | 期望 | 实测 |
|---|---|---|
| 引用度量：`FORMS` 缩回只有 `file.ext:line` 的窄正则 | 大量未分类 ⇒ 红灯 | 未分类 **326 种** → ❌ **exit 1** |
| 分类解析器：撤掉 `null` 形态支持 | 未识别数上升 ⇒ 红灯 | 识别 64→**50**、未识别 **14** → ❌ **exit 1** |
| C1 复验：制造孤儿键 | 中止并拒绝给结论 | ✅ 中止 |

三者正常态均 `exit 0`，且**明确声明「完整计数」**。

---

## 5. 可复用的一般判据

1. **度量工具必须区分「真的是 0」与「我没看懂」** —— 前者可入结论，后者必须报警。
2. **任何「匹配/解析」结果都要有第二条独立路径互证**（求值 / 实测 / 松界），两条不一致即中止。
3. **形态清单必须是显式登记表，不能是「我见过的那些」** —— 否则新增形态会静默落进 0。
4. **报区间优于报单值** —— 当判据本身有歧义档时（如 `标识符:数字` 与属性赋值同形），把歧义**显式隔离到上界**，而不是偷偷并入下界。
5. **加了防线之后，必须变异证明防线在跑** —— 见第 2 节 #6：我加的第一版 fail-loud 自己就是静默的。
6. **同一事实只允许一处实现** —— 见 #7：`NOT_CITATION` 数组因循环里另有一份硬编码判据而成为死配置。

## 6. 与仓库既有纪律的关系

本仓 `.quality-gates.md` 早有同型记录，且措辞几乎相同：

> 「**所以必须是机械拦截，不能靠自觉。**」—— 2026-10-07 单日误删 `.ccg/` 共 5 次复盘的结论（`scripts/safe-delete.js` 的由来）

**本条复盘是同一结论在「度量工具」这一新场景上的复现**：那次是**删除**动作被放大 5 次，这次是**度量**动作被放宽 5 次。两次的共同结构：

- 单次错误后果不大（少删一个文件 / 少算一个数）
- 但**错误方向一致**（都偏向「更少的动作 / 更小的数字」）
- 且**不报错**（静默）
- 于是写到文档、记进记忆都拦不住，**因为依赖临场自觉**

**所以处置也相同：改工具默认行为（fail-loud），而不是加一条纪律。**

## 7. 附：三个脚本的用法

```powershell
# 引用密度度量（带双界与形态归类；有未分类形态则 exit 1）
node measure-report-citations.cjs <报告.md> [更多报告.md ...]

# C1 缺陷独立复验（实测字符集 + 求值键集 + 单向交叉校验）
node verify-wemedia-c1-escape-bug.cjs

# 分类体系解析（形态无关；有未识别形态则 exit 1）
node analyze-wemedia-taxonomy-v2.cjs <解出的 data 目录>
```

**注意**：`measure-report-citations.cjs` 的引用密度**跨报告类型不可直接比** —— 代码拆解报告的证据是 `文件:行号`（ai-clip 36%、xhs 40%），而**数据拆解报告的证据是「哪个文件、什么字节」，本来就没有行号可引**（data.zip 0.2%）。**后者的低密度是正确的，不是缺陷。**
