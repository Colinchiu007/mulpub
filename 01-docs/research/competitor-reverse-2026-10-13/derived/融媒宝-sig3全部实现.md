## 1. sig3 = F(payload字符串, count, startupRandom) —— 三元气确定函数

| 自由变量 | 来源 | 行为 |
| --- | --- | --- |
| `payload` | 原生 `%s` 注入的 `sig3_data` **字符串** | 只有字符串形态进哈希；对象直传 ≡ 空串 |
| `count` | `realm.global.count`，自增计数器（初值 100，每调用 +1） | 同时影响高位和低位，但影响方式不同（§2） |
| `startupRandom` | 加载时定格 `Date.parse(new Date)/1000`（秒） | 影响高位和低位（通道表基值） |

**三者任一变 ⇒ 输出变；锁定 ⇒ 逐字节确定。**

## 2. ★★ 输出 28 字节的双通道分离结构

### 2.1 实验发现

| 差分维度 | 高位 nibble | 低位 nibble |
| --- | --- | --- |
| payload 单字节差 | **28/28 全变** | **28/28 全变** |
| startupRandom 差 | **28/28 全变** | **28/28 全变** |
| count Δ1 | 27/28 变 | 27/28 变 |
| count Δ8 | **0/28 变** | **27/28 变** |
| count Δ16（同 mod16） | **28/28 变** | **0/28 变** |

### 2.2 结构模型

```
高位 nibble_i = f_H(payload, startupRandom, count绝对值)
  ← SHA-256 流式哈希路径
  ← 管道：payload+sr+count → $()变换 → d()字数组打包 → p()SHA-256压缩循环 → D() → d()
  ← 全雪崩（任一输入变全变）

低位 nibble_i = f_L(count mod 16, startupRandom)
  ← 16 值查找表（每字节独立）
  ← 完美周期性：同 mod16 不同绝对 count ⇒ 低位 0/28 差异
  ← C 表随 sr 变化
```

**高位与低位是完全独立的两个计算通道**，在 t() 函数体内汇合拼接为最终 hex 串。

## 4. `t()` 函数体调用序列（$encode 主流程）

```javascript
function t(data, callback) {
    var r = global[""];           // 版本字段 1
    var n = global["5445"];       // 版本字段 2
    r = $(r, 25);                 // SHA-256 外层包装/初始化
    r = d(r, 15);                 // 字数组打包
    a = r.slice(...);             // 切片
    e = p(a, 2);                  // SHA-256 压缩循环
    e = D(e);
    e = d(e, 15);
    a2 = n.slice(...);
    e2 = p(a2, 2);                // 第二次压缩循环
    f = "";                       // 输出累加串
    // @75-101: f += startupRandom（条件）+ count（条件）← 时间量字符串拼接
    o = j(f, true);               // 拼装步进 ×4（每次不同参数）
    o = j(f, false);
    o = j(f, false);
    o = j(f, false);
    o = g(f, 13);                 // 字节求和校验
    f = o;
    o = s(f, r);                  // XOR 折叠编码
    // @178-194: 取 callback.suc / callback.err，调之 → 56 hex 输出
}
```

**修正前版**：count/startupRandom 不进 SHA-256 —— 它们在哈希**之后**被拼进输出累加串，
然后走 j/g/s 后处理。这解释了「count 线性通道」（拼装数字直接映射为 nibble 模式）。

## 5. 低位通道查找表（28 × 16，完整提取）

`sig3-fullpredict.cjs` 已提取全部 28 字节 × 16 个 count mod 16 值的低 nibble。
样本（payload=""，sr=1750000000，高位表=`fea924eccaaad790793dbbbbbbba`）：

```
b0: 7654ba98fedc3210   （递减，每 4 步跳 +4）
b2: 0123cdef89ab4567   （递增，每 4 步跳 +12≡-4）
b6: ba9876543210fedc   （纯递减）
b7: cdef0123456789ab   （纯递增）
b8: bbbb3333bbbb3333   （bit3 通道：只两值）
b27: 3210fedcba987654   （递减 wrap）
```

⇒ 全部通道 = `lo = base_i ± (count mod 4) + 4·floor((count mod 16)/4)` 的变体（或等价的 16 项查找表）。
**查找表是 sr 的函数** —— sr 变则全表变（已实证 28/28）。

## 6. b8 的 bit3 通道来源

b8 低位只有 `{0x3, 0xb}` 两值，差 = 0x8（bit3）。count bit3（=8 位）决定取哪个：
`(count >> 3) & 1` 为 0 → `0x3`；为 1 → `0xb`。
⇒ b8 是**唯一直接暴露 count bit3 的通道**（其他 27 个的 bit3 被 s/g 后处理折入递增/递减序列）。
