## 1. 决定性发现：sig3 的三元气组

```
sig3 = F( payload字符串, count, startupRandom )
```

| 自由变量 | 来源 | 实证 |
| --- | --- | --- |
| `payload` | 原生注入的 `sig3_data` **字符串** | 对象直传 ≡ 空串（受控实验 ②）；`{"a":1}` 字符串 ≠ 空串 |
| `count` | `realm.global.count`，**自增计数器**（初值 100，每调用 +1） | 重置扫描：count=100 精确复现基准输出；预置 99~106 输出全不同 |
| `startupRandom` | 加载时定格为 `Date.parse(new Date)/1000`（秒） | 冻结 Date.now 后恰等于 T/1000；此后不再变 |

**三者任一变 ⇒ 输出变；三者全锁 ⇒ 输出逐字节复现。**
（`count=100` 预置复现基准 = 决定性证据，输出是三元组的确定函数。）

> ⚠ 实验纪律教训：count 自增使相邻调用输出必不同 —— **受控对比必须独立实例 + count 重置**。
> 本轮首版 ② 实验因未重置 count 得出「对象 ≢ 空串」的反结论，重置后纠正。
> （与 harness 跨 realm 教训同型：实验装置未对齐就下结论。）

## 2. payload 契约（修正版）

| 输入形态 | 输出 |
| --- | --- |
| `{a:1}` / `{b:2}` / `{}` / `7` | **与空串完全相同** |
| `'{"a":1}'`（字符串） | 不同 |
| `'abc'` / `'abd'` / 长串 | 各不相同 |

⇒ **只有字符串形态进哈希**。真实链路里 `sig3_data` 由原生 `%s` 注入（字符串），
所以这不是缺陷而是**契约自洽**：VM 端按「已是字符串」设计，对象传入走默认分支。

## 3. 输出结构：28 字节的「高位表 + 低通道」模型

### 3.1 高位 nibble 表（payload 决定）

- 空串高位表：`f e a 9 2 4 e c c a a a d 7 9 0 7 9 3 d b b b b b b b a`
- `'abc'` 高位表：`b b a b e c d c 6 b 0 b a 7 8 0 8 3 e 6 e 5 e 4 d 5 6`
- 对象直传 vs 空串：**28/28 相同**；空串 vs `'abc'`：**0/28 相同**

⇒ 高位表 = `f(payload字符串)`（哈希类强扩散）。

### 3.2 低 nibble 通道（count 决定）

**27/28 字节**满足线性 XOR 模型：

```
lo_i = C_i ^ ((7 − count) & 7)
```

- C 表（payload=''）：`88ff8843?567ef2bd91d99bb456c`（27 个 + b8 例外）
- `b8` 特例：吃 count 的 **bit3**（`0x3 | ((count>>3&1)<<3)`）
- 通道周期 8：count 每 +8 输出循环回位

### 3.3 雪崩与性能

| 实验 | 读数 |
| --- | --- |
| payload 单字节差 | **28/28 字节全扩散** |
| 耗时 vs 长度 | 0→23ms / 1000→103ms / 10000→1191ms —— **线性** ≈ 90~120ms/千字符 |

⇒ payload 全量进流式 SHA-256（JS 实现速度量级）—— SHA-256 常量族（字节码取证）与行为实验互相锁定。

## 4. 与字节码组件的对应（整合版流水线）

```
payload(字符串) ──UTF-8(sub30)──▶ 流式 SHA-256(sub7 压缩循环, 主脚本 K 表) ──▶ 摘要 32B
                                                                      │
count(自增) + startupRandom(秒) ──sub2 拼装──▶ 时间块 ──TEA(sub29, ks-seed)──▶ 通道段
                                                                      │
                                    CRC32(sub26) 校验 ──▶ sub24 拼装(0xDEADBEEF/0x1001/…003)
                                                                      │
                                    高位表 = f(摘要) / 低通道 = C_i ^ ((7−count)&7)
                                                                      ▼
                                                        56 hex（28 字节）
```

**为什么 count 通道呈 XOR 线性而 TEA 应有雪崩**：TEA 轮函数的低位扩散弱
（每轮只动低位），且低 nibble 通道只取自 TEA 输出的低位 —— 与「TEA 低位弱扩散」吻合。
（推断级：需逐字节对账 TEA 轮数后焊死。）
