### 2.2 ⭐ 关键证据：引擎是「配置化模块」

`data/config.ini`（明文 GBK）：
```ini
[param]
channel=sogougf
MediaTaskMgrModule=MediaTaskMgr.dll
subchannel=sogougf
```

| 配置项 | 值 | 含义 |
|---|---|---|
| `channel` / `subchannel` | `sogougf` | **搜狗渠道包**（OEM 分发）|
| **`MediaTaskMgrModule`** | `MediaTaskMgr.dll` | **媒体引擎按配置名加载**，可替换/热更新 |

### 2.3 ⭐ 组件热更新链路（完整还原）

三条证据串起来：

1. `config.ini` 的 `MediaTaskMgrModule=MediaTaskMgr.dll` → 引擎是外部模块
2. 同目录存在 **`MediaTaskMgr_1.0.0.257.dll`**（旧版本）+ **`MediaTaskMgr.dll`（v1.0.0.264）** → 下载的载荷按 `<名字>_<版本>.dll` 落地，替换后旧文件未清理
3. exe 字符串含 `https://bkend.17van.com/ApiSoftware/CheckComponent` → 有组件版本检查接口

**推断的更新链路**：
```
启动 → ApiSoftware/CheckComponent 查询组件版本
     → 若服务端版本更新，下载 MediaTaskMgr_<新版本>.dll
     → 替换/切换加载 → 下次启动生效
```

**版本信息来源对比**：
| 文件 | ProductName | ProductVersion |
|---|---|---|
| `WEMedia.exe` | 融媒宝3.0 | 3.1.0.7433 |
| `MediaTaskMgr.dll` | **自媒体助手1.0** | 1.0.0.264 |

> **重要发现**：媒体引擎是**独立版本线的第三方/外包组件**
> （「自媒体助手」，版权方「自媒体工作室」，2020-2025），
> 与主程序（「融媒宝3.0」，上海生趣，2017-2030）**不同源**。
> 这解释了为什么引擎接口是**品牌无关的 C 风格导出 API**
> （见 §5.1 `InitMediaTaskMgr` 反编译实证）。

### 4.2 设计要点

| 要点 | 说明 |
|---|---|
| **同步返回** | `window.JsReadLocalFile(a)` **直接 return 字符串**（非 Promise/IPC），C++ 侧负责序列化 |
| **`Fn` 前缀封装层** | `FnJsReadLocalFile` 包裹 `window.JsReadLocalFile`，并做 `isJsonType()` 判断 + `JSON.parse` |
| **参数语义注释** | 每个方法都有中文注释说明用途（可读性好） |
| **`IframeWindowMy()`** | 多 iframe 场景下定位当前窗口（`PageId` 区分页面） |

### 4.3 对本项目的适用性

**不适用**：本项目是 Electron，有原生 IPC（`contextBridge` + `ipcRenderer.invoke`），
不需要 CEF 式的全局函数桥接。

**可借鉴**：`Fn` 前缀封装层 + 参数语义注释的**接口规范做法**。
本项目的 `apps/desktop/electron/preload/` 已有类似分层。

### 4.5.2 调用机制

```
隐藏 CEF 页（signN.html，13.4 KB 同构模板 + 空 body）
  ├── crypto-js.min.js / runtime.js / main.js（部分页需要）
  ├── signN.js          签名实现，暴露全局函数
  └── 内联 13.4 KB       FMP/FCP 性能观测（__FCP__/__FMP_OBSERVED_POINTS__/__FP__/__FULLY_LOADED__）

宿主 WEMedia.exe 经 CEF ExecuteJavaScript 调 window.getXBogus(url, data, ua)
```

与融媒宝自身的 JS↔C++ 桥（§4）**不同**：签名页不开新的 IPC 通道，
而是走 CEF 的 `ExecuteJavaScript` + 全局函数。

### 4.5.5 抖音 `X-Bogus` 内嵌 jsVMP（取证）

`sign4.js` 的 `_0x38c772` 用一段 hex 字节码驱动 **`jsvmp()` —— 一个完整的 JS 虚拟机解释器**（约 420 行）：

| 能力 | 证据 |
|---|---|
| **魔数校验** | 前 16 字节解出必须是 `"HNOJ@?RC"`，否则 `throw new Error("error magic number " + y)` |
| 变长指令解码 | 操作码 `13 * j % 241` 的分支树 |
| 栈机 | `O[++S]` / `O[S--]` 显式栈 |
| 完整运算符 | 算术/位运算/比较/`typeof`/`instanceof`/`in`/`delete` |
| 闭包与调用帧 | `function b(){var c=arguments; return b.y>0 ? $(...) : (b.y++, $(...))}` |
| 异常处理 | `try/catch/finally` 字节码区间登记 `o[i]=[[A+4,T-3],0,0]` |
| 字符串解密 | `String.fromCharCode(n ^ r.p[M])`（XOR 密钥流）|

`_0x25788b` 是**标准 RC4**（256 字节 KSA + PRGA XOR 流），用于字节码内字符串解密。

**含义**：X-Bogus 的 UA 哈希部分被 VM 保护，融媒宝的做法是**把 VM 和字节码一起搬来直接跑**，
不逆向 VM 内部逻辑。

## 8. 智能剪辑数据模型

`Asset/dist/view-smart-clip/js/config.js`（785 行）的结构：

```javascript
// 镜头（lens）—— 四层模型
{
  id: `lens${index}`, sort, title,
  durationType, durationText, fixSecond,

  // ① 素材层
  materialList: [{
    id, uuid, url, name, type, size, cover,
    duration_old,        // 原始时长
    duration_new,        // 处理后时长
    duration_audio,      // ★ 音频时长（独立）
    duration_video       // ★ 视频时长（独立）
  }],

  isOral: !im_oral,       // ★ 是否口播
  isCloseVoice: !voiceType, // ★ 是否静音

  // ② 字幕轨
  subT: [{
    name, oralplay, type, totalWords, value,
    list: [{ id, text, voiceDuration, voiceChannels, frequency }]
    //          ★ TTS 时长        ★ 声道
  }],
  curSubtNum, curSubT,

  // ③ 选中字幕定位
  curDialog: { parentId, id, text, left, top },

  // ④ 字体
  ft: { ...font, categorId, signaTempInx, family, familyVal }
}
```

**值得注意的 4 个设计**：
1. **音视频时长分离**（`duration_audio` / `duration_video`）—— 支持音视频轨独立裁剪
2. **口播标记**（`isOral`）与**静音标记**（`isCloseVoice`）—— 混剪时决定是否保留原声
3. **字幕带 TTS 时长与声道**（`voiceDuration` / `voiceChannels`）—— 字幕与配音对齐
4. **字体回退**：`family: font.family === "微软雅黑" ? "黑体" : font.family`

**对 `remotion-composer` 的参考**：可对比是否需要补齐
「音视频时长分离」「口播/静音标记」「字幕-TTS 对齐」这三项。

## 9. WebSocket 长连接（私信推送）

`Asset/dist/view-dy-interaction/js/myWebSocket.js`（118 行）：

```javascript
var wsUrl = "wss://rmbwss.17van.com/wss";

// 连接建立 → 发送订阅 → 启动心跳
myWS.onopen = function () {
  const message1 = {
    type: "ordinary",
    [wsParame.issubuser == "0" ? "uid" : "suid"]: wsParame.uid || "0"   // ★ 主/子账号区分
  };
  myWS.send(JSON.stringify(message1));
  heartCheck.start();
};

// 断线自动重连
myWS.onclose = function (evt) {
  onWebSocketReconnect(wsUrl);
  onWsClose("当前私信新消息推送已断开，重新连接中，请稍候", false);
};
myWS.onerror = function () { onWebSocketReconnect(wsUrl); };

// 3 秒连接超时保护
initTimer = setTimeout(() => {
  if (myWS && myWS.readyState != 1) myWS.close();
}, 3000);
```

**要点**：断线重连 + 心跳 + 连接超时 + **主/子账号区分订阅**（`uid` vs `suid`）。

**对本项目的价值**：若要做「平台私信/评论实时推送」，这是完整可参考的实现（118 行）。
