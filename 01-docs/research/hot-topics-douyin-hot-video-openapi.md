## 1. 为什么不能只"读文档"

| 事实 | 本轮现场读数 |
|---|---|
| 该文档站是 SPA，直接抓 HTML 拿不到正文 | 2026-10-18 抓取 `developer.open-douyin.com/docs/resource/.../hot-video-list` ⇒ 返回体只含样式与路由脚本，正文 0 段；据此**无法**取字段表 |
| 同名接口在两处描述，口径不同 | ① **能力中心**：`capacity-detail/7180577040481910795`（标题「抖音热门视频榜单」）—— 讲**开通条件、所需权限、主体要求、审核**；② **开发文档**：`.../data-open-service/tops-data/hot-video-list/hot-video-list` —— 讲**请求参数、返回字段、示例**。**两处都要取**，只取②会漏掉"能不能拿到"这条前置 |
| 免登录的公开视频榜端点已无数据 | `iesdouyin.com/web/api/v2/hotsearch/billboard/aweme/` 实测 `status_code:0` 但 `aweme_list: []`（2026-10-12 与 2026-10-17 两次互证）⇒ **不能拿它当替代证据**，它证明的是"没有"，不是"有什么" |

**结论**：取证必须由**具备开放平台资质的账号登录后实做**，产物是「渲染后的文档正文抄录 + 一次真实调用响应原文」两类，缺一不可。

## 2. 前置：账号与权限面（先确认，再调接口）

按顺序问清并逐条落证据，任何一条不成立就**停在该步如实记「不可达」**，不得跳过：

| # | 要确认的事 | 证据形态 | 不成立时的出路 |
|---|---|---|---|
| P-1 | 本应用（`Multi-Publish`，桌面分发形态）能否申请到"数据开放服务/榜单"这一能力 | 能力中心页面的开通入口与条件抄录；审核状态截图说明 | 转 §5 替代路径 |

| P-3 | 所需权限项（scope）名称与申请理由模板 | 页面原文 | 同上 |
| P-4 | 调用凭证形态：**应用级 client_token** 还是**需用户 user_access_token 授权**（决定能否在用户未登录时出榜单） | 文档"请求说明"原文 + 一次真实调用所用的凭证类型说明 | 若必须用户授权 ⇒ 产品形态要改，这条结论本身即为交付物 |

## 5. 若资质拿不到（P-1/P-2 不成立）

这才是本仓更可能的现实，出路按优先级，且**必须如实写进规格与记录**，不得静默降级成"看起来能用"：

1. **自托管签名方案**：`Evil0ctal/Douyin_TikTok_Download_API`（20,724★，**Apache-2.0**，含 `DOUYIN_HOT_SEARCH` 端点封装）作为**用户自装的外部服务**，应用只调其 HTTP 接口。代码不入包（许可证姿态要求），并标 `riskLevel: 'high'` + 独立熔断。
2. **归档型降级**（PRD §5 那片）：继续只做「在榜天数 / 峰值排名」这类**名次派生量**，明确不对用户提供条目，也不宣称条目能力。
3. **付费数据服务**（TikHub / JustOneAPI 一类）：可作为可选数据源，但界面必须如实标注付费来源，且需单独过一次合规评估。

## 6. 红线与操作纪律

- **不落任何凭证明文**：`access_token` / `client_secret` / cookie / 签名参数一律删除或截断；提交前对本仓脱敏口径自查一遍，凭证类内容进仓即事故。
- **不把用户隐私数据长期留在仓**：E-2 只保留**结构**与**少量样例**（建议 ≤3 条），其余删掉；不要把整榜几百条落 git。
- **不猜字段**：文档与响应不一致时以响应为准并记录差异；表格里"待填"的格子**不许**用推测填。
- **判据一律取产物**：调用成功与否看真响应文件，不看命令行 rc 或日志措辞；空数组与失败必须能区分（同 `hot/search/list` 的「200 + 空列表」教训）。
- **归因要带出处**：本文每一条结论后面标注「页面小节」或「响应 JSON 路径」，下一个会话不需要重跑就能复核。
- **取证完成后**：把 `01-docs/research/` 的新文件与本 PR 的记录一起收口，并回到 `openspec/changes/hot-topics-viral-items/` 关闭 O-1/O-3；若结论否证了现有规格（例如根本不给 `publishTime`），**改规格而不是改事实**。
