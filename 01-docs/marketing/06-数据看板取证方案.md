## 一、为什么需要这份方案

`01-docs/PRD-PUBLISH-METRICS-DASHBOARD-2026-10-04.md` 记录：
两份真实 profile 的 `tracked_content` / `performance_snapshot` / `pattern_performance` / `rewrite_history` **全 0 行**。

**这本身不是缺陷** —— 全盘 `publish-history.jsonl`（>500c）0 命中，
说明**那两个 profile 从未成功发布过任何内容**。没发过 ⇒ 没有可跟踪对象 ⇒ 0 行是逻辑必然。

但它留下一个真问题：

> **看板从未在真实数据下跑过端到端。**
> 三态空态文案有单元测试锁住，但「发一条 → 登记 → 回采 → 写快照 → 看板显示」这条链
> **从未被真机验证过一次**。

**所以 S-14 现在对外讲的两种说法都不对**：
- ❌「发布后自动回收表现数据」—— 没验证过，不敢说
- ❌「功能还没做完」—— 也不对，代码是全的

✅ 正确的说法是：「**刚上线的效果闭环，尝鲜中**」—— 但这也要建立在真机跑通之后。

## 二、取证清单

### 前置条件

| 项 | 要求 |
|---|---|
| 环境 | Windows 桌面端（`start-app` skill 契约），**用已登录 profile** |
| 账号 | 至少 1 个 cookie 有效的平台账号 |
| 内容 | 1 条**能在平台上查到公开作品**的内容（图或视频都行，**别用草稿**） |
| 时间 | 发布后至少等 **T+1h**（首采点）；完整看数据要等 T+24h |

> ⚠️ **不要用小红书草稿。** `phase4-events.js:229` 明确写了草稿没有公开作品锚点，
> 会被标成 `untrackable`，不进入回采队列 —— 那样测出来的 0 行不是链路问题，是设计如此。

### 执行步骤

| # | 动作 | 期望 | 不符合时说明什么 |
|---|---|---|---|
| 1 | 发一条内容到 1 个平台 | 发布成功，有 postId 或作品 URL | 发布链路问题，与看板无关 |
| 2 | 查 `tracked_content` 有无新行 | **1 行**，`recrawl_status='pending'`，`next_recrawl_at` = T+1h | 登记链路断（查 `phase4-events.js` 的 `addTrackedContent` 是否被调用） |
| 3 | 等 T+1h 后看 `performance_snapshot` | **≥1 行** | 回采没跑或跑失败（查 `performance-recrawl-service` 是否启动） |
| 4 | 打开看板 | 显示该作品的曝光/播放/涨粉等 | 读侧问题（查 `performance-loop-store` 与 `PerformanceFlowPanel`） |
| 5 | 等 T+6h / T+24h | 快照行数增加，数值变化 | 节奏推进断（查 `nextRecrawlAt` 推进逻辑） |
| 6 | 看板空态检查 | 有作品时**不显示**「从未发布」 | 复现 #4242 修的那类空态混淆 |

### 取证命令

```js
// 查 tracked_content / performance_snapshot
const { DatabaseSync } = require('node:sqlite')
const db = new DatabaseSync(profilePath + '/multi-publish.db', { readOnly: true })
for (const t of ['tracked_content', 'performance_snapshot', 'publish_history']) {
  console.log(t, db.prepare(`SELECT COUNT(*) c FROM ${t}`).get().c)
}
```

> 📌 用 `readOnly: true`，不碰任何凭证表。
> 完整复跑命令见 `01-docs/PRD-PUBLISH-METRICS-DASHBOARD-2026-10-04.md` §八 8.3。

## 四、时间成本

| 范围 | 等待时间 | 用途 |
|---|---|---|
| 最小取证 | **T+1h**（约 1 小时） | 证明「发布 → 登记 → 首采 → 看板显示」通了 |
| 完整取证 | **T+24h** | 证明节奏推进 + 数值在变 |
| 全量取证 | T+7d | 证明 7 天后停止归档 |

> 💡 **最小取证（1 小时）性价比最高** —— 一次真实发布 + 等一小时，
> 就能让 S-14 从「讲不了」变成「讲得清」。
