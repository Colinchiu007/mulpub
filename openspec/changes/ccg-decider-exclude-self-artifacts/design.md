# Design: 把"裁判不消费自己的判决"补到规模与敏感内容两维

## 决策点 1：排除动作落在哪一层——git pathspec 还是 JS 归类

| 方案 | 效果 | 否决/采纳理由 |
|---|---|---|
| A. `collectRange()` 的两个 git 参数加 `:(exclude).ccg`（与 `collectStaged()` 逐字同形） | 最小改动（2 行），mode 立刻对齐 | **否决**：被排除的文件**根本不进采集面**，于是"产物里贴着一条真口令"这一格从"报告"退化为"看不见"。本仓对同一问题的既有答案是 i3——**行还是要读，只是不改判定**（`docChangedLines` / `docSensitiveContentHits`）。A 与既有答案方向相反。 |
| B. 只在 `collectFromDiff()` 里按路径新增第三类，`collectStaged()` 的 git pathspec **保留不动** | 改动面小，区间档立刻对齐 | **否决（2026-10-20 由 critic 轴 Critical#2 否证，我原写的"两处幂等重叠"是错的）**：pathspec 让 `.ccg` 在 git 层就被摘掉，JS 层根本收不到那些行 ⇒ 暂存档的 `ccgChangedLines` **恒为 0**，而区间档报 N。两档 `mode` 会一致，但"唯一观测点"只在补跑档存在——这正是本刀声称要保的东西被自己关掉。现场佐证：同一份在飞差量两档 `fileCount=8 vs 9`，差的那 1 个文件就是产物。 |
| C. 排除动作**只住在 JS 一处**：`collectFromDiff()` 按路径分第三类，规模与内容两维都不消费它；同时把 `collectStaged()` 两个 stats 参数里的 pathspec **摘掉**，让两档走同一个归类出口 | 两档 `mode` 与 report-only 计数**同时**同源；排除逻辑只有一份 | **采纳**。 |

`stagedDiffHash` / `recordFileName()` 的 pathspec **保留**——那是独立的一次 git 调用（同文件 `:537` 一带），职责是内容寻址命名，不是取证面；它已被 `scripts/deep-review-deps.test.js:399` 的「配方必须与判定器同源」锁钉住，本刀不动它，并在 4.4 里跑那条锁自证没改坏。

## 决策点 2：谓词的口径

判据是**路径**，不是扩展名，也不是"文件名像不像产物"：`.ccg/` 目录下的全部内容都是判定器与评审链自己写的。写成 `(^|[\\/])\.ccg([\\/]|$)` 并在 `judge()` 与 `collectFromDiff()` 共用同一个导出谓词——两处各抄一份正则就是本仓反复犯的"两份事实"。

边界如实写出：`.ccg/` 下还有 `plan` 档产物与人工放进该目录的资产。本刀只保证"判定器不消费 `.ccg/`"，**不承诺** `.ccg/` 里不会有需要被守的东西；正因如此才必须保留 report-only 计数，而不是把目录整体从扫描域抹掉。

## 决策点 3：怎么证明"排除"没有顺手把敏感判定整条关掉

这一条是本刀唯一真正的风险面：判据被改宽 → 该 dual 的不 dual → QM-6 静默放行。两道闸：

1. **对偶行为锁（绝对参考，不是相对比较）**：夹具里放一个**真实代码文件**（`.js`），其新增行含 `apiSecret = "x"` ⇒ 必须仍判 `dual` 且 `sensitiveContentHits>0`。
   ⚠️ critic 轴 Critical#1 指出：**"两档同判"这一把锁单独存在是恒真的**——若谓词退化成一恒 `true` 的形态（一切文件都算自身产物），两档会**一起**降到同一个错误值，相等断言照样通过。所以同判锁必须与绝对参考锁**成对**：绝对锁要求"含真敏感行的 `.js` 在两档各判一次，两次都必须是 `dual`"，同判锁只负责"两档不得分歧"。
2. **纯自身产物提交的归属**：只改 `.ccg/**` 的提交，`isDocsOnly()` 必须把这些文件视为**可忽略**（既不当代码规模，也不挡 skip），否则两档会一个 `skip` 一个 `single`——那是本刀新造的口径分裂，不是修好的。判据归属：`skip`（这份改动没碰任何被测面）。
3. **变异反证**：M1 谓词恒 `false`（不排除）⇒ 排除锁红；M2 谓词恒 `true`（一切都算自身产物）⇒ **绝对参考锁**必须红（critic#1 要抓的正是这一格，M2 不得只被同判锁放过）；M3 把 `ccgChangedLines` 又并回 `codeChangedLines` ⇒ 排除锁红；M4 只在 `judge()` 排除、`collectFromDiff()` 不排除（规模与内容两维各切一半）⇒ 规模锁与内容锁各红一条。每条变异都要报"红的是哪几条用例"，红集互不相同才算数。

## 决策点 4：规模口径改动的副作用必须出声

`changedLines` 会因为排除而变小（实测那笔 PR 191→132）。这**不是**为了放宽阈值——阈值 `dualLineThreshold: 200` 一行不动。如实记录：排除前后读数差（本刀用"两档各判一次并打印"的方式留现场），使"规模变小"可归因到取证面，而不是被读成"这次改动真的更小"。

## 决策点 5：report-only 计数要不要有"机器消费者"（critic#3 的处置）

critic 判"`ccg` 计数仅打印无消费者 ⇒ 死字段"。**先量既有同构字段的地位再决定**：全仓检索 `docSensitiveContentHits`（2026-10-15 i3 定下的文档侧同类计数）只有 3 处出现，全部在判定器自己体内——写进产物 `stats`、`>0` 时打一行 console，文案原话是"请人工确认是否真凭证"；`scripts/check-pr-exec-record.js` 与任何 CI 判据**都不读它**。

所以本仓对这一维的既有设计就是**面向人的观测点，不是一条自动处置链**。处置分两半：

- **接受**："没人验证这行真会打印"成立 ⇒ 加一条 CLI 行为锁：在夹具仓库真跑 `node scripts/ccg-review-decider.js --base=…`，断言 stdout 含 `自身产物敏感内容=N` 且 N 与 `judge()` 的 stats 读数相等（打印面与计算面同源，否则"打印了"不等于"打印的是这个数"）。
- **不接受**："必须有门禁消费它才不算死字段"。把它升成阻断判据等于新增一条守门面（"产物里出现敏感词 ⇒ 红"），而产物里的命中**逐字来自方案与执行记录正文**——本刀的立论恰恰是"这些词不该触发判定"。同一份散文，一处不消费、另一处拦下来，是自相矛盾。这条边界如实写进规格（只报告，不改判定，也不自动处置）。

## 未覆盖（不假装已闭合）

- 决策层 `plannedPathHits` 从方案正文抽"路径样 token"再跑敏感路径规则，实测 1499 份产物里 1 条命中，且命中的是散文里的一个正则字面量（`sso/i.test`）。发生率与代价都不支持为它改判定面；留数不修。
- `.quality-rhythm/` 下的 vendored 判定器副本是本判据的**镜像真源分发件**：本刀只改仓内那份。实测仓内 `ccg-review-decider.js` **只有 1 份物理副本**（`find` 排除 `node_modules` 后单命中），`.quality-rhythm/installer/` 里是 `run.js`/`commands`/`husky`，不含门禁脚本本体，`check-gate-drift.js` 只存在于下游仓库 ⇒ 本刀没有"两张表必须同改"的联动面。规格侧联动判据照旧读 `scripts/quality-rhythm-spec-mirror.test.js` 的 `LIVE_SPEC`：它只镜像 `openspec-integration`，而本刀 delta 不落那份主规格，故不联动（读源码得结论，不拿先例当判据）。
- 若将来有人把评审产物写到 `.ccg/` 之外（例如 `openspec/reviews/`），该目录会重新进入取证面。谓词是单一出处，改一处即可，但**没有任何东西会因此变红**——这条缺口如实留在遗留里，不另开判据（要为"未来的目录布局"建锁，等于猜需求）。
