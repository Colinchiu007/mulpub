# 执行记录门禁 —— 规格变更（delta）

## ADDED Requirements

### Requirement: 每篇记录必须含门禁表与「远程同步」行，状态按闭合词表判定或按 git 现场推导收口

> **本条取代的关系必须写明**：`enforce-gate-record-presence`（未归档）里有一条「每篇记录必须含门禁表与『远程同步』行，状态按闭合词表判定」。本条沿用同一 concern，**取代其中"状态如何算收口"这一半**；该行「必须存在」的结构要求原样保留。两条 Requirement 会在基线里并存，读到的先后顺序不确定，因此本条正文自带优先级声明。
> 本条写成 ADDED 而非 MODIFIED 是**实测决定**，不是风格选择：对着不存在的基线写 MODIFIED 会被 `openspec archive` 硬拒（`code=archive_spec_update_failed`，原文 `target spec does not exist; only ADDED requirements are allowed for new specs`），详见 design.md D10。

系统 SHALL 要求每篇记录文件包含一张门禁表与一行 `远程同步` 状态。**行是否存在**属结构要求，SHALL 独立判定，任何推导档 MUST NOT 豁免缺行。**行是否收口** SHALL 按下列顺序求值，先到先停：

1. **派生通道**——该行存在，且该记录文件在基线分支上由某次带 squash 尾注 `(#NNNN)` 的合并提交**最近一次新增**、该 PR 可被合并账本解析 ⇒ 判为已收口，**不看状态列写了什么**；
2. **断言通道（兼容读）**——**派生通道不成立时一律进入本通道**（含三种情形：账本不可用、归属提交没有尾注、解析出的 PR 不在账本），状态列 SHALL 按既有**闭合词表**判定；凡未知写法一律判为未收口（fail-closed）。
3. 两条通道都不成立 ⇒ 未收口。

归属取值本身 SHALL 是三态，MUST NOT 塌成两态（塌态会让"改名后旧路径"与"本次新增"两种相反语义共用一个出口）：

- `NOT_IN_BASE`——该路径不在归属映射里（从未作为新增进过基线：本次变更集刚写的记录，或改名后的旧路径）；
- `NO_FOOTER`——在映射里，但那次新增提交没有 `(#NNNN)` 尾注（实测存在此形态）；
- `PR(n)`——在映射里且解析出 PR 号 `n`；`n` 命中账本才成立派生通道。`n` 不命中账本属**取证不一致**，MUST 出声打印并走断言通道（不得借此跳过词表判定，也不得算作"账本不可用"）。

词表、判定与文件扫描域 MUST 复用既有单一实现，MUST NOT 出现第二份。字段卫生（"已收口却仍留登记字段"）的适用范围 SHALL 限于**状态列做过闭合断言的记录**（第 2 通道命中，或第 1 通道命中且状态列仍写了闭合词）；纯靠派生收口、状态列未写闭合词的记录 MUST NOT 被判字段卫生——实测该豁免覆盖 21 篇存量，若不豁免则本 change 自己违反「存量零漂移」。

#### Scenario: 缺行即红（派生不豁免）

- **WHEN** 记录文件存在但整篇没有 `远程同步` 行，即使该文件的归属提交可被 git 解析
- **THEN** 判为不合规并以非零退出，指明该文件缺该行

#### Scenario: 派生通道收口

- **WHEN** 一行状态列写着 `PENDING`，但该记录文件确由某个已合并 PR 最近一次带入基线
- **THEN** 判为已收口，不要求登记字段，且不要求任何后续写回

#### Scenario: 未知状态在派生不可用时仍按未收口处理

- **WHEN** 合并账本不可用（ref 取不到、解析失败或规模读数为 0），且状态列是词表之外的写法（例如"差不多好了"）
- **THEN** 判为未收口，必须携带该文件自身的登记字段，不得因"读不到证据"而放行

#### Scenario: 收口写法放行

- **WHEN** 状态列以词表内的收口前缀开头（`PASS` / `N/A` / `✅` / `已`）
- **THEN** 判为已收口，不要求登记字段

#### Scenario: 未收口必须自带登记（只服务兼容档，新形态不得借此预填）

- **WHEN** 一篇**已在基线上**的记录既无派生证据、状态列又未闭合
- **THEN** 同一文件内必须写明登记原因与回填责任人，登记字段不得为空
- **AND** 由本次变更集新增的记录 MUST NOT 用登记字段换取豁免——它走 byDesign 通道；新形态记录 MUST NOT 预填这三个字段（模板的默认预填同步删除，见 tasks 4.3）

#### Scenario: 派生不成立的三种情形都必须落到断言通道，不得悬空

- **WHEN** 账本不可用 / 归属提交没有尾注（`NO_FOOTER`）/ 解析出的 PR 不在账本（取证不一致）
- **THEN** 三种情形一律继续走断言通道按闭合词表判定；MUST NOT 出现"两条通道都不适用"的悬空格，也 MUST NOT 因派生不成立而直接判收口或判不可判定

## ADDED Requirements

### Requirement: 合并账本与记录归属只允许一份实现，取不到读数一律按未证实处理

系统 SHALL 提供唯一实现用于「由 git 现场推导合并事实」，至少导出：合并账本（PR 号 → merge SHA 与时间，只认 squash 尾注 `(#NNNN)$`）与记录归属映射（记录文件路径 → **最近一次**把它加入基线的提交）。取向必须显式：取最近一次而非首次，否则"删除后由另一 PR 重新加回"会被归给一次已不在主干历史里的交付。判据 SHALL 从该实现取值，MUST NOT 在判据内另写 git 解析，也 MUST NOT 自行枚举记录目录（文件集合只接受调用方传入的既有枚举结果，递归扫描会把 `_exempt/` 读进门禁域）。该实现在解析时 MUST 关闭重命名检测并关闭路径转义（`--no-renames`、`core.quotepath=off`）；`--no-renames` 的已知后果必须如实写明：**改名会把归属重指到改名那次提交**，而不是"解析不到"。

**任何取不到读数的分支（基线 ref 不可解析、git 命令失败、账本规模读数为 0）SHALL 使推导档整体停用并出声打印原因，退回断言通道判定；MUST NOT 把"看不见账本"读成"已合并"。**

#### Scenario: 归属与账本同源

- **WHEN** 判据需要判断某篇记录是否已随合并进入基线
- **THEN** 结论来自共享实现的同一次遍历，且现场打印账本规模（`MERGE-LEDGER prs=<n>`）作为"这一趟真的测过"的证据

#### Scenario: 账本不可用不得判绿

- **WHEN** 基线 ref 取不到或账本规模读数为 0
- **THEN** 打印推导档停用，并退回"只有状态列写明收口写法才算收口"的口径；未收口记录仍被判为欠账

#### Scenario: 改名会把归属重指到改名那次提交（后果必须如实声明）

- **WHEN** 某篇记录在后续提交中被改名或移动（`--no-renames` 下新路径会作为"新增"出现在改名提交里，实测成立）
- **THEN** 归属解析为**改名那次提交**，系统 MUST NOT 谎称"解析不到"或"检测得到"；收口结论仍成立（该文件确在基线上），但"哪次交付带它进来"已改变
- **AND** 若该记录声明了来源 PR，改名导致的不符 MUST 判红；未声明者只打印重指事实，不做拦截
- **AND** 记录文件名即分支名属本仓约定，改名本身是可禁止操作，MUST NOT 靠"归属会重指"来默认允许

#### Scenario: 派生档的文件集合必须来自同一份枚举

- **WHEN** 合并账本或归属映射自行枚举记录目录（递归遍历、`git ls-tree -r`、另写一份过滤）
- **THEN** 判红：文件集合 MUST 由调用方传入的既有 `listRecordFiles` 结果决定，共享实现内 MUST NOT 出现第二份目录扫描（实测教训：自建过滤会把 `_exempt/` 读进门禁域，使"缺行即红"被绕过）

### Requirement: 记录不得预写尚不存在的合并证据，且声明的归属与 git 事实不符时判红

系统 SHALL 拒绝两类"声明与事实不符"：

1. **预写**——该记录文件是本次变更集新增（基线上尚不存在），而状态列写了闭合词 ⇒ 判红。理由：一篇还没进主干的记录不可能已经"远程同步"，这正是断言通道无法分辨、改造前长期存在的缺口。
2. **归属不符**——该记录显式声明了来源 PR，而 git 推导出的"把它带进基线的 PR"与之不同 ⇒ 判红。该字段缺省时本条不参与判定（存量不动）。

#### Scenario: 合并前预写 PASS 变红

- **WHEN** 一个 PR 新增记录文件并把状态列写成 `PASS`，而该文件在基线上不存在
- **THEN** 判红并指明"该记录尚未进主干，不得预写已合并"

#### Scenario: 本次变更集新增的记录不得判成欠账

- **WHEN** 记录文件由本次变更集新增且状态列未闭合
- **THEN** 判为 byDesign（自己不能证明自己已合并），不拦截；该 PR 合并后同一条记录 SHALL 经派生通道自动收口，无需任何写回

#### Scenario: 声明 PR 与实际带入 PR 不符

- **WHEN** 记录声明来源 PR 为 `#A`，而基线上**最近一次**新增该文件的提交尾注为 `#B`
- **THEN** 判红并打印两个编号；不得静默择一

#### Scenario: 存量零漂移

- **WHEN** 改造合入后在同一条主干上重跑判据
- **THEN** 拦截集合与改造前逐篇相同，且记录文件的字节内容零改动；任何"改前绿→改后红"的新增拦截一律视为回归
