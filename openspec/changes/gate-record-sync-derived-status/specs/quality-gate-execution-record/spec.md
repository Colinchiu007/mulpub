# 执行记录门禁 —— 规格变更（delta）

## MODIFIED Requirements

### Requirement: 每篇记录必须含门禁表与「远程同步」行，状态按闭合词表判定或按 git 现场推导收口

系统 SHALL 要求每篇记录文件包含一张门禁表与一行 `远程同步` 状态。**行是否存在**属结构要求，SHALL 独立判定，任何推导档 MUST NOT 豁免缺行。**行是否收口** SHALL 依次尝试两条通道：

1. **派生通道**——该行存在，且该记录文件在基线分支上由某次带 squash 尾注 `(#NNNN)` 的合并提交新增、该 PR 可被合并账本解析 ⇒ 判为已收口，**不看状态列写了什么**；
2. **断言通道（兼容读）**——派生不可用时，状态列 SHALL 按既有**闭合词表**判定，凡未知写法一律判为未收口（fail-closed）。

词表、判定与文件扫描域 MUST 复用既有单一实现，MUST NOT 出现第二份。

#### Scenario: 缺行即红（派生不豁免）

- **WHEN** 记录文件存在但整篇没有 `远程同步` 行，即使该文件的归属提交可被 git 解析
- **THEN** 判为不合规并以非零退出，指明该文件缺该行

#### Scenario: 派生通道收口

- **WHEN** 一行状态列写着 `PENDING`，但该记录文件确由某个已合并 PR 首次带入基线
- **THEN** 判为已收口，不要求登记字段，且不要求任何后续写回

#### Scenario: 未知状态在派生不可用时仍按未收口处理

- **WHEN** 合并账本不可用（ref 取不到、解析失败或规模读数为 0），且状态列是词表之外的写法（例如"差不多好了"）
- **THEN** 判为未收口，必须携带该文件自身的登记字段，不得因"读不到证据"而放行

#### Scenario: 收口写法放行

- **WHEN** 状态列以词表内的收口前缀开头（`PASS` / `N/A` / `✅` / `已`）
- **THEN** 判为已收口，不要求登记字段

#### Scenario: 未收口必须自带登记

- **WHEN** 一篇记录既无派生证据、状态列又未闭合
- **THEN** 同一文件内必须写明登记原因与回填责任人，登记字段不得为空

## ADDED Requirements

### Requirement: 合并账本与记录归属只允许一份实现，取不到读数一律按未证实处理

系统 SHALL 提供唯一实现用于「由 git 现场推导合并事实」，至少导出：合并账本（PR 号 → merge SHA 与时间，只认 squash 尾注 `(#NNNN)$`）与记录归属映射（记录文件路径 → 首次把它加入基线的提交）。判据 SHALL 从该实现取值，MUST NOT 在判据内另写 git 解析。该实现在解析时 MUST 关闭重命名检测并关闭路径转义（`--no-renames`、`core.quotepath=off`），否则改名与含非 ASCII 路径会被静默漏解析。

**任何取不到读数的分支（基线 ref 不可解析、git 命令失败、账本规模读数为 0）SHALL 使推导档整体停用并出声打印原因，退回断言通道判定；MUST NOT 把"看不见账本"读成"已合并"。**

#### Scenario: 归属与账本同源

- **WHEN** 判据需要判断某篇记录是否已随合并进入基线
- **THEN** 结论来自共享实现的同一次遍历，且现场打印账本规模（`MERGE-LEDGER prs=<n>`）作为"这一趟真的测过"的证据

#### Scenario: 账本不可用不得判绿

- **WHEN** 基线 ref 取不到或账本规模读数为 0
- **THEN** 打印推导档停用，并退回"只有状态列写明收口写法才算收口"的口径；未收口记录仍被判为欠账

#### Scenario: 改名不自动跟随

- **WHEN** 某篇记录在后续提交中被改名或移动
- **THEN** 归属解析不到该路径，记录落入未收口或兼容档并出声，MUST NOT 把改名所在提交当成它声称的那次交付

### Requirement: 记录不得预写尚不存在的合并证据，且声明的归属与 git 事实不符时判红

系统 SHALL 拒绝两类"声明与事实不符"：

1. **预写**——该记录文件是本次变更集新增（基线上尚不存在），而状态列写了闭合词 ⇒ 判红。理由：一篇还没进主干的记录不可能已经"远程同步"，这正是断言通道无法分辨、改造前长期存在的缺口。
2. **归属不符**——该记录显式声明了来源 PR，而 git 推导出的"把它带进基线的 PR"与之不同 ⇒ 判红。该字段缺省时本条不参与判定（存量不动）。

#### Scenario: 合并前预写 PASS 变红

- **WHEN** 一个 PR 新增记录文件并把状态列写成 `PASS`，而该文件在基线上不存在
- **THEN** 判红并指明"该记录尚未进主干，不得预写已合并"

#### Scenario: 本次变更集新增的记录不得判成欠账

- **WHEN** 记录文件由本次变更集新增且状态列未闭合
- **THEN** 判为 byDesign（自己不能证明自己已合并），不拦截；该 PR 合并后同一条记录 SHALL 经派生通道自动收口，无需任何写回

#### Scenario: 声明 PR 与实际带入 PR 不符

- **WHEN** 记录声明来源 PR 为 `#A`，而基线上首次新增该文件的提交尾注为 `#B`
- **THEN** 判红并打印两个编号；不得静默择一

#### Scenario: 存量零漂移

- **WHEN** 改造合入后在同一条主干上重跑判据
- **THEN** 拦截集合与改造前逐篇相同，且记录文件的字节内容零改动；任何"改前绿→改后红"的新增拦截一律视为回归
