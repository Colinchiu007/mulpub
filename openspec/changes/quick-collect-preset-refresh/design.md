# 设计：快捷采集·内置词条按用户真实需求重排

## 1. 根因：为什么「agent 推演的内容」会被当成「用户要求」

链条是这样的（每一步单独看都合理，合起来就错了）：

1. 用户在需求里给了**一条**提示词原话（AI 与新技术领域的真实动态）；
2. 上一个会话为了让「快捷采集」这一页更像产品，**另外推演了 5 条内置词条**（热点选题、平台规则、创作工具、同行趋势、舆情风险），
   推演依据写进了 PRD §1 的三个场景 —— 其中场景 2 是"我关心平台规则有没有变化"；
3. 6 条词条与 3 个场景**放在同一份 PRD / 同一个 proposal 文件里**，只有 `AI 领域动向` 带"用户给定文本"标记；
4. 后续会话（本轮）读 PRD 时，把"PRD 里写着"等价于"用户要过"，于是为场景 2 排了整片 S3 扩展。

**可复用的判据**：文档里的「需求」与「推演」必须能被机械区分，而不是靠读者回忆谁说过什么。
对照串（AC-10）只覆盖了 1 条，其余 5 条在结构上与它**无法区分** —— 这就是漏洞本身。

## 2. 修法：给每条词条加 `provenance`，并把它锁进测试

```js
provenance: 'user'   // 用户给定原文：逐字实现，改动即改需求（本仓有独立手录对照串锁着）
provenance: 'agent'  // 依 PRD 场景推演的产品内容：可随需求调整，改动不算改需求
```

三条设计取舍：

- **为什么不放渲染端**：词条本身在主进程（产品内容，且要随版本更新），来源标注必须与词条同处一地，
  否则又会分叉出第二份清单。
- **为什么是 `'user' | 'agent'` 两态而不是自由文本**：两态能被断言锁死（"恰好一条 user"），自由文本不能。
  本次事故的本质是"可被含糊描述"，判据必须做到没有解释空间。
- **为什么不干脆删掉其余 5 条只留用户那条**：用户明确表示"官方内置 + 自定义"的产品形态是他要的、
  且这 5 条也都是 AI/创作向的实用内容；本次只按用户点名处替换 2 条，其余保留并标 `agent`。

## 3. 替换后的两条词条为什么这么设计

### 3.1 `builtin-ai-papers`（📄 AI 前沿论文速览）

- **它填的是一个真实空白**：S2 接进来的 `arxiv_cs_ai` 与 `hf_papers` 目前**没有专属词条** ——
  `builtin-ai-trends` 虽含这两个源，但它的提示词侧重"版本发布 / GitHub 新项目 / 重大事件"，
  论文在这套问法下会被当成"事件"压缩掉。用户原话里的"AI 与新技术领域的真实动态"包含研究前沿。
- **源选择**：`arxiv_cs_ai` + `hf_papers`（论文主场）+ `qbitai`（中文 AI 媒体解读）+ 英文社区三源（讨论/复现反馈）；
  `windowHours: 168` —— 论文是周级节奏，且 arXiv 周末空榜（`emptyBySchedule` 已能如实表达，不算故障）。
- **提示词要求写"能不能用上"**：只报标题没价值；要求给"对哪类人有价值 + 是否已有开源实现/可试用工具"，
  把论文落回"值不值得关注"这个用户原始判据上。

### 3.2 `builtin-ai-howto`（🛠️ AI 实操技巧与工作流）

- **用户要的是"其他实用的"**：这条的产出是**可以直接照做的做法**，而不是"发生了什么"。
- **源选择**：`sspai` / `oschina` / `infoq_cn`（中文科技时间线，实用类文章多）+ 英文社区三源；
  不吃中文热榜（榜单没有"教程"，硬吃只会得到噪音 —— 已由测试断言锁住）。
- **提示词要求可复制**：每条必须给"最小可复制的提示词/步骤骨架 + 前置条件 + 复现反馈 + 预期收益"，
  并单列"听着好但实际不好用"的做法 —— 与既有词条"宁缺毋假"的写法一致（找不到就说找不到）。
- **为什么与 `builtin-dev-tools` 不重复**：后者讲**工具的新版本/新能力**（东西），前者讲**怎么用**（方法）。

## 4. 风险与边界

- **旧 id 的历史结果**：已跑过的结果条目里 `quickCollect` 溯源字段存的是**指令标题文本**（只用于展示），
  不存在"词条被删导致结果打不开"的问题；不做数据迁移。
- **两条新词条由 agent 编写**：所以它们自己就是 `provenance:'agent'` —— 这套机制不假装新内容变成用户要求了。
- **词条数量不变**：渲染端、校验、存储口径均不受影响，本次不引入迁移风险。
