# desktop-ui-consistency — 可见导航（UX 审计 1.5）

## ADDED Requirements

### Requirement: 同一导航动作在鼠标与键盘两条入口上必须产生同样的可见结果

"导航"必须作用于**当前真正显示给用户的那一面**，而不是固定作用于主窗口路由。
本应用同时存在三种"当前页面"：首页虚拟标签（主窗口 SPA）、普通网页标签（原生
`WebContentsView` 覆盖层）、内嵌主页实例（home-shell，一个独立的 SPA 实例）。
两条入口（侧边栏点击、全局快捷键）**MUST 走同一段实现**；MUST NOT 在任一处保留
第二份"该跳到哪一面"的判断。

#### Scenario: 停在网页标签时按快捷键

- **WHEN** 用户聚焦在普通网页标签上（原生覆盖层可见）并按下导航快捷键
- **THEN** 先切回首页标签，再推主窗口路由，顺序不可反
- **AND** 屏幕上出现目标页面；MUST NOT 只改主窗口路由（那会让跳转发生在覆盖层背后，用户看不到任何变化）

#### Scenario: 聚焦内嵌主页实例时按快捷键

- **WHEN** 当前聚焦标签是 home-shell 实例且主进程回执 `handled:true`
- **THEN** 由该实例自身跳转，主窗口那条隐藏路由 MUST NOT 被推（否则两侧路由从此漂移）
- **AND** 不重复切标签

#### Scenario: 已在首页标签时不产生多余副作用

- **WHEN** 当前聚焦就是首页标签
- **THEN** 只推主窗口路由，MUST NOT 再发一次切标签的 IPC
- **AND** 与鼠标点侧边栏的结果逐字相同

#### Scenario: 两条入口的实现收敛

- **WHEN** 快捷键入口被改回裸的"只推主窗口路由"，或侧边栏重新自带一份三段判断
- **THEN** 结构锁判红（扫描域排除注释行，避免说明文字自指）

### Requirement: 「没拿到回执」不得读成「已经处理」，降级必须出声且仍可完成

定向导航的成败判据是主进程回执的内容，不是"调用过这个 API"。
只有回执形如 `{ code: 0, data: { handled: true } }` 才算被内嵌实例接管；其余一律
**继续走主窗口可见路径**。降级过程 MUST NOT 抛给调用方（快捷键回调炸掉壳层比跳错页更糟），
且必须以告警形式留下痕迹。

#### Scenario: 无回执的四种形态

- **WHEN** 回执为 `null`、`code` 非 0、`data` 缺席或 `handled:false`
- **THEN** 回落到"切回首页标签 + 推主窗口路由"，导航照常完成
- **AND** 这四种形态逐个被测（不得只测其中一种）

#### Scenario: 定向 IPC 抛错

- **WHEN** 定向调用自身抛异常（桥断开、主进程 handler 报错）
- **THEN** 记一条告警并回落主窗口路径；MUST NOT 把异常读成"已处理"

#### Scenario: 切标签失败仍然完成跳转

- **WHEN** 已决定要切回首页标签但切标签失败
- **THEN** 仍然推主窗口路由（至少路由对了，用户切回首页时看到目标页）并记告警

#### Scenario: 宿主没有该能力

- **WHEN** 运行在纯浏览器开发态或旧版 preload（无 `pageManager` 或无该方法）
- **THEN** 不抛错，按主窗口路径完成跳转

#### Scenario: 标签列表里没有首页标签时，仍跳转但必须留痕

- **WHEN** 当前聚焦是普通网页标签，而标签列表里找不到首页虚拟标签（异常数据形态）
- **THEN** 仍然推主窗口路由（不得什么都不做）
- **AND** 必须记一条告警：这条路径的可见结果与「跳转发生在覆盖层背后」这一缺陷 1:1 同形，
  静默走完等于把缺陷重新变成无日志的沉默
- **AND** 反向同样成立：标签列表正常时**不得**误报该告警（防它退化成恒发）

### Requirement: 导航入参必须按类型而非按真值校验，且被拒绝的输入必须留下痕迹

入参非字符串、空串一律不动作；但 `'/'`（回首页）MUST 被当作合法目标 ——
真值判空会让这一格静默失效。被拒绝的输入 MUST NOT 静默丢弃：静默丢弃与
「按了没反应、日志零痕迹」同形，正是本单元要消灭的缺陷形态。

#### Scenario: 非法输入不动作但出声

- **WHEN** 目标为 `''`、`null`、`undefined`、数字或对象
- **THEN** 既不切标签也不推路由
- **AND** 记一条告警（逐个非法值各一条），排障者能从日志知道"这个请求到过但被拒了"

#### Scenario: 根路径是合法目标

- **WHEN** 目标为 `'/'`
- **THEN** 正常跳转到首页

#### Scenario: 宿主取不到桥

- **WHEN** 运行在纯浏览器开发态或旧版 preload
- **THEN** 不抛错，按主窗口路径完成跳转，且不为此制造噪声日志

### Requirement: 注入依赖必须在每个调用点被装配

可见导航需要读宿主桥（`electronAPI`）。依赖由调用点注入，实现本身 MUST NOT 直接 import 桥模块
（否则每个 mock 桥接层的测试夹具都被迫补出该具名导出，间接导入会把无关用例整片打红）。
"调用点漏传注入参数"不会编译失败，只会让定向分支恒不生效，因此 MUST 有按调用点的装配锁，
且调用点集合 MUST 与登记清单一致（新增入口不得带着未登记的调用点上线）。

#### Scenario: 漏传注入参数会当场变红

- **WHEN** 某个生产调用点的 `useVisibleNavigation({ … })` 不再传入取桥函数
- **THEN** 装配锁判红并点名该文件

#### Scenario: 新增入口必须登记

- **WHEN** 仓内出现第三个调用该实现的文件而未登记
- **THEN** 调用点集合断言判红（清单只能与现场一致，不得靠记忆维护）

#### Scenario: 取桥必须惰性求值

- **WHEN** 调用点在 setup 期直接绑定 `getApi` 而不是传 `() => getApi()`
- **THEN** 依赖 mock 桥接层的既有用例会在 import/访问期报错——该形态 MUST 被避免并在实现注释中写明原因
