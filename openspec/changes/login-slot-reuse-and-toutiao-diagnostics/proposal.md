## Why

头条号登录页「点发送验证码 → 灰显几秒 → 才弹图形验证码」这件事，2026-10-21 现场复现后归因出**两个不同责任方**：

**其一，平台侧（不在本仓责任范围，但必须如实登记）**

- 登录页引用的 `https://s3a.bytecdn.cn/ta/resource/v0/analytics.js` 被**字节自家边缘节点 504**，
  挂 **9~17 秒**（实测：直连真实 CDN IP `111.13.110.60` 同样 504，TTFB 9.3s；
  让 Jina Reader 从它自己的服务器拉同一文件**同样 504** ⇒ 字节侧故障，非本机线路）。
- 图形验证码组件（`sf16-secsdk.ibytedtos.com/.../webmssdk.js` 520KB +
  `sf16-scmcdn-*.ibytedtos.com/.../captcha.js` 784KB）在**冷缓存**下各要 ~1.1s。
- 登录页另带 43MB 背景视频（206 分段响应，Chromium 不入磁盘缓存 ⇒ 每次仍重拉，本刀也救不了）。

**其二，本仓（本刀修的部分）**

1. **登录视图每次新建空分区**：`AuthViewManager.openLogin` / `QrCodeLogin.openLogin` 都用
   `Date.now()` 造一个全新分区 ⇒ 第三方登录页的 HTTP 缓存**每次从零开始**。
   同一台机器上普通 Chrome 因为早就缓存了这些资源而「正常」，
   于是用户看到的是「浏览器正常、app 慢」——这个差异**是本仓造成的**。
2. **头条号的请求一条都不记**：`login-network-diagnostics` 的过滤面只有微信/腾讯域，
   头条登录链路的失败、慢请求、验证码组件加载时长全部无痕 ⇒ 现场只能靠外部抓包倒推。

## What Changes

- **登录视图与扫码登录改为「按平台复用同一分区目录」**（槽位 `auth-auth-<platform>-slot`）：
  目录名不带时间戳 ⇒ 缓存跨多次登录留存；HTTP 缓存**不再被清**。
- **凭证隔离改由「开局清槽位」保证**：导航前清掉槽位里的旧 Cookie/存储（保留 HTTP 缓存），
  否则复用槽位会让第二次登录直接命中上一个账号的登录态（平台自动登录 ⇒ 静默存成重复账号）。
- **「本轮是否取到凭证」改为按轮次判定**：槽位跨轮次同名，按分区名判会把「上一轮成功」
  误当成「本轮成功」⇒ 该清的没清。
- **发布链磁盘兜底的读取端零改动**：槽位落在既有前缀 `auth-auth-<platform>-` 下，
  读取端「从新到旧逐份探」会先探槽位、槽位空时自然落到旧目录 ⇒ 回退链完整保留。
- **头条号进入登录期观测面**：会话级记失败请求与 HTTP ≥ 400；CDP 记慢请求耗时、
  图形验证码组件加载完成、监测域内请求失败。**未登记平台行为一字不变。**
- 配套：用户侧排障手册（OpenClash 规则写法 + 验证步骤）`01-docs/TROUBLESHOOT-TOUTIAO-LOGIN-SLOW-2026-10-21.md`。

## Impact

- 影响规格：`desktop`（ADDED 登录槽位与轮次判定）、`desktop-logging`（ADDED 按平台登录期观测）。
- 影响代码：`apps/desktop/electron/services/auth-partition-reclaim.js`（槽位命名与豁免、
  保留缓存的清理、按轮次的 captured 判定）、`auth-view-manager.js`（槽位 + 开局清 + 关闭保留缓存）、
  `qrcode-login.js`（槽位 + 开局清）、`login-network-diagnostics.js`（按平台过滤面 + 计时层）。
- **新模块（按仓内行数门禁拆分）**：uth-login-slot.js（槽位规则单一真源，**叶子模块**：不反向依赖回收模块）、login-network-monitor.js（覆盖面与判定口径）、uth-view-saved-account.js（「打开已保存账号」纯平移，行为逐字不变，特征测试先钉住）。
- **性能**：监测域匹配由「每请求线性扫域数组」改为**按平台编译正则并缓存**（O(1) 查表）；同一平台的多次登录共享一份 HTTP 缓存 ⇒ 第二次起不再重下风控 SDK 与页面资源。
- **行为变化（唯一一处，用户可感知）**：同一平台第二次起打开登录页更快（风控 SDK 与页面资源命中缓存）。
  用户可见 UI、文案、按钮、弹窗**零变化**。
- **已知取舍（如实登记）**：① 43MB 背景视频不受益（206 分段不入磁盘缓存）；
  ② 「正在重新登录」的窗口内，发布链的**分区兜底**读不到槽位（凭证库真源不受影响）；
  ③ 同一平台两个登录 UI 同时打开的边缘情形下共用槽位（实际 UI 一次只开一个）。
- 存量一次性目录（老版本留下的 `auth-auth-<platform>-<ts>`）仍按既有窗口回收，不受影响。
