# Design — freeze-legacy-gate-carrier

## Context

要取消的是"每个 PR 都必须往两个全仓共用文件里写一笔"这个动作，而不是取消这两个文件本身——它们承载 2026-08 以来的 613 个记录块（现值以 `scripts/gate-carrier-freeze.json` 为准；读数演进链 603→605→607→613，四次都是主干前进后判据当场报红、由人工重取，见 tasks 1.1）与 25 条未收口欠账，是审计痕迹的历史所在，也是别人正在关账的对象。

## Decisions

### D1 基线用「排序标题的 sha256 + 条数」，不用 `git show <冻结commit>:`

后者更省文件，但 CI 默认浅检出**取不到**那个 commit。而这个判据一旦读不到基线，只剩两种可能：静默跳过（= 空集恒真，本仓反复复发的形状：`gh pr checks` 在 pending 时以非 0 退出但表格在 stdout、只取 try 分支 ⇒ 空集 ⇒ "最该等的时候判通过"）或每跑必红。基线入库为一个小 JSON，判据不依赖任何历史可达性；同时用两条抛错把"读不到"和"零基线"都堵死（缺文件抛 `冻结基线缺失`，`headingCount<=0` 或缺 sha 抛 `不合法`）。

代价如实记：多一个约 73 KB 数据文件（实测 74378 字节，613 条标题），**且它是一次会随主干漂移的读数**——落地前后共重取四次（603→605→607→613），第四次发生在合并后的回填笔里。

### D2 判据是"集合相等"，不是"不许变多"

只卡"不许加块"会留下另一条静默通道：把旧块整体搬走/覆盖（本仓实测过 `git add -u` 收走他人改动、以及"整取 tip 会回退主干上他人的 `.ccg` 产物"）。所以加块与删块同判红，added / removed 各自点名。

已知漏洞（不假装已闭合）：净零漂移（一加一删）时计数不变、只有哈希变——因此仍判红，但报出的两个清单会同时非空，需要人读。这比"完全看不见"强，比"自动定位到肇事提交"弱。

### D3 必须保留"就地改状态行"这条合法通道

判据若把旧载体一律封死，会立刻造出 25 条无法关闭的欠账（实测：`gate-record-debt-ledger.json` 里键最多的仍是 2026-08 的老记录，只存在于旧载体）。而且那会**复制**本 change 要消灭的那个副作用：为了关一笔旧账，作者被迫去做一次"结构性"改动（比如把旧块改头换面以绕过哈希），从而制造新的更大漂移。所以"只改状态行不算漂移"不只是便利，是防止判据被绕过的必要条件，并配一条**正向**用例钉住（`冻结：只改已有块里的状态行 ⇒ 不得报漂移`）。

### D4 顶部棘轮退役，但不是删掉这条信息

`topRecordMissingRow` 继续计算并作为可见项打印，只从 `hasBlocking` 移除；同时删掉旧的 `❌ 最顶部的执行记录缺…` 打印——**不拦截却打 ❌ 会把读者引向一个不存在的失败**，与本仓"不得承诺一个不在该代码路径上的错误码"同型。"哪篇最新"改由记录文件源承担：每篇都必须带状态行（`missingRecordRows` 在拦截面上），不再需要靠位置猜。

### D5 基线注入而不是硬编码

`collect({ carrierFreeze })` 由调用方注入，只有 CLI 侧读生产文件。理由是本仓踩过两次的同款：把清单/例外写成常量会让夹具恒判陈旧、8 条测试集体红；而"给了夹具目录却静默读生产状态"是假绿通道（同一文件的 `loadLedger` 就是这么修的）。配一条用例断言"未注入 ⇒ 不报漂移"，并另有一条断言"缺基线必须抛错"。

### D6 与 `hot-carrier-atomic-landing` 的关系：让位而不是并存

那份规格（本日已合入）的三档里，(2) 一条命令收口 与 (3) pre-commit 归属拦截 的对象在本 change 之后**不再出现于新 PR**（新 PR 不写旧载体），继续实现只会新增"别人窗口没关，我的提交被拒"的误伤面。因此按它自己写的退场条件处理：保留 (1) 事后测量（守卫侧窗口读数，仍能捕获"有人就是去改了旧载体"这一残余形态），(2)(3) 标为不实现并在其 tasks.md 里写明理由与指回本 change。

## Risks & Rollback

- **R1 判据本体变更，须人工过目**：`check-gate-record-debt.js` 是 required check（`QG Changes` / Gate 2c）的判据来源，按 AGENTS.md 属"改谁来守门"，本 PR 不自动合并。
- **R2 误伤正在写旧载体的在飞会话**：基线是在本 worktree 生成的；若某会话已把旧载体的新块提交进 main，rebase 后哈希必然不等 ⇒ 本判据当场红并点名那块。这是**期望行为**（它正是我们要拦的形态），但处理办法是把内容改写进 `openspec/records/` 而非重算基线；因此实现 PR 合入前，主干若已出现新块，须以 rebase 后的树重算一次基线（人工）。
- **R3 约 73 KB 基线被误改**：判据直接由同一文件计算，手改基线等于同时改判据——归入 R1 的人工审查面；未来可加一条"基线只能由 `freeze-gate-carrier.js` 生成"的结构断言，但那条断言本身要靠读源文件比字节，收益不抵本轮范围，暂不做。
- **回退**：`hasBlocking` 里摘掉 `r.carrierDrift`、删除基线与生成器即可完全回退；测试里有 `escaped=0` 的变异反证记录（M1 摘拦截项 / M2 哈希改常量 / M3 缺基线静默跳过，各让不同指名字用例变红），回退后这些用例会红，是防止"静默留着半套判据"的护栏。
