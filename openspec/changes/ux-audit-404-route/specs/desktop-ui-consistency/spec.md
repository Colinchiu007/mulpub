## ADDED Requirements

### Requirement: 无法匹配的地址必须落到可见的兜底页

任何解析不到路由记录的地址，应用必须渲染一个明确的「页面不存在」兜底视图，
而不是留下一个只有外壳、内容区空白的页面。兜底页必须如实回显用户试图访问的路径。

#### Scenario: 用户手输一个不存在的地址

- **WHEN** 导航到一个 `routes` 数组里不存在、也不属于任何已声明动态路由的 hash 地址
- **THEN** 内容区渲染兜底页，且页面上出现用户输入的那条路径原样文本

#### Scenario: 兜底页不得是空白

- **WHEN** 兜底页渲染完成
- **THEN** 页面至少包含一条说明文案与一个可点击出口，DOM 中不存在「内容区零子节点」的状态

#### Scenario: 已知地址不受影响

- **WHEN** 导航到一个已登记的具体路径（如 `/collection`）
- **THEN** 渲染该路径自己的视图，兜底页不参与匹配

### Requirement: 兜底页必须给出可执行的出口，且不得把用户困在原地

兜底页必须提供「回到主页」出口；当且仅当存在可回退的应用内历史时，才提供「返回上一页」出口。
用户点击出口必须真正离开兜底页，而不是原地重渲染。

#### Scenario: 回主页

- **WHEN** 用户点击「回到主页」
- **THEN** 路由离开兜底页并落在主页，兜底页不再渲染

#### Scenario: 没有可回退历史时不出现「返回上一页」

- **WHEN** 用户直接以错误地址启动应用（应用内没有更早的历史条目）
- **THEN** 页面不渲染「返回上一页」出口，只渲染「回到主页」

#### Scenario: 有可回退历史时出现「返回上一页」

- **WHEN** 用户从应用内某个页面进入兜底页
- **THEN** 页面渲染「返回上一页」出口，点击后回到进入前的页面

### Requirement: 兜底路由在路由登记表中是一等类型，且不谎报入口

路由登记表必须用显式的 catch-all 类型表达兜底路由，而不是用「暗路由 + 宿主入口」来表达它。
门禁必须保证全表恰好一条 catch-all、其路径形状与路由器声明一致，且该登记项不声明侧边栏入口、
不声明宿主入口。

#### Scenario: 兜底路由必须登记为 catch-all

- **WHEN** 路由器声明了 catch-all 路由但登记表未把它标记为 catch-all
- **THEN** 路由登记门禁失败，并指出该路由未能回答入口

#### Scenario: 兜底路由不得有第二条

- **WHEN** 登记表出现第二条被标记为 catch-all 的登记项
- **THEN** 路由登记门禁失败

#### Scenario: catch-all 不得伪装成侧边栏项或暗路由

- **WHEN** catch-all 登记项同时带有侧边栏入口声明，或被标记为暗路由
- **THEN** 路由登记门禁失败

#### Scenario: 普通暗路由的入口要求不得被放宽

- **WHEN** 一条非 catch-all 的登记项既无侧边栏入口又未申报宿主入口
- **THEN** 路由登记门禁仍然失败（豁免只作用于被标记为 catch-all 的那一条）

### Requirement: 兜底页的可见文案与标签标题必须可本地化且不泄漏内部细节

兜底页所有用户可见文案必须以 zh/en 成对的形式存在于语言资源中；标签页标题必须有对应映射，
不得静默回退成应用品牌名。兜底页只回显用户输入的路径，不得显示组件名、chunk 名或错误堆栈。

#### Scenario: 语言切换后文案随语言变化

- **WHEN** 应用语言分别为中文与英文时渲染兜底页
- **THEN** 页面文案来自语言资源对应语言，不出现另一种语言的残留

#### Scenario: 标签标题不回落品牌名

- **WHEN** 用户停留在兜底页
- **THEN** 标签标题使用该页面的标题键，而不是应用品牌名兜底值

#### Scenario: 不显示内部实现细节

- **WHEN** 兜底页渲染任意错误路径
- **THEN** 页面上不出现视图文件名、chunk 名或异常堆栈文本
