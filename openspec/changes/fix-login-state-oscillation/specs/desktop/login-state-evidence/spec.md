## Purpose

规定登录态真源（后端 `accounts.json` 的 `status`）被改写所需的**证据门槛**：只有拿到正向证据（检测成功）或负向证据（检测明确失效）才允许改写；「本轮没拿到定论」既不是正向也不是负向证据， MUST NOT 被当成反证去覆盖既有结论，但也不能让一个长期拿不到定论的账号永远保持乐观。据此消除 `active ↔ unverified` 周期性振荡，同时不回到「无证据却显示已登录」的假绿灯。

## ADDED Requirements

### Requirement: 登录态只被正向或负向证据改写
系统 SHALL 只在检测给出明确结论时改写登录态真源：结论为有效时 MUST 写 `active`，结论为失效时 MUST 写 `expired`。当检测**未取到定论**（结果既非有效也非失效、被跳过、超时、或检测自身抛异常）时，系统 MUST NOT 把既有的 `active` 或 `expired` 改写为 `unverified`；`unverified` MUST 只表示「从未有过结论」。

#### Scenario: 已登录账号遇上一轮无定论的检测
- **WHEN** 某账号真源为 `active` 且最近一次定论在宽限期内，本轮检测返回无定论
- **THEN** 系统不发起任何登录态写入，真源保持 `active`
- **AND** 该账号在结果中被标记为「本轮未改写真源」，而不是被降级为「未确认」

#### Scenario: 已失效账号遇上一轮无定论的检测
- **WHEN** 某账号真源为 `expired`，本轮检测返回无定论
- **THEN** 真源保持 `expired`，不得因缺证据被翻成 `unverified` 或 `active`

#### Scenario: 从未有过结论的账号
- **WHEN** 某账号真源没有 `status` 或已是 `unverified`，本轮检测返回无定论
- **THEN** 真源为 `unverified`，界面如实显示「未确认」

#### Scenario: 检测拿到明确失效
- **WHEN** 任意现状的账号，本轮检测明确返回失效
- **THEN** 真源被写为 `expired`，不受宽限期与「保持原状」规则影响

### Requirement: 保持原状必须有超龄兜底
系统 SHALL 为「无定论时保持 `active`」设定可配置的时间上限：当账号最后一次拿到定论的时间距当前超过宽限期（默认 7 天，可由 `MP_LOGIN_STATE_GRACE_DAYS` 调整），或该时间戳缺失/不可解析时，本轮无定论 MUST 使真源降级为 `unverified`，以避免已实际失效却长期显示已登录的僵尸绿灯。

#### Scenario: 长期拿不到定论的已登录账号
- **WHEN** 某账号真源为 `active`，其最近定论时间已超出宽限期，本轮检测仍无定论
- **THEN** 真源降级为 `unverified`
- **AND** 该变化照常广播给界面刷新

#### Scenario: 缺少定论时间戳
- **WHEN** 某账号真源为 `active` 但没有可用的最近定论时间
- **THEN** 本轮无定论即视为超龄，降级为 `unverified`

#### Scenario: 运维调整宽限期
- **WHEN** 运维把 `MP_LOGIN_STATE_GRACE_DAYS` 设为非正数或非法值
- **THEN** 系统回落到默认 7 天，不出现「零宽限」或「永不降级」

### Requirement: 三态判定口径必须唯一
系统 SHALL 把「检测结果 + 当前真源 → 是否改写了什么」的判定收敛为唯一一处实现，检测链路的每个入口（单账号检测、批量检测、后台定期监控）MUST 复用同一实现，不得各自维护一份三态映射。新增「无定论」出口时 MUST 由该唯一实现的回归用例覆盖，否则视为口径漂移。凭证成功落盘（登录/重新登录）属正向证据，MUST 继续直接固化 `active`，不经由该判定函数形成双重门控。

#### Scenario: 新增一条无定论出口
- **WHEN** 某平台检测实现新增一个「跳过 / 超时 / 异常」返回路径
- **THEN** 该路径经唯一实现判定后遵守「无定论不改写 + 超龄降级」，并由唯一实现的规则表回归用例覆盖

#### Scenario: 登录成功保存凭证
- **WHEN** 用户登录成功且加密凭证落盘成功
- **THEN** 系统直接固化 `status='active'` 与 `last_validated`，不做「保持原状」判定

### Requirement: 界面必须区分「未取到定论」与「未确认」
系统 SHALL 在批量检测汇总中把「本轮未取到定论」与「已失效」分别计数与表述，文案 MUST 明确本轮未改写真源；未取到定论的账号 MUST NOT 被计入失效集合，也 MUST NOT 因此显示「去登录」入口。

#### Scenario: 混合结果的汇总提示
- **WHEN** 一轮批量检测得到 1 个明确失效、1 个无定论、其余有效
- **THEN** 汇总文案同时报出失效数量与「未取到定论（保持原状态）」数量
- **AND** 无定论的账号在界面上保持其原有徽章，不出现「去登录」
