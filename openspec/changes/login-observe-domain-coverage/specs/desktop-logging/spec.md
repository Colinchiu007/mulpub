## ADDED Requirements

### Requirement: 登录期观测的覆盖面 MUST 覆盖真实登录页静态引用的资源域

头条号登录期观测的监测域清单 MUST 覆盖**真实登录页静态引用**的全部资源域，
MUST NOT 仅覆盖「首屏运行时已发起请求」的域。

- 取数 MUST 同时使用两个互补的口径：
  - **运行时请求流**（首屏加载触发的域）；
  - **登录页 HTML 的静态引用**（页面引用但尚未被请求的域，含按需加载的验证码组件）。
- 只用运行时请求流会**结构性漏掉**「点发送验证码之后才按需加载」的组件域 ⇒ 视为覆盖不完整。
- 清单 MUST 是**实测得来**的，MUST NOT 是拍脑袋的通配清单。
- 补充 MUST NOT 放宽既有匹配口径（主机名等于监测域或为其子域；不用 URL 子串宽匹配）。

#### Scenario: 按需加载的验证码组件域也在监测面内

- **GIVEN** 头条号登录页 HTML 静态引用了某验证码组件域的脚本
- **WHEN** 读出注册给 webRequest 的过滤面
- **THEN** 该域 MUST 出现在过滤面里
- **AND** 该域上的请求 MUST 能命中 `isMonitoredHost`

#### Scenario: 清单覆盖新增域后过滤面同步生效

- **GIVEN** 监测域清单新增某域
- **WHEN** 读出该平台的过滤面
- **THEN** MUST 同时含 `*://<域>/*` 与 `*://*.<域>/*` 两条

### Requirement: 图形验证码组件的判定 MUST 覆盖真实链路上出现过的路径形态

「图形验证码组件加载完成」的判定 MUST 命中**真实登录页实际引用的**组件路径形态，
MUST NOT 只覆盖单次实测中的某一种包形态。

- 判定 MUST 是**组合锚点**（版本目录段与组件段**同时**出现），
  MUST NOT 退化为「只认其中一段」的宽匹配：
  - 只认组件段 ⇒ 无关资源误命中，噪声淹没真信号；
  - 只认版本目录段 ⇒ 同目录下非验证码资源被算成组件，灰显时刻读数失真。
- 既有包形态的锚点 MUST 保留，既有反例（查询串 / 域名里出现标记名不算）MUST 继续成立。
- 风控 glue 一类的**非验证码**资源 MUST NOT 被判成验证码组件（否则灰显时刻读数提前）；
  它在监测域内时，其慢请求与失败 MUST 照常被记。

#### Scenario: 真实链路的验证码入口被判定为组件

- **GIVEN** 某验证码组件脚本的 URL 形如
  `<主机>/obj/rc-verifycenter/sec_sdk_build/<版本>/captcha/index.js`
- **WHEN** 判定该 URL 是否为验证码组件
- **THEN** MUST 判定为真

#### Scenario: 只满足组合锚点其中一段的不算组件

- **GIVEN** 某 URL 的路径含验证码段但**不在**版本目录下
- **WHEN** 判定该 URL 是否为验证码组件
- **THEN** MUST 判定为假

#### Scenario: 版本目录下但非验证码资源的不算组件

- **GIVEN** 某 URL 的路径含版本目录段但**不含**验证码段
- **WHEN** 判定该 URL 是否为验证码组件
- **THEN** MUST 判定为假

#### Scenario: 查询串与域名里出现标记名仍不算

- **GIVEN** 某 URL 的查询串或域名里出现组件标记名
- **WHEN** 判定该 URL 是否为验证码组件
- **THEN** MUST 判定为假
