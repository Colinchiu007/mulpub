## Purpose

定义「pre-commit 钩子把 CCG 判定记录自动暂存进同一次提交」这一行为**应当付出的机械成本上界**，以及它的候选集合语义在实现改写后必须保持不变的部分。目标是把「提交耗时随审计留痕数量线性恶化」这一形态从设计内建变为可判定且默认变红，同时不得以「什么都不做」来冒充「做得更快」。

## ADDED Requirements

### Requirement: 判定记录自动暂存的进程创建次数 MUST NOT 随树上记录数增长

钩子 MUST 从 git 自身视图派生待暂存集合（未跟踪集 ∪ 已跟踪但有改动集），并 MUST 以常数次 git 进程创建完成该判定；MUST NOT 对 `.ccg/reviews` 下的每个文件逐个 fork git 询问其状态。该要求的判据 MUST 是「调用次数与记录数无关」，而非某个绝对预算数字。

#### Scenario: 记录数增长时调用次数逐字不变

- **WHEN** 同一钩子分别在待判定记录数为 2 与为 200 的仓库上各执行一次提交
- **THEN** 两次执行中钩子产生的 git 调用总数必须完全相等，且 argv 中出现 `.ccg/reviews` 的调用数必须 ≤3

#### Scenario: 大批记录仍须全部入库（不得以不干活达标）

- **WHEN** 仓库存在 200 条未跟踪判定记录且一次提交完成
- **THEN** 该次提交的文件清单必须包含全部 200 条记录；若调用数达标而入库数不足，判不合规

#### Scenario: 目录缺失或为空时不发起暂存

- **WHEN** 仓库不存在 `.ccg/reviews` 目录，或该目录存在但无匹配记录
- **THEN** 钩子必须正常通过、不得报错，且不得发起任何 `git add`

### Requirement: 候选集合语义 MUST 与既有实现逐字同域

改写后的候选集合 MUST 恰好等于「未跟踪的 `.ccg/reviews/*.json`」∪「已跟踪且工作树已改动的 `.ccg/reviews/*.json`」；已跟踪且无改动的记录 MUST NOT 被重复暂存；该目录下非 `.json` 的文件 MUST NOT 进入候选。pathspec MUST 覆盖 `*.json` 且 MUST 由 git 侧匹配（不得交由 shell 展开），且 MUST NOT 跨目录分隔符 `/`——git 裸 pathspec 的 `*` 走 wildmatch 且未置 `FNM_PATHNAME`，相对旧形态所用的 POSIX pathname expansion（`*` 不跨 `/`）**多出一层子目录**，因此 MUST 带 `:(glob)` 路径魔法，否则「逐字同域」只对扁平目录成立。

#### Scenario: 三种状态的记录各自得到正确处置

- **WHEN** 夹具同时预置未跟踪记录、已跟踪但已改动的记录、已跟踪且无改动的记录各若干，以及一个非 `.json` 文件
- **THEN** 提交结果必须只包含前两类的全部文件；第三类与非 `.json` 文件不得出现在该次提交的文件清单中

#### Scenario: 含空格与非 ASCII 字符的文件名不得被拆坏

- **WHEN** 待暂存记录的文件名包含空格与中文字符
- **THEN** 该文件必须作为**一个**条目入库，不得出现被拆分为多个路径或漏暂存的情形

- **WHEN** 该目录下另有一个子目录，其中也放着 `.json`（旧形态的 shell glob 根本枚举不到它们）
- **THEN** 子目录里的文件不得进入候选、不得被暂存；候选集合必须与旧形态逐项一致。
  这条存在的事实依据：git 裸 pathspec 的 `*` 走 wildmatch 且未置 `FNM_PATHNAME`，**跨 `/`**，
  而 POSIX pathname expansion 的 `*` 不跨 `/`。因此 pathspec MUST 带 `:(glob)` 路径魔法，
  否则「逐字同域」只对扁平目录成立，候选集会静默变成旧集合的超集

### Requirement: 批量暂存 MUST 经 stdin 与 NUL 分隔传递，不受命令行长度约束

一次性暂存大量记录时，路径清单 MUST 通过标准输入以 NUL 分隔传入（`--pathspec-from-file=-` 与 `--pathspec-file-nul`），MUST NOT 依赖把全部路径塞进单条命令行参数，因为 Windows 进程创建接口对命令行长度存在约 32k 字符上限，而记录数会持续增长。

#### Scenario: 大量路径一次完成且不溢出

- **WHEN** 待暂存记录数量足以使 argv 形态逼近命令行上限
- **THEN** 暂存必须一次成功，且不得因参数长度问题产生「记录越多越易失败」的退化形态

### Requirement: 批量暂存失败 MUST 回退逐条处理并出声

批量 `git add` 失败时，钩子 MUST 退回逐条暂存以保持既有「单条失败不阻断提交」的语义，并 MUST 在输出中明确告知已发生回退；MUST NOT 静默吞掉批量失败，也 MUST NOT 因批量失败而让整次提交失去全部判定记录。

#### Scenario: 注入批量失败后仍完成暂存且留有声音

- **WHEN** 用注入手段使批量暂存这一步必然失败
- **THEN** 记录仍须逐条入库、提交不得被阻断，且钩子输出必须包含指明「已回退到逐条」的告警文本

#### Scenario: 回退路径的成本必须由「本次真要暂存的条数」驱动

- **WHEN** 树上存在大量已跟踪且无改动的记录（旧形态正是被这一类拖成线性成本），同时批量暂存被注入为必然失败
- **THEN** 逐条 add 的次数必须等于本次新增/改动记录的条数，与树上记录数无关；两档对照（同树、新增 1 条与 2 条）
  必须各自打印现场读数，使「计数为 1」与「探针恒 0」可区分

### Requirement: 候选集扫描失败 MUST 被点名，且 MUST NOT 被当作「无记录需要暂存」

两次候选集扫描（未跟踪、已改动）任一失败时，钩子 MUST 输出指明哪一侧失败的告警，MUST NOT 发起
批量暂存中**失败那一侧**的清单（半截清单会造成静默漏暂存），健康侧照常暂存；提交 MUST NOT 被阻断。扫描的标准错误输出 MUST NOT 被整体丢弃，
否则「index 损坏」会伪装成「没有记录」，使判定记录无声滞留未跟踪区——那正是自动暂存要消除的形态。

#### Scenario: 扫描被注入失败后仍然出声

- **WHEN** 用注入手段使未跟踪扫描必然失败
- **THEN** 钩子输出必须包含指明扫描失败的告警文本，且不得出现任何批量暂存调用，提交本身不被阻断

#### Scenario: 放弃条数必须标为下界而非损失量

- **WHEN** 某一侧扫描被注入失败，且该侧的临时清单文件因重定向已被截断为空
- **THEN** 告警必须说明**该侧清单不可信**，并把读到的条数明确标注为**下界**（不代表损失量）；
  MUST NOT 以 `count=0` 这种确定值形态出现——扫描失败时真实损失不可知，
  把「一条也没读到」印成「一条也没丢」会把排障者引向相反结论

#### Scenario: 该修复必须有专属回归锁（否则修复本身裸奔）

- **WHEN** 把「丢弃扫描错误输出且忽略退出码」的写法重新引入钩子
- **THEN** 必须至少有一条专属判据变红；若成本类判据与存活判据对它全部无反应，则该专属判据不得省略

### Requirement: 批量暂存对 git 版本的能力依赖 MUST 在退化时自证现场

批量暂存依赖的 pathspec-from-file 能力存在最低 git 版本要求；在不具备该能力的机器上，实现 MUST
退回逐条暂存并 MUST 在告警中带出**可归因的现场信息**（至少含 git 版本），使「O(N) 形态原地复活」
不是一句无法核对的推测。回归锁 MUST 断言批量路径在受测环境里真的被走到，以防退化被静默吸收。

#### Scenario: 受测环境必须走批量路径

- **WHEN** 规模锁在 CI/本机执行钩子
- **THEN** 计数证据中必须出现批量暂存那一次调用；缺失即判不合规（说明已静默退化成逐条）

### Requirement: 该形态 MUST 在 CI 常驻可判定，且承载判据的新文件 MUST 能被 git 跟踪

仓库 MUST 提供一个只使用 node 内置模块的结构判据，解析钩子正文并断言「按 glob 逐文件 fork git」的形态不再出现；该判据 MUST 接在 `quality-gate.yml` 中**不被 docs-only 短路**的作业上并以 fail-fast 方式执行。同时，判据文件与其测试 MUST 经 `git check-ignore` 当场证明未被 `.gitignore` 静默排除。

#### Scenario: 回退成逐文件循环时 CI 变红

- **WHEN** 钩子里重新出现对判定记录逐文件调用 git 的写法
- **THEN** 该结构判据必须以非零退出并点名命中的形态，使 PR 无法合入

#### Scenario: 判据文件被忽略时接线判据变红

- **WHEN** 承载判据的新脚本落在 `.gitignore` 的忽略规则之内（例如 `scripts/*.js`）
- **THEN** 必须当场判定为未接线并变红，不得让「写了但永远不会被 CI 执行」以绿色通过

#### Scenario: 预算棘轮的作用域必须只覆盖暂存段

- **WHEN** 钩子的无关段落（例如版本同步）新增一条与记录暂存无关的 `git add`
- **THEN** 预算判据不得因此变红——它测的是暂存段每提交付多少次调用，与无关段落耦合会让预算恒等于「现状 + 0 余量」，
  下一次正常改动即撞出与判据语义无关的假红，而假红的真实代价是维护者抬高预算、棘轮自弱
- **AND** 同一段落内新增 `git add` 时**必须**变红（否则"作用域"等于"关掉检查"）；全文计数仍须作为 metrics 出声
- **AND** 当段落的起止锚点解析不出来（缺失、重复、或终点早于起点）时，判据 MUST NOT 判通过，
  MUST 记为自身故障并与"发现违规"分档退出——区间切片一旦静默放大，守卫会继续绿却不再测量它声称的那一段

### Requirement: 机器级进程创建成本 MUST 与本仓库侧改动分开归因

本能力 MUST NOT 声称修复「单次进程创建约一秒」这一机器级前提；仓库侧改动只解除「提交耗时随记录数增长」这一耦合。该前提的取证、排除项建议与自证方法 MUST 以文档形式随同交付，且 MUST 明确其为未闭合项。

#### Scenario: 交付物中如实标注未闭合范围

- **WHEN** 本能力落地完成
- **THEN** 记录文档必须写明进程创建成本属机器级、不在本 PR 修复范围，并给出可复跑的测量判据，避免下一次变慢时被误归因为「又是钩子」
