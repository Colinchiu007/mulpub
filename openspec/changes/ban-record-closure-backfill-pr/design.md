# 设计（ban-record-closure-backfill-pr）

## D1 机械化而不是再写一遍文档

禁令在 `AGENTS.md` 里已经存在且措辞明确，实测 4 小时内被 4 笔 PR 违反（proposal 的表）。这不是措辞问题：**执行这些会话的分支在禁令落地前就切出去了**，它们读到的 `AGENTS.md` 是旧口径。任何"把话说得更清楚"的方案对这一类违犯都零作用——违犯者根本没看到那句话。

所以本 change 只做一件事：让判据看见**这次改动本身**。判据不看文档版本、不看会话记不记得，它看 diff。

**判据必须能执行它自己要求的那次迁移**（继承仓规「前提锁必须能执行自己要求的迁移」）：把那一行改成「由门禁推导」必须绿，否则锁会把新机制的唯一正确动作也拦下来，结局是逼人清空登记表或 `--no-verify`。

## D2 判据形态：行级状态词跃迁，不是"整个 PR 只动那一行"

- ❌ 窄判据（变更集 ⊆ {记录文件} 且 diff 行 ⊆ {那一行 + sync_*}）：**实测漏 2/4**。#3890/#3891 顺带加了 `### main push 回读` 小节与 QM 行状态，窄判据放过它们。
- ✅ 采用：**同一记录文件的本次 diff 中，存在一行 `| 远程同步 |` 被删除时状态列未闭合、且存在一行 `| 远程同步 |` 被新增时状态列为闭合词** ⇒ 判红。

配对不要求行号对齐（同一文件里那一行的位置会随上下文移动），只要求**同一文件内**两侧同时成立。

闭合词表与状态列取法 **MUST 复用既有单一实现**：`ROW_RE`、`CLOSED_RE`、`normalize`、`split('|')[2]` 这套口径已在 `check-gate-record-debt.js` 内存在（Gate 2c 判存量用的就是它）。新增判据 MUST NOT 另写第二份词表——两份必然漂移，而漂移表现为这条新锁放过某个新词或误伤某个旧词。

### D2b 五条必要加固（跨家族对抗评审 F1–F5 命中，每条独立核实后并入）

**F1 · Critical，且推翻了我原来的立论前提。** 上一段原本写的是「一篇记录里 `远程同步` 行只应有一行，重复行已被既有判据拦」——核实结果：`readRecord` 用 `findIndex` 取**第一行**（`check-gate-record-debt.js:213`），而"同一条记录被写两遍"那条判据统计的是 `.quality-gates.md` 的 `## ` 标题（`headingCounts`，:341-342），**与记录文件里的表格行无关**。于是"追加第二行 `| 远程同步 | PASS | <sha> |`、原 PENDING 行不动"这条绕法：删除侧无未闭合行 ⇒ 本判据不红；首行仍 PENDING 而账本可推 ⇒ 落 `derivedClosed`；`hasBlocking` 各项全空 ⇒ **rc=0 完全静默**。它比被抓的 4 笔真实回填**改动更少**，是旧 SOP 会话最自然的退化形态。
⇒ 必须补一条独立判据：**单篇记录文件内 `ROW_RE` 命中行数 > 1 ⇒ 判红**，进 `hasBlocking`。这条不只是为本锁补洞——"一篇记录两行收口状态、彼此可以相反"本身今天是无人看守的歧义面。

**F3 · 我自己词表里埋的缝。** 实测：`已由门禁推导` 对 `CLOSED_RE=/^(PASS|N\/A|✅|已)/` 为 **true**，对 `DERIVED_MARKER_RE=/^\s*由门禁推导/` 为 **false** ⇒ 迁移成「已由门禁推导」（很自然的中文措辞）会判红，**红在机制唯一正确的动作上**。⇒ `DERIVED_MARKER_RE` 放宽为允许可选前缀 `已`，在**同一份实现**里改（不得另立词表），正反夹具各一条。

**F2 · 同文件内容盲配对。** `--unified=0` 挡不住它：代码围栏里的 `| 远程同步 | PASS | 示例 |` 不是上下文行，是独立的 `+` 行。本仓记录天然会引用这种行（本 change 自己的记录就是候选），而判据文件头注释已记过一次同款自指误报。⇒ diff 解析 MUST **按旧侧/新侧各自跟踪 ``` 围栏状态**，围栏内的 `+`/`-` 行不参与配对。

**F4 · 跨文件拆散。** 改名或"整删 + 新增"会把删除侧与新增侧拆到两个路径 ⇒ 不红。核实历史：main 上 `openspec/records/` 的删除共 10 笔，**全部在 `_exempt/`**（文档化的消费后清理路径），真实记录一篇没被删过 ⇒ 判据可安全收窄为：**非 `_` 前缀的记录文件在本次 diff 中被删除 ⇒ 判红**；`_exempt/` 与 `_` 前缀不受影响。取 diff MUST `--no-renames`（与 `merge-ledger` 同口径——开 rename 检测会把删除伪装成 rename 而绕开这条）。

**F5 · 第二形态的对称缺口。** docs-only 记录要求表格行与 `- 保留门禁：… | 远程同步 <状态>` bullet 同写，而**只改 bullet 不碰表格行**的回填对本判据完全无感；唯一能看见 bullet 的 `statusMismatchVisible` 是明示**不拦截**的可见面，且它"实测 0 篇"的论据已被新机制推翻（现在「表格行未闭合而 bullet 宣称完成」正是活矛盾）。⇒ bullet 侧用**既有** `CLOSED_DECL_RE`/`UNCLOSED_DECL_RE` 做同一套跃迁配对，MUST NOT 新增第三份词表。

**F6/F8 记为边界，不改判据**：净 diff 令「闭合→未闭合→闭合」三段坍缩成"闭合→闭合"，本锁不拦（派生模型下手写闭合词无判定力；唯一例外是账本不可用的回退档仍读状态列 ⇒ 如实写进残留风险，不假称已闭合）。另外 rebase 把他人行吸收进本分支时，红文案 MUST 给出自证路径（`git log -p -- <file>`），不得默认"你就是回填"。


## D3 扫描域只含新载体，旧载体通道保持可走

判定域 = `listRecordFiles(recordsRoot)` 的结果 ∩ 本次 diff 的文件集。**不含** `.quality-gates.md`、不含 `scripts/gate-record-debt-ledger.json`。

为什么必须这样切：AGENTS「旧载体冻结」明写「仍**允许**就地改写旧载体里已有记录块的状态行——ledger 里还挂着历史欠账（现读数以键数为准，本轮实测 23 条），它们只存在于旧载体，关闭只能靠这条通道；把这条路封掉等于把旧账永远钉红」。所以：

- 只改旧载体 ⇒ 绿（合法销账）
- 改新载体的那一行到闭合词 ⇒ 红
- 两者同时改（同一 PR 既关旧行又新写记录）⇒ 红，但文案必须**点名是哪一篇新记录**，让作者能把旧载体那部分单独拆出来走。这是有意的不对称：新载体已经不需要人工收口，而旧载体需要，混在一个 PR 里会让"哪部分合法"无法判定。

## D4 迁移豁免：`由门禁推导` 与"保持不动"都不红

`DERIVED_MARKER_RE` 已在上一轮落地。新判据对新增行的判定是 `闭合词 ∧ 非派生标记`：

- 新增行 = `由门禁推导` ⇒ 不红（鼓励方向）
- 新增行 = `PENDING`（在飞 PR 的正常态）⇒ 不红（未闭合）
- 新增行 = `PASS` / `N/A` / `✅` / `已…` 且被删行未闭合 ⇒ **红**

反向跃迁（闭合 → 未闭合）不判：它不是"预写证据"，而且在派生模型下无害（收口由推导给出，手写状态词不再具有判定力）。把它判红只会把"我在清理旧文案"这类动作误伤，扩大拦截面而买不到东西。

## D5 落点：现有阻塞门禁，不动 workflow

`check-gate-record-debt.js` 在 `quality-gate.yml` 的 `changes` job 里已经是阻塞步骤（`node scripts/check-gate-record-debt.js --carrier-mode="$CARRIER_MODE"`，位置在非 PR 早退**之前**）。新红走同一条出口：`format` 打印 + `hasBlocking` 返回真。

因此本 change **不改 `.github/workflows/`**，也就不触发「改 workflow 的 pwsh run 正文必须喂真解释器」那条约束；同时 `check-unwired-tests.js` 的登记表不动（测试文件早已点名）。

**但必须实测两档**：PR 档与 main push 档都要跑，且两档的判定域都必须正确。原因是这一格上有过事故——`carrier-mode` 那条锁在 PR 档被改成 visible，动因是「pull_request 检出的是 main⊕本分支的合并预览，主干每几分钟长一块，PR 档'等于基线'必红」。本判据看的是 `base...head` 的**差量**，别人合入不进入我的 diff，因此结构上不受该问题影响；**"结构上不受"必须由用例证明**，不得由推理放行：

- 用例 A（PR 档形态）：临时仓库里 base 有记录（未闭合），head 改成闭合 ⇒ 红。
- 用例 B（并发合入污染）：在 base 之后**另加一次合入把第三篇记录改成闭合词**，再跑本 PR 的判定 ⇒ 那一篇 MUST NOT 进红集。这条是"差量口径"的实质证明，少了它，锁就退化成"谁历史上写过 PASS 谁红"。

## D6 取源：一条 diff，一个 base

新增旗标 `--head-ref`（默认 `HEAD`）。取源用 `git diff --unified=0 <baseRef>...<headRef> -- <记录文件>`，三点式 = merge-base 语义，与本仓其他 PR 级判据一致（`classify-docs-only.js` 的 `changedFileStatuses` 内部就是这套）。

**本条原有的一处主张已被对照实验否证，这里按实验改写**（原文写的是"两点式会把别人在 base 之后合入的改写算进本 PR 的红集"）：临时仓库实测（init → 分支只改 `mine.md` PENDING→PASS → 主干再改 `theirs.md` PENDING→PASS，然后比 `git diff base head` 与 `git diff base...head`）——

```
--unified=0  两点式红集=["mine.md:PENDING->PASS"]  三点式红集=["mine.md:PENDING->PASS"]
--unified=0  两点式文件集=2                        三点式文件集=1
<默认上下文> 与上面两行逐字相同
```

⇒ **红集不可分辨，可分辨的是扫描域**：两点式把别人改过的那篇也拉进"本 PR 触碰的文件集"。这仍然必须用三点式，但理由换成了实测的那条：**域正确性**（D8 的"存量不得凭历史写法红"、以及任何后续在域上做的判断都建立在"域=本 PR 触碰集"之上），不是"少一条红"。

推论有两条纪律价值：① 用例 MUST 断言**文件集**，不是断言红集——断言红集的话，两点式与三点式同绿，那条锁就是装饰；② `--unified=0` **同样测不出差异**，所以本 change 不为它设变异反证，只把它作为"取最小出口"的工程选择保留。**给不出可分辨反例的形态主张，就不许写成锁**——否则又是"既精确又无用"的装饰性门禁，而且这次是写在我自己的设计里。

- 记录文件清单**必须**来自 `listRecordFiles`，MUST NOT 由 diff 自己枚举目录（`git diff` 只给改过的文件，用它当扫描域会把"没改但写得不对"的篇目漏掉——不过本判据只看改动，所以这里的方向是：diff 文件集 ∩ `listRecordFiles`，两个来源都要在场，交集才是域）。

## D7 回读证据的替代落点（否则锁会被正当绕过）

AGENTS 收尾清单第 6 条要求「回读这次合并触发的 main push，再宣布收工」并留下读数。merge SHA 只在合并后存在 ⇒ 与旧回填同源的第二个循环依赖。

本轮实测到的唯一可行出口：**写在 PR 评论里**。#3892 合并后我按此把三条产物与 `NO_RUN(by design)` 判读写在 PR 上（`gh pr comment`），零额外 PR、零仓库文件改动、判据也碰不到它。

所以本 change 同时改口径：
- `AGENTS.md` 第 6 条补一句"读数落 PR 评论，不落仓库文件；main 真红才开 follow-up PR"。
- `_TEMPLATE.md` 那一行旁注补"改写为闭合词会被 Gate 2c 判红；回读证据写 PR 评论"。

**为什么这是机制闭合而不是甩锅**：判据只拦"那一行的状态词跃迁"，加小节不拦——如果反过来把"任何合并后补写记录"都拦掉，就等于给第 6 条制造一个没有出口的硬要求，那个要求的唯一出路是绕开锁。**一条逼使用者绕行的判据比没有判据更糟**，因为它同时失去合规性与可信度。

## D8 存量零改

只作用于本次 diff。main 上现存的 36 篇手写 `PASS` 原样保留，不批量迁移、不改写。

- 为什么不批量迁：那需要一个 PR 改 36 个文件，而这个 PR 本身的形态就是"为改写那一行开 PR"——**本 change 的落地不能违反本 change 立的规则**。这类迁移只能随各会话下次自然改动该记录时顺路收敛。
- 因此必须有一条**真仓下界断言**记录现状（当前读数：80 PR 样本中 36 篇命中），并且这个数只能缩小。它同时是"这条锁确实有东西可拦"的现场证据，也是将来判断迁移是否真的在发生的唯一坐标。

## D9 fail-closed：取不到读数一律按"未证实"，不得读成"没有回填"

三类取不到读数：`baseRef`/`headRef` 不可解析、`git diff` 失败、diff 输出为空但文件集非空（前两个是浅检出的典型形态）。处置：

- 本机档：打印 `HAND-CLOSURE-UNPROVEN (reason=<…>)`，不判红（继承上一轮"本机浅克隆/无 origin/main 是合法使用形态"的口径）。
- CI 档：与 `MERGE-LEDGER prs=0` 同档处理 ⇒ **非零退出并点名"这条锁这一趟没测到"**。判据停用不是通过。
- 断言两侧各一条独立用例，且必须**分别指名**——把"不可用"做成"跳过检查"时，只有分开的断言能指出哪一半先烂（继承上一轮 LEDGER-1 的口径）。

## D10 git 取源不得落在判据文件内 —— 基线规格早就禁过这件事

`openspec/specs/quality-gate-execution-record/spec.md` 第一条 Requirement 原文：**「判据 SHALL 从该实现取值，MUST NOT 在判据内另写 git 解析，也 MUST NOT 自行枚举记录目录」**，且该禁令已由两条在跑的锁钉住（判据源码禁 `execFileSync('git'`、禁第二份 `git log`）。本判据要跑 `git diff` —— 若把它写进 `check-gate-record-debt.js`，**我就是当着两条锁的面改代码**。

正解只有一条：diff 取源放进独立的 git 取源模块 `scripts/lib/pr-record-diff.js`，判据只消费其返回结构。

- **不得**为了少建一个文件去放宽那两条锁——那两条锁是上一轮 M8/N8 系列实测换来的，放宽等于拆门。
- 也**不得**图省事塞进 `merge-ledger.js`：那个模块的名字与它唯一的职责（合并账本/归属）是绑定的，塞进 diff 解析会让"一份实现"变成"一个杂物间"，下一个人无从判断该往哪加。新模块自带一条同源锁：**diff 取源全仓只允许这一处**（判据与 merge-ledger 都不得各写一份）。
- 三点式、`--no-renames`、`-c core.quotepath=off` 三条口径与新模块的一致性由该模块自己的测试钉住；`--unified=0` 按 D6 的实测结论**不设反证**（工程选择，不是契约）。

**动因记录**：这一条不是我自己在设计时想到的，是 opencode 那一轴在**未交付最终 findings** 的中途输出里提出的题头（"git diff vs MUST NOT 另写 git 解析"）。核实后成立。⇒ 一次"零交付"的评审仍可能含唯一有价值的命中；处置口径只能是**逐条按内容判**，不是"这轴没交付结论就整轴作废"。

## D11 CI 侧 ref 可得性不需要新任务

`quality-gate.yml` 的 checkout 已是 `fetch-depth: 0`（注释原文：merge-base diff 需要完整历史），且 `check-gate-record-debt.js` 已在同一 `run:` 块内。⇒ 三点式所需的 base 在 CI 与本机同形可得，**不新增接线任务、不新增 workflow 步骤**。这一格由核实而非假设确定（同上一轮"取源可得不必新增任务"的教训：先查现况再决定加不加东西）。

## D12 重复行档的判据形态：判"本 PR 造成的重复"，不判"存在重复"

F1 的修法第一版写成"同一记录文件内 `ROW_RE` 行数 > 1 ⇒ 判红"。**这条被存量实测否证**：`openspec/records/` 现有 447 篇，其中 **10 篇本来就有两行**（`mime-stock-freeze` 两行都 PENDING、`docs-prd-p2` 两行都 PASS 且证据文本略异、`batch-b-debounce-watch` 两行都 PASS）。无条件判红的后果是一篇记录被任何无关原因改动时，作者会被一个他**没造成**的重复钉住 ⇒ 要么误红、要么被迫加一张只减不增的豁免清单，而清单本身就是本仓反复记录过的"逼人绕过去"的形状。

改为**归因判据**：`本次 diff 在该文件内新增了 ≥1 行 ROW_RE` **且** `该文件结果内容里 ROW_RE 行数 > 1` ⇒ 判红。

- 它精确覆盖 F1 描述的绕道（追加第二行 PASS、首行不动）——那条绕道**必然**新增一行。
- 它对 10 篇存量恒不触发（它们的两行都在 base 里就存在，本 PR 没新增行）。
- 它不需要豁免清单，因此没有"清单只能缩小但没人能缩小它"的死账。
- 存量那 10 篇仍会被任何人**顺路**清理：一旦谁去动它们并新增行才会红，正常改别的行不受影响。⇒ 这条锁不制造义务，只禁止"让情况变坏"。

口径附带一条：`readRecord` 现在用 `findIndex` 只看第一行（F1 的根因之一）。本 change 让它额外回报 `rowCount`，**但收口判定仍按第一行**——改判定方向属行为变更，会把 10 篇存量的既有语义一起掀动，不在本 change 范围。这条区分必须写下来，否则下一个会话会以为"既然数了行数，判定也该用"。

## F7：误报主张必须按**形态**证，不是按标题证

proposal 第一版写「36/36 命中都是回填标题 ⇒ 0 误报」。**这条方法学被驳回，而且驳得对**：本 change 的整个立论就是"自述口径（文档、SOP、标题）会失灵"，用标题当真值给自己作证 = 用被质疑的信源验证自己。标题相关只证明"自述为回填的都被抓到"，不证明"非回填形态的 PR 不会被误伤"——F2/F3 这类形态在 80 样本里可能压根没出现过，样本对它们是**零信息**。

## D13 实做纠正：空差量不是"取不到读数"（spec 初稿写错，已改）

spec 初稿把"diff 为空但文件集非空"列进未证实三形态之一。实测 `--base-ref=HEAD --head-ref=HEAD`——那是 main push 的常态，也是任何不碰记录文件的 PR 的常态——当场 rc=0 且差量确实为空。**照那句话实现，CI 会在每一个代码 PR 与每一次 main push 上退 2**，唯一出路是逼人给判据加 skip 开关，而 skip 开关就是这条锁的坟场。

纠正后的口径：git **成功取回**的空集算"测到了"；三档读数在打印面上分开——`触碰记录=0`（没碰记录）/ `触碰记录=N`（碰了 N 篇且逐篇判过）/ `触碰记录=n/a`（没测到）。这条不是锦上添花：M2 那种断线发生后，打印面恰好只剩 `prs=n/a`，如果空差量也打 `n/a`，"接线坏了"与"这个 PR 没碰记录"就完全同形，缺陷会伪装成常态。

锁两处：`classify 的 touched 按「域 ∩ 差量」计`（模板与 `_exempt/` 不进计数，因为域本来就是 `listRecordFiles` ∩ diff）、`打印面：空差量是常态而非门禁故障…`（三档各一条断言，含"取不到不得打数字"）。变异 M14（摘掉 `touched++`）与 M15（未证实档改打数字）各自指名红。

## 残留风险（不假装已闭合）

1. **拦不住"合并前就把状态列预写成闭合词"之外的绕行**：例如新增一行 `| 远程同步 | 由门禁推导 |` 同时另起一行手写 PASS——那会撞上既有的"同一条记录被写两遍"判据，但两条锁的组合是否覆盖全部排列，只有 M 系列跑完才知道；跑不出来的组合如实记为未证实。
2. **旧载体那 23 条欠账本 change 不动**，它们仍需要"就地改写 + 同次销账"这条人工通道；那条通道在形态上就是一次回填，只是落在旧载体。彻底清掉它需要另一件事（批量销账或让派生通道也读旧载体），不在本 change 范围。
3. **`_TEMPLATE.md` 里"存量 21 篇"这类活数会继续漂**（本轮实测同族档位已到 23）。本 change 只加下界断言不写死总数，注释里的孤立读数仍会过时——这是文档层的固有代价，不靠加判据解决。
4. **本 change 自己的 PR 不能是"为改写那一行开的 PR"**：它改的是判据不是记录行。落 PR 时如果顺手动任何记录的收口行，就会被自己的新锁判红——那是**预期的自指验证**，届时必须如实记录它红了什么、怎么绕过去的（正解是不动那一行），不得反过来放宽判据。
5. **闭合→闭合的改写不拦**（跨家族评审 F6，实测确认而非推测）。净 diff 只看两端：`PASS → PASS（换了 SHA、改了散文）` 两侧都是闭合词，跃迁档无感；三段式（闭合→未闭合→闭合）在单 PR 内坍缩成"没变"。真实暴露面是**存量 36 篇手写 PASS 行的证据文字**（merge SHA、时间、散文）可被任意 PR 无锁改写。派生模型下这基本无害——收口判定不看那一列——但有一个精确边界：`format()` 在账本不可用那档明写「收口只认状态列的闭合词表（fail-closed）」，即**回退档里手写闭合词仍有判定力**。本机档不拦、CI 档撞上一条 rc=2，所以降为残留风险而非缺陷。要收它得加"diff 触碰已闭合行即红"，而那条会把**修正一个写错的 merge SHA** 也判红——那是没有正解的硬要求，本仓纪律是不造这种锁（见 D7）。
6. **rebase 把他人行吸收进本分支** 时判据会红并点名那篇别人的记录（评审 F8）。verdict 可辩护（这个 PR 确实把该变更带进了主干），且与 D6 里"两点式污染"是不同形态：那是不该看的人，这是**确实由我带入**的人。处置走文案而不改判据：红块要求先 `git log -p -- openspec/records/<篇名>` 核归属，"不是你改的就别默认自己是回填，但也别放宽判据"。
