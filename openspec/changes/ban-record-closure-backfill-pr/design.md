# 设计（ban-record-closure-backfill-pr）

## D1 机械化而不是再写一遍文档

禁令在 `AGENTS.md` 里已经存在且措辞明确，实测 4 小时内被 4 笔 PR 违反（proposal 的表）。这不是措辞问题：**执行这些会话的分支在禁令落地前就切出去了**，它们读到的 `AGENTS.md` 是旧口径。任何"把话说得更清楚"的方案对这一类违犯都零作用——违犯者根本没看到那句话。

所以本 change 只做一件事：让判据看见**这次改动本身**。判据不看文档版本、不看会话记不记得，它看 diff。

**判据必须能执行它自己要求的那次迁移**（继承仓规「前提锁必须能执行自己要求的迁移」）：把那一行改成「由门禁推导」必须绿，否则锁会把新机制的唯一正确动作也拦下来，结局是逼人清空登记表或 `--no-verify`。

## D2 判据形态：行级状态词跃迁，不是"整个 PR 只动那一行"

- ❌ 窄判据（变更集 ⊆ {记录文件} 且 diff 行 ⊆ {那一行 + sync_*}）：**实测漏 2/4**。#3890/#3891 顺带加了 `### main push 回读` 小节与 QM 行状态，窄判据放过它们。
- ✅ 采用：**同一记录文件的本次 diff 中，存在一行 `| 远程同步 |` 被删除时状态列未闭合、且存在一行 `| 远程同步 |` 被新增时状态列为闭合词** ⇒ 判红。

配对不要求行号对齐（同一文件里那一行的位置会随上下文移动），只要求**同一文件内**两侧同时成立。理由：一篇记录里 `远程同步` 行只应有一行（重复行已被既有判据 `同一条记录被写两遍必须判红` 拦），所以"同文件内一删一增"就是那一行的改写，不需要更复杂的行位匹配。

闭合词表与状态列取法 **MUST 复用既有单一实现**：`ROW_RE`、`CLOSED_RE`、`normalize`、`split('|')[2]` 这套口径已在 `check-gate-record-debt.js` 内存在（Gate 2c 判存量用的就是它）。新增判据 MUST NOT 另写第二份词表——两份必然漂移，而漂移表现为这条新锁放过某个新词或误伤某个旧词。

## D3 扫描域只含新载体，旧载体通道保持可走

判定域 = `listRecordFiles(recordsRoot)` 的结果 ∩ 本次 diff 的文件集。**不含** `.quality-gates.md`、不含 `scripts/gate-record-debt-ledger.json`。

为什么必须这样切：AGENTS「旧载体冻结」明写「仍**允许**就地改写旧载体里已有记录块的状态行——ledger 里还挂着历史欠账（现读数以键数为准，本轮实测 23 条），它们只存在于旧载体，关闭只能靠这条通道；把这条路封掉等于把旧账永远钉红」。所以：

- 只改旧载体 ⇒ 绿（合法销账）
- 改新载体的那一行到闭合词 ⇒ 红
- 两者同时改（同一 PR 既关旧行又新写记录）⇒ 红，但文案必须**点名是哪一篇新记录**，让作者能把旧载体那部分单独拆出来走。这是有意的不对称：新载体已经不需要人工收口，而旧载体需要，混在一个 PR 里会让"哪部分合法"无法判定。

## D4 迁移豁免：`由门禁推导` 与"保持不动"都不红

`DERIVED_MARKER_RE` 已在上一轮落地。新判据对新增行的判定是 `闭合词 ∧ 非派生标记`：

- 新增行 = `由门禁推导` ⇒ 不红（鼓励方向）
- 新增行 = `PENDING`（在飞 PR 的正常态）⇒ 不红（未闭合）
- 新增行 = `PASS` / `N/A` / `✅` / `已…` 且被删行未闭合 ⇒ **红**

反向跃迁（闭合 → 未闭合）不判：它不是"预写证据"，而且在派生模型下无害（收口由推导给出，手写状态词不再具有判定力）。把它判红只会把"我在清理旧文案"这类动作误伤，扩大拦截面而买不到东西。

## D5 落点：现有阻塞门禁，不动 workflow

`check-gate-record-debt.js` 在 `quality-gate.yml` 的 `changes` job 里已经是阻塞步骤（`node scripts/check-gate-record-debt.js --carrier-mode="$CARRIER_MODE"`，位置在非 PR 早退**之前**）。新红走同一条出口：`format` 打印 + `hasBlocking` 返回真。

因此本 change **不改 `.github/workflows/`**，也就不触发「改 workflow 的 pwsh run 正文必须喂真解释器」那条约束；同时 `check-unwired-tests.js` 的登记表不动（测试文件早已点名）。

**但必须实测两档**：PR 档与 main push 档都要跑，且两档的判定域都必须正确。原因是这一格上有过事故——`carrier-mode` 那条锁在 PR 档被改成 visible，动因是「pull_request 检出的是 main⊕本分支的合并预览，主干每几分钟长一块，PR 档'等于基线'必红」。本判据看的是 `base...head` 的**差量**，别人合入不进入我的 diff，因此结构上不受该问题影响；**"结构上不受"必须由用例证明**，不得由推理放行：

- 用例 A（PR 档形态）：临时仓库里 base 有记录（未闭合），head 改成闭合 ⇒ 红。
- 用例 B（并发合入污染）：在 base 之后**另加一次合入把第三篇记录改成闭合词**，再跑本 PR 的判定 ⇒ 那一篇 MUST NOT 进红集。这条是"差量口径"的实质证明，少了它，锁就退化成"谁历史上写过 PASS 谁红"。

## D6 取源：一条 diff，一个 base

新增旗标 `--head-ref`（默认 `HEAD`）。取源用 `git diff --unified=0 <baseRef>...<headRef> -- <记录文件>`，三点式 = merge-base 语义，与本仓其他 PR 级判据一致（`classify-docs-only.js` 的 `changedFileStatuses` 内部就是这套）。

- 记录文件清单**必须**来自 `listRecordFiles`，MUST NOT 由 diff 自己枚举目录（`git diff` 只给改过的文件，用它当扫描域会把"没改但写得不对"的篇目漏掉——不过本判据只看改动，所以这里的方向是：diff 文件集 ∩ `listRecordFiles`，两个来源都要在场，交集才是域）。
- `--unified=0` 是硬要求：默认上下文会把**未改动**的邻行也带进 `+`/`-` 之外的行，而带上下文的块一旦换行位就可能把上一篇记录的闭合行读进本文件的块里。取最小出口。

## D7 回读证据的替代落点（否则锁会被正当绕过）

AGENTS 收尾清单第 6 条要求「回读这次合并触发的 main push，再宣布收工」并留下读数。merge SHA 只在合并后存在 ⇒ 与旧回填同源的第二个循环依赖。

本轮实测到的唯一可行出口：**写在 PR 评论里**。#3892 合并后我按此把三条产物与 `NO_RUN(by design)` 判读写在 PR 上（`gh pr comment`），零额外 PR、零仓库文件改动、判据也碰不到它。

所以本 change 同时改口径：
- `AGENTS.md` 第 6 条补一句"读数落 PR 评论，不落仓库文件；main 真红才开 follow-up PR"。
- `_TEMPLATE.md` 那一行旁注补"改写为闭合词会被 Gate 2c 判红；回读证据写 PR 评论"。

**为什么这是机制闭合而不是甩锅**：判据只拦"那一行的状态词跃迁"，加小节不拦——如果反过来把"任何合并后补写记录"都拦掉，就等于给第 6 条制造一个没有出口的硬要求，那个要求的唯一出路是绕开锁。**一条逼使用者绕行的判据比没有判据更糟**，因为它同时失去合规性与可信度。

## D8 存量零改

只作用于本次 diff。main 上现存的 36 篇手写 `PASS` 原样保留，不批量迁移、不改写。

- 为什么不批量迁：那需要一个 PR 改 36 个文件，而这个 PR 本身的形态就是"为改写那一行开 PR"——**本 change 的落地不能违反本 change 立的规则**。这类迁移只能随各会话下次自然改动该记录时顺路收敛。
- 因此必须有一条**真仓下界断言**记录现状（当前读数：80 PR 样本中 36 篇命中），并且这个数只能缩小。它同时是"这条锁确实有东西可拦"的现场证据，也是将来判断迁移是否真的在发生的唯一坐标。

## D9 fail-closed：取不到读数一律按"未证实"，不得读成"没有回填"

三类取不到读数：`baseRef`/`headRef` 不可解析、`git diff` 失败、diff 输出为空但文件集非空（前两个是浅检出的典型形态）。处置：

- 本机档：打印 `HAND-CLOSURE-UNPROVEN (reason=<…>)`，不判红（继承上一轮"本机浅克隆/无 origin/main 是合法使用形态"的口径）。
- CI 档：与 `MERGE-LEDGER prs=0` 同档处理 ⇒ **非零退出并点名"这条锁这一趟没测到"**。判据停用不是通过。
- 断言两侧各一条独立用例，且必须**分别指名**——把"不可用"做成"跳过检查"时，只有分开的断言能指出哪一半先烂（继承上一轮 LEDGER-1 的口径）。

## 失败模式表

| 失败模式 | 现状 | 后果 | 处置 |
|---|---|---|---|
| 会话按旧 SOP 回填 | 实测 4 笔/禁令后 4h | 结构性成本回来了（每条交付两趟 PR） | 本判据判红 |
| 把那一行改成闭合词以"清理旧文案" | 未知，理论存在 | 误红 | 文案给出唯一正解（改「由门禁推导」或不动）；`delivered_by_pr` 不参与 |
| 判据只看 diff ⇒ 别人合入的记录被判到我头上 | 若用两点式 diff 会成立 | 每个 PR 都红 | D5 三点式 + 用例 B 实测钉住 |
| 旧载体销账 PR 被误伤 | 概率高（那类 PR 常同时新建记录） | 合法通道被堵 | D3 扫描域排除 + 文案点名具体篇目 |
| diff 取不到读数被读成"没有回填" | 浅检出必现 | 装饰性门禁 | D9 三档 + CI rc≠0 |
| 有人为了通过而 `--no-verify` / 改成可见项 | 仓规禁止 | 锁被拆 | 不在本 change 处置，属流程纪律；但红文案必须给出**不需要绕**的正解 |

## 反证计划（每条必须实测变红，且红集指名到用例）

- **M1** 摘掉新红（`handClosedRows` 不 push）⇒ 红在「未闭合→闭合必须红」那条。
- **M2** 把扫描域从"新载体 ∩ diff"换成"全部记录文件"⇒ 红在 D5 用例 B（并发合入污染）与 D8 下界断言之一。
- **M3** 去掉 `由门禁推导` 豁免 ⇒ 红在「迁移方向不红」那条。
- **M4** 把 `--unified=0` 改成默认上下文 ⇒ 红在配对用例（邻行被吸入造成误配）。
- **M5** 把三点式 `...` 改成两点式 `..` ⇒ 红在 D5 用例 B。**这条是本轮最贵的形态**，因为两点式在单仓库夹具里经常仍绿——夹具必须造出"base 之后又有别人的合入"那一格，否则探针通路无效。
- **M6** 把 D9 的"不可用 ⇒ 跳过"改成"不可用 ⇒ 判红"⇒ 红在「本机浅克隆不拦」那条；改成"不可用 ⇒ 绿"⇒ 红在 CI 档 rc 那条。两条各测一个方向。
- **M7** 让新红不进 `hasBlocking`（只打印不拦）⇒ 红在「打印且阻断」那条——继承上一轮"捕获而不阻断"的同型事故（Gate 7 长期 `|| views_exit=$?` 就是这一格）。
- **M8** 复用词表被拆成第二份（新判据自带一个 `/^(PASS|N\/A|✅|已)/`）⇒ 红在单一口径结构锁；这条锁的意义是让"两份必然漂移"在机械上不可发生。

## 残留风险（不假装已闭合）

1. **拦不住"合并前就把状态列预写成闭合词"之外的绕行**：例如新增一行 `| 远程同步 | 由门禁推导 |` 同时另起一行手写 PASS——那会撞上既有的"同一条记录被写两遍"判据，但两条锁的组合是否覆盖全部排列，只有 M 系列跑完才知道；跑不出来的组合如实记为未证实。
2. **旧载体那 23 条欠账本 change 不动**，它们仍需要"就地改写 + 同次销账"这条人工通道；那条通道在形态上就是一次回填，只是落在旧载体。彻底清掉它需要另一件事（批量销账或让派生通道也读旧载体），不在本 change 范围。
3. **`_TEMPLATE.md` 里"存量 21 篇"这类活数会继续漂**（本轮实测同族档位已到 23）。本 change 只加下界断言不写死总数，注释里的孤立读数仍会过时——这是文档层的固有代价，不靠加判据解决。
4. **本 change 自己的 PR 不能是"为改写那一行开的 PR"**：它改的是判据不是记录行。落 PR 时如果顺手动任何记录的收口行，就会被自己的新锁判红——那是**预期的自指验证**，届时必须如实记录它红了什么、怎么绕过去的（正解是不动那一行），不得反过来放宽判据。
