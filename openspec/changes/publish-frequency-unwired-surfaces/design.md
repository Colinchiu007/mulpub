# 设计：频率声明面的收编与删除

## 决策 1 —— `clearRollbackDisabled` 删掉，而不是把 UI 接上

**主张的来源**：它自己的 docblock 与 `_disableRollbackForPlatform` 的告警文案都写着
「重启**或用户在设置页确认后**解除」。设置页没有这个入口（全仓 `grep` 无 IPC handler、无 UI 组件、
唯一调用点是它自己的回归测试）。

**为什么不"补齐那条路"**：接线之后要给用户一个"我确认该平台接线正常"的按钮，
其语义是**由用户判断来推翻一个机械判据**（探针判定"已证实能成功发布的平台上出现了从未发起尝试的失败"
⇒ 说明打点管道有洞）。这个判断我们既无法验证也无从追责，而它换来的权力是"允许回滚一个仍在飞的窗口"
—— 恰好是 D1 花了两代去掉的那个风险。方向不对称：**不接**最坏是"多等一个窗口直到重启"；
**接了**最坏是重复发布。所以删接口 + 把文案改成只有"重启"这一条出路。

**反证形态的要求**（本条踩过一次才写对）：变异必须取"被禁形态本身"。
把 `clearRollbackDisabled` 加回来 ⇒ U5 红；把文案改回「重启或用户在设置页确认后解除」⇒ U6 红。
两条各测一个面（接口 / 承诺），缺一面就还剩一面在骗人。

## 决策 2 —— 日配额上界放策略模块，三条写入路径共用，渲染层只"接收"不"持有"

同一个量的合法域此前是：**env 无上界 / 设置页覆盖无上界 / UI `:max="999"` / 分钟那两处 `:max="10080"`**。
这不是"UI 保守一点"，是两套真值 —— 填不进 UI 的值能用 env 填进去，而 env 填错没人说界在哪。

选值 `MAX_DAILY_QUOTA = 5000`：v4 最大档（short 500）× 10 的余量。两条约束写进测试：
① 必须**严格大于**最大默认值 —— 写成"刚好等于"时，下一次上调默认值会撞上界并被**静默钳位**；
② 各路径保持自己原有的错误语义：env 越界**钳位并出声**（沿用 `MAX_INTERVAL_MS` 的先例），
设置页覆盖越界**整体丢弃**（那是它既有的 all-or-nothing 语义，改成钳位会把"半生效"放进来）。
**上界改了不许只改一处**：判据是"下发值 == 真源值"（U10 把下发值硬编码成 999 必须红），
所以改常量不需要动测试。

渲染层拿不到 CJS 策略模块（`check-renderer-cjs-boundary` 挡着），因此上界经 `publishFreq:getPolicy`
下发；载荷缺字段时 UI 取 `undefined`（= 不设上界）而不是回落到一个"看着像默认值"的数字 ——
权威拒绝在主进程 validator，UI 的界只是提前告知。

## 决策 3 —— 启动期裁剪：日键必须取守卫的 `today()`，且按 owner 逐个删

`prunePublishDailyCount` 自 v2 就有实现和单测却没有调用方 ⇒ `publish_daily_count` 只增不减。
先例在同一族文件里：`phase1-context.js` 的 signalCollector 注释原文是
「启动时执行一次 30 天清理（C2 修复：**cleanup 需要有生产调用点**）」。

两条不变量：

- **日键同源**：写入方是守卫的 `today()`；启动侧另算一次本地日期就是第二套口径，
  差一天的表现是"昨天的行今天被删"或"该删的一行没删"，两处都不报错。
  所以 `phase1` 取 `container.get('publishIntervalGuard').today()`，
  并在夹具里如实给这个形状（不是替对方补字段 —— 真守卫确实有 `today()`）。
- **删除必须按 owner**：本仓 owner 隔离不变量要求"查询、更新和删除同时匹配 `owner_subject`"。
  一条不带 owner 的 `DELETE WHERE day_key < ?` 与"逐 owner 删"在**最终删了哪些行**上可以同形，
  所以判据必须锁**语句本身**：新增一条拦截 `prepare()` 的用例，断言裁剪期间每条 DELETE
  都带 `owner_subject = ?` 谓词、首参是非空 owner 串、且每个 owner 各一条。
  U7 就是把 SQL 改成跨 owner 那一版 —— 它证明这条锁不是装饰。

另外：日键校验**不能只看形状**。`'2026-13-40'` 过得了 `/^\d{4}-\d{2}-\d{2}$/`，
但 `Date.UTC(2026, 12, 40)` 归一化滚到 2027-02 ⇒ cutoff 落在所有历史行之后 ⇒ **整表被删**。
这是保留窗口的破坏性输入，不是无害空操作，所以谓词必须做 round-trip（解析后重新格式化等于输入），
两个 prune 入口共用它。U8 把校验退回"只看形状"（同时摘掉区间判断，否则变异没取到被禁形态）必须红。

## 决策 4 —— 返回值区分"没有行"与"没测到"

`prunePublishDailyCountAllOwners` 返回 `{owners, removed, basis}`，`basis ∈ measured|invalid_input|not_ready|unproven`。
理由与本仓 #3639 那条同源：把「没测到」印成 `0` 会让运维以为表是干净的，
而 `all()` 在包装层出错时是"log.error + 回吐非数组"，正是"没测到"。
启动日志因此打 `basis=`，且**接不上时也必须出声**（`startup-prune-skipped` WARN）——
否则将来谁把这条维护摘掉，现场是静默的。

## 决策 5 —— `getProbeCounts` 保留但如实登记为"观测面"，不在本片造 UI

它是 D1 `inflightUnknown`、`rollbackDisabledPlatforms`、`missingWiring` 三个探针的唯一出口。
删掉它等于把 fail-closed 的降级变成无痕；为它造设置页展示属 v2 tasks 3.4 未完成的半片，
是功能开发（要 PRD 文案表 + i18n 成对 + 视觉面）。所以本片只在 PRD §8 把它从
"声明了没人接（待接线）"改成"当前消费者是测试；UI 消费另片"，并留工单。
**这不叫收编，叫把话说准** —— 登记的意义是让人知道它还欠什么，而不是假装还着。

## 不做

不动守卫三桶判定、抖动、D1 终身锁、回滚硬顶公式；不实现平台级日配额；不收编 `full-auto-pipeline` 旁路。
