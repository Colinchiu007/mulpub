## 1. 缺陷形状（8 段文案实测归因）

| # | 坏切实例 | 现守卫为何放行 |
| --- | --- | --- |
| 1 | `风速每秒 8 │ 米` | `isSafeCutPosition` 五条件全过：切点两侧都不是保护短语、非"了"边界、**小数内部守卫只认 `数字.数字`**——`8│米` 左数字右汉字，不在其判定面 |
| 2 | `套现约 3.2 │ 亿元` | 同上；`3.2` 是合法小数 token，`│亿元` 无任何规则管 |
| 3 | `提升了 │ 60%` / `制程是 │ 3 纳米` | 切点**左**是汉字（引导词"了/是"），**右**是数字+单位——现有守卫根本不看"右边是否为完整数量词组" |
| 4 | `当 │ 成`、`千 │ 万人`、`遗 │ 忘`、`那 │ 段` | 这些是**双字搭配**，`no_cut_bigrams` 的语义就是"切点不得落在短语内部"，但词表没收录这些高频搭配 |

## 4. 数据同步（跨仓三副本）

规则表是**两仓字节级副本**（#3970 的锁）：`subtitle-rules.json` 改动必须同批同步 sidecar 仓，并重跑 `gen_subtitle_python_golden.py` 更新金标（18 例语料里 `B_shuzi_danwei` 不存在——金标语料不含本次压力文案，**理论上金标不变**；若变了说明规则误伤，即为红灯）。

**回归承诺**：既有 44 条共享向量的 `expected_blocks` 零变化（`unit_guard` 只拒绝新形态坏点；44 条里没有数字│单位切点）；金标 169 块零变化。若违反即说明误伤，当场修词表。

## 4.1 零误伤预检（评审 i5：把口头承诺变机械读数）

改规则**前**扫描既有 44 向量 + 18 金标语料的块间接缝，模拟新词条与 unit_guard 的命中。实测读数：

- no_cut 新词条 8 条：命中 **2 处**，全部是 `飘地`（命中 v1.3 向量 `qing_piao_piao` 块2|3 与金标 `real_hsm_passage` 块51|52——会改变已发布期望输出）⇒ **`飘地` 被否决移出词表**；其余 7 条命中 0。
- unit_guard：命中 **0 处** ⇒ 零误伤 ✅。

## 6. 明确不做

- **`老槐│树下`**：专名处所短语。逐例登记可防这一例，但"处所+方位词"是开放集合，枚举不完备且会持续漏——记为已知限制，等可观测性切片用数据说话。
- **`先想三秒： │ 这钱花出去`**：冒号尾块 + 后块完整通顺，不是坏切。不动。
- **`max_chars_per_block` 上限调整**：会把所有块变长，影响节奏，不做。
