## Purpose

规定账号「显示名」的来源标记与可见性规则：区分系统从平台页面或接口抓取的名字与用户自己写的名字，使前者可以被过滤掉明显的抓取错误、后者永不被过滤，并保证所有展示该名字的界面使用同一口径。

## ADDED Requirements

### Requirement: 账号显示名必须携带来源标记
系统 SHALL 为账号的**首选显示名字段**记录其来源，来源取值只有两类：`auto`（由系统从平台页面、平台接口或平台固定名称产生）与 `manual`（由用户在账号界面上显式命名产生）。任何写入首选显示名的路径都 MUST 同时写明来源；来源缺失时系统 MUST 按 `auto` 处理，不得因缺失而报错或丢字。来源标记 MUST 绑定在「界面实际优先展示的那个字段」上 —— 若把用户命名写进一个不被优先读取的字段，该命名将永远不可见。

#### Scenario: 用户在卡片上改名
- **WHEN** 用户在账号卡片上把显示名改为任意文本并确认
- **THEN** 该账号的首选显示名被更新为该文本，且其来源被记为 `manual`
- **AND** 该次改名不会被后续的资料回填覆盖

#### Scenario: 系统抓取或回填显示名
- **WHEN** 系统通过登录捕获、页面采集或平台接口为账号写入显示名
- **THEN** 该显示名的来源被记为 `auto`

#### Scenario: 读取升级前存量的账号记录
- **WHEN** 一条在本能力引入前写入的账号记录被读取，其来源字段不存在
- **THEN** 系统按 `auto` 处理该记录，且不修改其存储内容

### Requirement: 用户显式命名必须原样显示
当账号显示名来源为 `manual` 时，系统 MUST 原样显示用户写入的文本，不得因任何「看起来像抓取错误」的形态规则（站点后缀、指标量词、省略号、括号不闭合、空格包裹的分隔符、已知页面标题枚举等）而隐藏、替换或改写它。

#### Scenario: 用户命名包含空格包裹的分隔符
- **WHEN** 某账号来源为 `manual`，显示名为 `阿飞 - 自由职业`
- **THEN** 账号卡片显示 `阿飞 - 自由职业`
- **AND** 编辑框回填的也是 `阿飞 - 自由职业`，而不是平台名称

#### Scenario: 用户命名包含省略号或间隔号
- **WHEN** 某账号来源为 `manual`，显示名为 `小美…的厨房` 或 `Rhythm · 音乐厅`
- **THEN** 界面显示与用户输入逐字一致

#### Scenario: 用户命名恰好等于某个平台的页面名
- **WHEN** 某账号来源为 `manual`，显示名为 `小红书创作服务平台`
- **THEN** 界面显示 `小红书创作服务平台`，不回落为平台名称

### Requirement: 系统抓取的名字必须通过噪声过滤才有资格显示
当账号显示名来源为 `auto` 时，系统 MUST 只在它未被判定为「抓取错误文本」时才显示它；被判定为抓取错误时 MUST 回落显示该账号所属平台的名称，且 MUST NOT 因此报错、清空该账号的其它字段或改变其登录状态。

#### Scenario: 抓取到统计块文本
- **WHEN** 某来源为 `auto` 的账号显示名为 `485.9万人看过`
- **THEN** 界面显示该平台名称（如 `今日头条`），不显示该文本

#### Scenario: 抓取到被截断的页面标题
- **WHEN** 某来源为 `auto` 的账号显示名为 `哔哩哔哩 (゜`
- **THEN** 界面显示该平台名称，不显示该残缺文本

#### Scenario: 抓取到真实昵称
- **WHEN** 某来源为 `auto` 的账号显示名为 `数字生命丘丘`
- **THEN** 界面显示 `数字生命丘丘`

#### Scenario: 抓取失败导致显示名缺席
- **WHEN** 系统未能取到任何显示名，该字段为空或缺席
- **THEN** 界面显示该平台名称
- **AND** 该账号上一次已成功记录的非空显示名不被清空

### Requirement: 所有展示账号名的界面必须共用同一口径
凡是向用户展示账号名称的界面，MUST 使用同一套「来源标记 + 噪声过滤 + 平台名回落」解析规则；不得出现某些界面过滤、另一些界面原样输出的分裂状态。

#### Scenario: 同一账号在卡片与分组界面
- **WHEN** 某账号来源为 `auto` 且其显示名被判定为抓取错误文本
- **THEN** 账号卡片与「分组管理」中的成员列表显示同一个值，且该值为平台名称

#### Scenario: 同一账号在改名后
- **WHEN** 用户把某账号改名为 `阿飞 - 自由职业`
- **THEN** 账号卡片与「分组管理」中的成员列表都显示 `阿飞 - 自由职业`

### Requirement: 改名必须写入被读取的真源
用户在界面上改名后，系统 MUST 把新名字与其 `manual` 来源写入**账号列表实际读取的那份存储**，并 MUST 在同一次操作后的列表刷新中可见。写入任何仅供其它用途、不被列表读取路径消费的副本，均不满足本要求。

#### Scenario: 改名后立即刷新列表
- **WHEN** 用户把某账号改名为 `阿飞 - 自由职业` 并确认，随后列表重新加载
- **THEN** 列表返回的该账号显示名为 `阿飞 - 自由职业`、来源为 `manual`
- **AND** 卡片显示 `阿飞 - 自由职业`

#### Scenario: 改名后重启应用
- **WHEN** 用户改名成功后关闭并重新启动应用
- **THEN** 该账号仍显示用户写入的名字，不回退为抓取值或平台名称

#### Scenario: 改名覆盖一个已存在的合法抓取昵称
- **WHEN** 某账号的首选显示名已是一个合法的机器抓取昵称（非噪声），用户把它改名为 `阿飞 - 自由职业`
- **THEN** 界面显示 `阿飞 - 自由职业`，而不是原先的机器抓取昵称
- **AND** 该账号来源变为 `manual`

#### Scenario: 改名请求失败
- **WHEN** 改名写入真源失败（后端返回非成功码或网络异常）
- **THEN** 界面提示失败，且卡片继续显示改名前的值，不得出现「界面显示新名、存储仍是旧名」的分裂状态

### Requirement: 资料回填不得覆盖用户显式命名
系统在登录态检测或重新登录后回填账号资料时，MUST NOT 用抓取到的名字覆盖来源为 `manual` 的显示名；对来源为 `auto` 的显示名，仍按「新值未被判定为抓取错误」的条件覆盖，且新值不合格时 MUST 保持原值不变。

#### Scenario: 用户改过名后触发验证
- **WHEN** 某账号来源为 `manual`，用户点击「验证」且平台接口返回了另一个昵称
- **THEN** 该账号显示名与来源均保持不变

#### Scenario: 抓取名未被判定为错误时回填
- **WHEN** 某账号来源为 `auto` 且显示名为空，检测时采集到合格昵称
- **THEN** 显示名更新为该昵称，来源仍为 `auto`

#### Scenario: 抓取名被判定为错误时回填
- **WHEN** 某账号来源为 `auto` 且已有合格显示名，检测时采集到 `首页 - 知乎`
- **THEN** 原显示名保持不变，不被该文本覆盖
