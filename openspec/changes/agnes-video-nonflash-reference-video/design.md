# Design — agnes-video-nonflash-reference-video

## 1. 决策：参考视频走 Data URI，不引入公网上传基建

上一轮规划里，「参考视频」被设想成需要**公网素材托管**（复用 `podcast-hosting-upload.js` 的 OSS PUT 原语）。重新核算后，这个前提不成立：

- 参考视频**时长受限**（官方 2–12 秒），短片 base64 后体积可控；
- 单请求上限 50MB ⇒ 一个 ≤20MB 的参考视频（base64 后 ≈27MB）仍留有余量；
- 与仓内既有做法一致（`film-engineering/video-reference-inputs.js` 的「本地图片 → dataURL → provider 参考输入」）。

⇒ **先按 Data URI 交付**，零新基建。若上游拒收（官方文档对参考视频写的是「可公开访问的视频 URL」），改动点只有 `pushVideos` 的输出形态 ⇒ 届时再引入公网托管（该原语已在 `podcast-hosting-upload.js` 里备好）。

**未实测项**已记入执行记录（与参考图 T1 同族）。

## 2. 决策：能力门控用属性，不写模型名单

参考视频上传位是否出现，由**当前模型的能力声明**（`supportsReferenceVideo`）决定，而不是「如果是 Agnes Flash 就隐藏」。理由与 `agnes-video-models.js` 一致：名单判据对新增对象默认不成立；属性判据只要求能力表收录该模型。

⇒ 非 Flash 模型一旦被选中，参考视频位**自动出现**；Flash 选中时**自动不出现**。UI 里没有一行模型名。

## 3. 决策：计费口径随能力描述下发

`describeVideoCapabilities` 一并返回 `prices`（各档位现行价 ¥/秒）与 `listPrices`（列表价）。渲染层据此计算预计成本：

```
预计成本 = 输出秒数 × 现行单价
```

- 免费模型（Flash 现行价 ¥0）⇒ 显示「限时免费」而不是 ¥0.00；
- 有参考视频 ⇒ 追加「其时长另计」。

**为什么不给总额**：参考视频的**时长客户端读不到**（需 ffprobe，主进程才有）。给一个偏小的总额比不给更危险 ⇒ 只给「可确定的输出部分 + 明确的另计说明」。

**为什么必须显示**：官方计费口径是「输出秒数 + 输入视频秒数」相加计费。8 秒输出 + 3 秒参考视频 = 11 秒 × ¥0.15 = ¥1.65，比不带参考视频的 ¥1.20 **多 37%**。不显示就是让用户意外多付。

## 4. 决策：非 Flash 的端点不绑定

官方文档标注 `agnes-video-2.5`「已在国际站上线」（`apihub.agnes-ai.com`），而本仓 `agnes-multimodal` 的 base_url 是中国站（`api.agnes-ai.cn`）。

**能力与端点解耦**：模型暴露不绑定端点，端点仍由用户在「模型设置」里配置（既有能力）。这样「模型是否可用」由用户自己的 key/端点组合决定，不在代码里替用户猜。

## 5. 风险与回退

| 风险 | 回退 |
|---|---|
| 上游拒收参考视频的 Data URI | 改走公网上传（改动点：`pushVideos` 的输出形态） |
| 非 Flash 在中国站不可用 | 用户把端点切到国际站；能力描述与端点无关，不需改代码 |
| 参考视频体积撑爆单请求 | 客户端 20MB 上限；超限不入列（不发起请求） |
| 成本显示不完整（参考视频时长未知） | 已明示「其时长另计」；不虚报总额 |
