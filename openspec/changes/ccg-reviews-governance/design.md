## Context

判据要防的是「深度审查静默地从未发生」，而不是「建议项没改完」。旧实现把这件事完全建立在 `.ccg/reviews/<sha>.json` 的工作树副本上 —— 一份**任何人改一行就能自证闭环**的仓内文本。

本设计的核心是把闭环声明抬到「两源自洽 + 公开 PR 面留痕 + 可机器重算载荷」。强度边界见 D9：它抬高伪造成本，**不消除**自证能力，也不构成密码学证明。

> ⚠ 本文档经历过一轮**内部模拟外部评审**（2026-10-16，两个独立上下文的评审代理，判词均为「不可合并」）。
> 下面 D4/D7/D8 的措辞、以及新增的 D10–D13，全部是那两轮否证之后的版本；原文中被否证的两句
> 保留在「曾被否证」小节里，不改写成"一开始就想对了"——那是本仓禁止的叙事方式。

## Decisions

### D1 形态取 B（原始产物移出主干、保留派生台账），但本 PR 只落台账那一半

原始 json 的价值是审计，而审计已由 git 历史完整承载（实测从主干 blob 读回旧记录 6/6 可复原），HEAD 里那份只是「检出继承物」。派生台账（每分支一组状态字段）才是判据真正需要的东西。**刀 2 才动 HEAD**，刀 1 先把判据的数据源换掉。

### D2 台账状态由引擎收口写、判据交叉核验

手写 `ccg_status: cleared` 与被禁的旧形态（改 json 状态词）等价。所以闭环声明必须由 `ccg-record-ledger.js` 在引擎出裁决后产出，且带判据能独立重算的量。**D11 之后这条才真正落地**：`ccg_written_by` 参与否决 + 引擎那份 json 必须同时闭环。

### D3 双读一个周期，不硬切

实测 15 个在飞 open PR 中 **13 个**变更集带 `.ccg/reviews` 文件（2026-10-16 当场读数，会自增；复取：`gh pr list --state open --json number --jq ".[].number"` 后逐个 `gh pr view N --json files` 数 `.ccg/reviews` 前缀）。台账出现任一 `ccg_*` 字段 ⇒ 取新源；否则退回旧 json 语义。硬切会撤掉这 5 个 PR 的守卫，且**不报错**。

### D4 base 与 head **两端**都 MUST 固化成完整 sha

- CI 侧 `--base` 是 `classify` 算出的 merge-base sha（`quality-gate.yml:133` → `classify-docs-only.js:93`），本地手上只有会移动的 `origin/main` ⇒ 记 ref 名则任何并发合并都造出「裁决不是这份代码」的假红。
- 内部评审 I6 补的对称一半：我原先只钉了 base，评论与台账里的 head 仍是字面量 `HEAD`。范围有一半是移动指针，等于抽查者按它重算会得到另一棵树。现在写入侧解析 `HEAD` 成 sha，判据额外核对 `ccg_payload_head` 等于本次评审对象（D12）。
- 代价如实写：rebase 后锚失效，需重跑收口。**且重跑会重做模型审查**（见「曾被否证」），因为引擎没有「已闭环即跳过」分支。

### D5 证据锚 MUST 指向一条具体评论，且写入侧 MUST NOT 伪造

- `EVIDENCE_URL_RE` 要求 PR URL **带** `#issuecomment-\d+` 或 `#discussion_r\d+`；裸 PR 链接等于「我在这个 PR 里说过话」，任何人都能填。
- 必须接受 `#issuecomment-`：`gh pr comment`/`gh api` 产出的就是这一形态，只放 `#discussion_r` 会让每次真实收口假红（我写判据时先犯了这个错）。
- 写入侧贴完从 GitHub **读回**比对 URL，读不回即不写字段；owner/repo 只取本仓 remote（评审 M6：从子进程输出反推会让 GHES 变成「写入侧自认合格、判据恒拒」的死红），且不合成任何形式的兜底 URL。

### D6 载荷哈希 MUST 排除 `openspec/records` 与 `.ccg/reviews`（自指防护）

证据 URL 与哈希本身就写进记录文件，钩子每笔提交还重写 `.ccg/reviews/**`。不排除 ⇒ 「写下哈希」改变被哈希内容 ⇒ 判据永远红，等于没有判据。锁双向：改这两条路径哈希不变（负控），改 `src/a.js` 必须变（正控）。

### D7 写入侧尽力而为、判据负责强制 —— 但**当前强制档位是本地 + 可见，不是 CI 阻断**

`deep-review.sh` 保留引擎裁决码为退出码，收口失败只出声。理由：收口失败的后果（无锚）由判据记账，写入侧再抢一次阻断权只会把「本分支还没有 open PR」这种正常时序误判成评审失败。

**如实标注落点**（评审 I1 指出我把它写成了 CI 强制）：判据在 CI 只被 `quality-gate.yml:145` 以 `--mode=advisory` 调用，`report()` 在该档恒 `exit(0)`；唯一的阻断路径是 AGENTS.md「PR 自动合并」判据第 4 条里 agent 自己跑的 `--mode=enforce`。所以今天这句话的准确形式是「**没有锚 ⇒ 自动合并判据第 4 条不通过 + CI 有可见红字**」，而不是「CI 必红」。转阻断属改「谁来守门」，必须另 PR 并带实测影响面。

### D8 空载荷 MUST NOT 入锚，且判据侧 MUST 认得那个常量

`base == head` 时 diff 为 0 字节，其 sha256 是人人可算的固定常量。写入侧 `assertPayloadNonEmpty` 拒绝它，判据侧再拒一次（评审 M4：只放写入侧时，「记录-only 的变更集」里任何声称等于该常量的锚都自动同源）。

### D9 这枚锚的强度边界（不夸大成强证明）

它把伪造门槛从「改一行仓内文本」抬到「必须让**引擎记录也闭环**、并往公开 PR 写一条指向本次载荷的自洽评论」。它**不是密码学签名**（载荷 sha256 无密钥，任何人重算都得同一值），所以能证明的是「裁决与这份代码同源」，不是「裁决可信」。真实性仍靠人抽查 —— 评论正文逐字写了这句话。

### D10 diff 的生成参数 MUST 被钉死（内部评审 C2 实测后新增）

实测同一仓库状态只换本机 `[diff]` 配置：default / `diff.noprefix=true` / `diff.context=9` ⇒ 三个互不相等的 sha（bytes 180943 / 180693 / 210397）。写入侧跑开发者机器、判据跑 ubuntu runner ⇒ 带这些配置的人每次重跑都得到自己那个 sha，永远不等，且**没有任何带内出路**；本仓对这类假红的既有归宿是「被当噪声，然后被放宽」。
落点：`payloadArgs` 用 `-c` 钉 `diff.noprefix/context/algorithm/indentHeuristic/mnemonicPrefix`，并在子命令后加 `--no-ext-diff --no-textconv`。
两条踩过的坑一起记着：① `--no-ext-diff` 是 `diff` 的选项，放到子命令**之前** git 直接 `unknown option` —— 表现为判据一次都没跑起来，而报错读起来像参数拼错；② 曾用 `GIT_CONFIG_GLOBAL=os.devNull` 做 env 隔离，Windows/MSYS 下变成 `//./nul` 让 git 当场失败 —— 命令行 `-c` 的优先级本就高于所有配置文件，env 隔离是多余且有害的。

### D11 引擎 json 与台账 MUST 两源一致（伪造路径的主修法）

评审实测：台账四个被判值（状态词 / 证据 URL / base sha / 载荷 sha）**全部可离线导出**，只看 URL 形状的判据会把「一条不存在的评论」判成外部证据；我自己的那次「现场自证」跑出 OK，正确读法就是伪造成功。
判据不能联网，所以修法不是把 URL 变强，而是让引擎那份判定记录成为必要条件：台账说闭环而 json 没闭环 ⇒ 两源必有一假 ⇒ 一律计欠账并点名两源读数。真实流程不误伤 —— 写入侧本就要求 json 已闭环才落台账。
配套：`ccg_written_by ≠ 'deep-review'` 单独否决（此前它只被写出、无人读，是装饰字段）。

### D12 锚 MUST 签在本次评审对象上

判据核对 `ccg_payload_head` == 本次 head（解析成 sha）。没有这一条，「锚自洽」可以是拿**另一笔提交**的 diff 算出来的。

### D13 借用他人裁决 MUST 被 stagedDiffHash 同源校验挡住

起点候选（D4/多提交分支）指向的是「公共提交」名下的记录，而 34 个 worktree 共享一份对象库、文件名按父提交 sha 命名 ⇒ 完全可能读到别的会话那份 dual+closed。实测 origin/main 的 16 份 dual+closed 记录里有 3 份本身就是 main 的祖先。
落点：起点候选必须用 decider 同口径重算 `stagedDiffHash` 并比对，缺字段或不符 ⇒ 退回「不同源」这一档并给出**与「没找到记录」不同**的补救文案（W19 锁这一区分）。
刻意不合并的一处：该比对**不用** D10 的钉参数 —— 要比的是 decider 当时算的数，两边必须逐字同实现，钉死反而制造永久不等。

## 曾被否证（保留原文，不改写历史）

1. 「rebase 后重跑收口只需重算哈希、不重做模型审查」（本文件旧版 D4）。**否证方式**：读 `deep-review.sh` 与引擎 —— 两处都没有「已闭环即跳过」分支，`node "$DRIVER" --sha` 无条件执行。现改为如实说明重跑会重做审查。
2. 「没有锚 ⇒ PR 在 CI 变红」（旧版 D7 与 spec 措辞）。**否证方式**：`grep check-pr-exec-record .github/` 只有 `:145` 一处调用且带 `--mode=advisory`；`report()` 在该档恒 `exit(0)`。见 D7。
3. 「台账接管旧 json 的 pending 是预期行为」（旧版判据用例，且被钉成断言）。**否证方式**：该形态正是 D11 要关的伪造通道；用例已反转，并补两源一致的正控。
4. 「`upsertFrontmatterFields` 只碰被点名的行」（旧版实现与注释）。**否证方式**：混合行尾输入实测 CR 2→8、`changed` 只报 1。现按行 splice、绝不碰行内 `\r`，并加混合行尾夹具。
5. 「收口在生产路径上是通的」。**否证方式**：`deep-review.sh` 用 `--base <值>`（空格形）而解析器只认 `--k=v` ⇒ base 读成布尔 true、rc=2，一次都没落过锚；13 条 JS 层变异全部逃过（洞在 shell→node 边界）。现两种写法都吃，并加真进程真仓库的 argv 锁（W16）与结构锁（W17）。
