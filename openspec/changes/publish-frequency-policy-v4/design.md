# design — publish-frequency-policy-v4

## D1 平台档：三个候选与选择依据

| 候选 | 内容 | 结论 |
|---|---|---|
| A 保留分级、只收数值 | 3′/2′/1′ → 例如 2′/1′/1′ | 可行，但分级本身不可验证（没有任何本地指标能说明"长文平台的跨账号节奏更稳"带来了什么），三档值只是让用户多做两次无法判断的输入 |
| **B 三档统一 1′（选定）** | 机制在、分级撤 | 语义简化为"同平台任意两次发布至少隔 1 分钟"；跨号关联防线保留；long/clip 吞吐几乎不受限（账号档 5′/3′ 才是它们的实际闸门） |
| C 整条删除 | `platformMinMs = 0` | **否决**。平台桶只防"同机不同号同平台并行"，而这恰是本地唯一无信号的故障面（平台侧关联 → 限流/连坐掉登录）。删掉后三号矩阵在同一平台可零间隔并行，一旦命中，症状与前几轮真实事故族（"第一次是登录页""莫名掉登录"）同形，排查成本极高 |

选定 B，并把 B 的"不得退化成 C"做成可执行约束：变异 **N6** 把三档 `platformMinMs` 归 0，必须让
`v4：平台间隔三档统一 1′`、`15 个支持平台全部登记，且三个维度均为正数` 两条同时变红（已实测）。
后者是既有锁——`0` 在"正数"判据下本来就被拒，两条各守一处。

## D2 日配额：为什么 350，以及单调锁的形状变了

用户给的是区间端点（200 / 500），没给中间档。取等差 350 的唯一理由是**保持既有档间单调**
（`long < clip < short`），这样"配额维度仍分档"这条产品规则不需要被推翻，只需换数。
若运营后续要 clip 贴 200 或贴 500，改一个常量即可，锁会跟着变红并要求同步改数据表——这是刻意的：
改配额必须是一次"看得见锁在动"的动作，不是静默漂移。

档间单调锁本身在 v4 改了**形状**（不是放宽）：

- 间隔维度：`long > clip > short` 仍是**严格**大于（v4 没动账号档）。
- 平台维度：v3 是 `long ≥ clip ≥ short`（允许相等，因为当时分级）；v4 三档相等 ⇒
  改成 `long == clip == short`。**等号从"不弱于"变成"必须相等"是收紧，不是放宽**，
  它把"有人偷偷给 long 档留 3′"变成红的。
- 配额维度：仍严格小于。

## D3 基线（未登记平台回落）与"独立常量"的代价

`BASELINE_INTERVALS` 不从 `TIER_PRESETS` 派生，所以 v4 必须**手工同步**它，否则新平台一登记就比
老平台严/宽一截。v3 已有逐维度锁（间隔取已登记最大值作下界、配额取已登记最小值作上界）兜住这件事；
v4 下该锁的实际读数：

- `accountMinMs`：基线 5′ ≥ 全域最大 5′ ✓（等号，收紧到 long 同值）
- `platformMinMs`：基线 1′ ≥ 全域最大 1′ ✓
- `accountDailyMax`：基线 200 ≤ 全域最小 200 ✓（等号 ⇒ 回落比任何平台都宽就被拒）

三条等号意味着"基线与最严档完全重合"，这是 v4 数值形状的直接结果，不是巧合；
变异 **N4**（基线配额写成 600）证明这条锁真的有牙（实测 2 条红）。

## D4 回滚硬顶为什么不随配额放大（复述并补锁）

`_rollbackCap = min(max(2, dailyMax), MAX_ROLLBACK_PER_DAY=5)`。配额 30→200 时该值不变，
但**必须实测**而不是从公式推断——v3 的教训是"公式对、接缝错"。v4 新增一条行为锁：把**真实策略**
接进守卫，逐档读 `_rollbackCap` 并断言恒等于 5；N5（退回 `max(2, dailyMax)`）变红。
同时保留 v3 那条"真表读数 > 封顶"的前提锁——两条各测一层：前提锁保证封顶**会被触发**，
新锁保证触发后的**结果**是 5 而不是 200/350/500。

## D5 文案为什么必须改

`platformIntervalHint` 原文「默认各档账号档**更**严」在 v3 成立（5′>3′、3′>2′、1′… short 档
账号 1′ == 平台 1′ ——其实 v3 就已不成立，只是当时没人读这句）。v4 下短内容档相等这一事实更明显，
所以措辞改为"都不低于本值（短内容档两者相等）"，并在测试里同时钉住：
禁止出现旧句、必须出现"不低于"。这是"文案与生效值同源"的落点，不是润色。

## D6 本轮不做的事（避免范围漂移）

数值类反证只覆盖"值/形状"，不覆盖"归属是否合理"（把 weibo 挪进 long 档不会让任何数值红）；
`full-auto-pipeline` 的 5s 旁路不经守卫，本 PR 的锁对它**完全无效**——已在 PRD §8 写成欠账而非遗漏。
