# Proposal: ux-audit-implement

> 本 change 是 `01-docs/UX-AUDIT-2026-10-17.md`（71 条 finding / 6 阶段）的**实施契约**。
> 规格回答"必须成立什么"，PRD `01-docs/PRD-UX-AUDIT-IMPLEMENT-2026-10-18.md` 回答"长什么样、怎么交互、怎么校验"。
> 已实现：阶段 0（0.1–0.6）+ 阶段 1 批次 A（1.5/1.6/1.7/1.8/1.9）。其余阶段在 `tasks.md` 逐项待办。

## Why

审计的三条结论无法靠"知道"来解决，必须有机械闸门：

1. **确认机制碎成 4 套且自称契约与现实不符**（audit-12）：`utils/confirm-danger.js` 注释写着"所有删除类/不可逆操作必须经由此函数"，实测只有 4 个消费点，其余走 `notifyConfirm`（48 处）、应用内 `ConfirmDialog`、两步内联。没有东西在检测这句话，于是它是装饰性的。
2. **同一个删除 API 在两个页面守卫不对称**（audit-2，blocker）：`draftDelete` 在采集页有确认、在发布页没有——用户在发布页误点"删除"即永久丢正文，全仓无回收站无撤销。
3. **"已实现但没人渲染"是一个可枚举的结构性缺陷类**（audit-6/66）：暗色主题（6 轮对比度修复全部投向用户进不去的态）、公告横幅（数据链齐备、零挂载点）、快捷键面板（IPC 齐备、渲染端零调用）、全局注册的 `LoadingState`（模板零使用）、只写不读的 `lastEventAt`（写 4 读 0）。这类缺陷的共同点是**每一层各自看起来都完整**。

## What Changes

- 新增 capability **`desktop-ui-experience`**，把上述三类事实写成可被测试直接引用的 Requirement：
  1. 破坏性写入口必须经确认（含作用域判据与豁免登记口径）；
  2. 不可逆操作必须"取消即不执行"，且文案点名对象 + 披露不可恢复；
  3. 未保存内容在两条出口（路由切换 / 关窗）都不得静默丢失，覆盖面必须**扫出来**而不是记下来；
  4. 模态原语的安全默认值不得低于它替换的库；破坏性动作不得绑在关闭路径上；
  5. 已注册但无消费者的组件/字段属缺陷，必须有门禁让下一批出现即红；
  6. 未知路由必须有可行动的兜底页，不得空白；
  7. 网络与进度的观测通道必须双向（只报恢复不报断开 = 没有通道）；
  8. 用户可见文案必须双语成对，且图标/宿主 API 具名引用必须真实存在（不得只在打包阶段暴露）。
- 文档交付：新增 `01-docs/PRD-UX-AUDIT-IMPLEMENT-2026-10-18.md`（显示项/交互/校验/提示文字全清单）、
  `docs/frontend-interaction-spec.md` 追加导航与守卫章节。
- 明确不改的：品牌名（产品决策）、IA 归并（依赖埋点数据就绪）、`CreateView.vue` 重构、
  给 Publish 挂离开拦截（keep-alive 已保活，防一个不会发生的丢失）。
