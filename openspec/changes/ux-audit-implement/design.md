# Design: ux-audit-implement

## D1 确认原语的"硬化顺序"：先门禁，后复用

外部评审（第一轮 w6）否证了原计划的顺序：`audit-1` 要"复用 `confirmDanger`"，而 `audit-12` 恰好证明该原语是自称契约、实测 4 个消费点、无门禁——复用一个不可信机制等于传播它。
因此顺序固定为：**0.4 接线门禁先落地 → 0.1/0.2/2.6 才引用它**。本 change 已按此序执行。

## D2 门禁判据为什么选"函数作用域"而不是"同文件"

审计稿原话是"扫 delete/remove/clear 写入口未走该函数即红"。可实现的判据有三种，实测差异如下：

| 判据 | 漏报 | 误报 | 结论 |
|---|---|---|---|
| 同文件出现过确认 | "确认写在另一个函数里"（实测 3 例） | 少 | 太宽 |
| 所在函数体内有确认 | 少 | "薄封装 + 上游确认"（实测 6 例） | 需配合登记表 |
| 调用点可达图上有没有确认 | 少 | 少 | 静态实现代价不成比例 |

选**中间档 + 登记表**：判定单位是函数作用域，跨层确认必须在 `danger-confirm-debt.json` 写 `confirmed_by`（指明确认发生在哪个文件哪一行，或写明该操作可重做故不锁）。理由：本仓"新增持久化字段必须同时改所有投影白名单"那条 MUST 的同型教训说明，**免检清单比没有清单更危险，而带证据的免检清单是可审的**。

作用域判定必须是字符级掩码：注释与正则字面量里的 API 名不是调用（`// draftDelete(x)`），同名定义点不是调用（`stores/accounts.js` 里就有个局部函数叫 `batchDelete`）。这两条都是实跑撞到的。

## D3 未保存守卫的覆盖面必须"扫出来"

审计结论自己写了"先枚举哪些编辑态页面不在 keep-alive include 内，再挂脏标记；**不得**把 Publish 与它们并列"。落地时枚举用扫描而不是清单：`src/unsaved-leave-contract.test.js` 以 `<textarea v-model>` 为编辑态形态，三选一（保活 / 已挂守卫 / 带实测理由的欠账）。

为什么不一次挂满 8 个：每个守卫都需要一个**内容级**脏判据；判据写错（恒真）会把每次导航变成打扰，那是一条新的用户可见缺陷，比原来的丢失更难退。本批只挂判据无歧义的 `RewriteView`（`savedDraftId` 是既有的"已落真源"信号，且内容变化时已有 `invalidateSavedDraft` 复位），其余带逐条实测理由登记。

## D4 `UiModal` 只翻两个默认值，第三个判据改写

审计稿建议翻三个默认值。实测复核后：

- `trapFocus` / `closeOnEsc` 是**纯增益**（焦点循环与 Esc 关闭都是既有实现，只差默认开），翻。
- `closeOnOverlay` 不翻：全局翻转会从 33 个良性弹窗拿走"点遮罩关闭"这一常用手势（评审 w7）。
- 而审计稿给出的理由"破坏性弹窗点遮罩即消失＝默认同意"经实测**不成立**：三处承载删除的 `UiModal`（`AccountGroupManager`、`AccountProxyDialog`、`CreateView` 项目删除对话框）的关闭路径都路由到 cancel，不触发破坏动作。
- 于是判据换成可机械检出的真风险形状：**破坏性动作不得绑在关闭路径上**（`@close` 表达式里出现 delete/remove/clear/revoke/confirm-executing 即红），承载点清单只能缩小。

## D5 离线：补方向而不是加轮询

主进程 `net.on("offline")` 早已存在，症状"断网无横幅"的真实断点是**只有恢复方向有出口**。所以修法是在 `onNetworkChange` 的 `!wasOffline && isOffline` 分支加 `offline:lost` 推送 + preload 暴露 + 白名单登记，而不是在渲染层加定时器轮询（轮询会引入新的能耗与状态延迟，且仍会有窗口）。
渲染层再加 `window` 的 `online/offline` 作为第二通道，因为主进程推送依赖"存在可发送的窗口"这一前提。

## D6 陈旧看门狗的三个"不谎报"边界

`lastEventAt` 写 4 读 0 的修复不能反过来制造假故障：

1. 取**所有 running 任务里最近一次事件**，任一任务刚动过就不算整体停滞；
2. 两个锚点（`lastEventAt`/`startedAt`）都缺 ⇒ 沉默；
3. 全部终态 ⇒ 不判停滞。

阈值 3 分钟，采样 15 秒；定时器与订阅同生命周期（App 级），`init()` 幂等由 `listenersBound` 守，并额外断言"重复 init 只挂一个 interval"——本仓有过"全局单例监听器在窗口重建时重复注册"的同族缺陷。

## D7 图标/宿主具名引用不能只在打包阶段暴露

设置页新 Tab 挑图标时写了 `Keyboard`，`@element-plus/icons-vue` 里根本没有这个名字，而**组件测试全绿**（视图测试按交互规范 §11.3 用 Proxy 兜底 mock 图标），只有 `vite build` 报 `"Keyboard" is not exported`。这是本 PR 唯一一次真实撞到"CI 才会发现的构建期失败"，因此补了 `src/icon-imports-exist.test.js`：扫渲染端所有具名图标 import 并用**真模块**核对，另加一条"判据自己有区分力"的断言（`Keyboard ∉ 导出集`、`Key ∈ 导出集`）防止扫描器退化成恒真。
