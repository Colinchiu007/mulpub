本文件规定「怎么做」。proposal 规定「做什么」，tasks 规定「做到什么程度算完」。

## 1. 范围与优先级（人工裁定，非执行方自行变更）

| 维度 | 裁定 | 理由 |
|---|---|---|
| 范围 | **账号管理 + 内容发布**，两者都做，发布优先 | 用户明确要求"全方面升级和优化"，不预设收窄 |
| 首发方向 | **内容发布链路**先行 | `kuaishou-sig3.js` 已打通一条完整链路，有现成方法论可复制；账号管理的 ticket-guard 尚未定性，风险更高 |
| UI/交互 | 仅参考 B 级（架构/流程/契约），**不参考竞品 UI** | 避免产品层面对竞品的直接模仿 |
| 敏感词库 | **本 change 范围内不做** | 属合规灰区，需单独立项并单独裁定用途口径 |

执行方发现上述裁定与实际需求冲突时，**停下来报告，不自行变更**。

## 2. 覆盖度矩阵：判据与形态

### 2.1 为什么必须先做矩阵

仓里有 114 项逆向成果。没有索引就动手，典型后果是：一头扎进某个模块、
重复分析已结论的内容、或把 C 级情报当 A 级实现依据。矩阵的作用是**把成果映射到缺口**。

### 2.2 三档判据（机械判定，不许用形容词）

| 档位 | 判据（必须同时满足） |
|---|---|
| **已支持** | ① 存在 adapter；② 该链路有**真实服务端验证**证据（只读端点，含带签/无签对照） |
| **可优化** | ① 存在 adapter；② 但缺真实服务端验证 / 签名链路不最优 / 有已记录缺口 |
| **完全缺失** | 竞品支持该平台链路，而我方无对应 adapter |

> 「有代码」不等于「已支持」。判据是**外部真值验证**，不是"文件存在"。
> 这条与 `kuaishou-sig3.js` 落地时修掉的根因同型——把"自己和自己比"当成"和平台比"。

### 2.3 矩阵形态（必须是表格，禁止散文代替）

| 平台 | 我方状态 | 我方签名方式 | 竞品签名方式 | 差距 | 风险 | 建议优先级 |
|---|---|---|---|---|---|---|
| 例：快手 | 已支持 | `__NS_sig3` 本地纯 JS | 页面内 JS 签名（VM） | 无 | 低 | — |
| 例：抖音 | 可优化 | 本地 `clientSign` + 空 `a_bogus` | 同（参考产品链） | 缺活体裁决 | 中 | 高 |

### 2.4 停止条件

矩阵完成后**立即停下来报告**，由人指定第一个落地项，执行方才进入实现阶段。
理由：矩阵会暴露多个缺口，自行挑选等同于自行决定优先级——那是人的决策。

## 3. 单个落地项的执行纪律

### 3.1 顺序（不许跳步）

```
写测试（先红） → 实现 → 算法对拍（如涉及签名） → 只读端点真实验证 → 全量测试 → 执行记录 → PR
```

### 3.2 涉及签名算法时的额外要求

1. **逐字节对拍**：与竞品 VM/实现比对 N/N 样本，N ≥ 10（沿用 `kuaishou-sig3.js` 的标准）。
2. **自检 + 变异反证**：提供 `verifyKnownVector()` 等价物；
   且必须有一条测试证明「基线集合不是恒真式」（否则自检是装饰）。
3. **不可"修正"的坑必须写进注释**：凡逆向发现竞品行为与标准实现不一致处
   （如 sig3 的 `pad` 长度字段 = `bitLen+512`、字保持有符号、`compress` 必须 slice IV），
   必须在源码注释中明确标注「不可修正」及原因。
   理由：这些是竞品真实行为，"修正"会导致签名不被接受；而它们看起来就像 bug，
   后来者极可能"顺手修掉"。

### 3.3 状态隔离

凡签名器持有可变状态（计数器、startupRandom 等），必须提供 `createSigner()` 等价物，
并明确并发语义。禁止只暴露一个模块级单例。

### 3.4 fail-closed 边界

签名函数**不承担**凭据校验（分层：校验在调用方），但**必须存在**校验层。
缺 cookie / 缺关键字段时必须抛错或拒绝，**不得无条件产出"格式合法"的值**。

> 这条是 PR #4090 三轮评审的教训：我曾把 `api_ph` 依赖整个删掉，导致无凭证调用
> 也能拿到合法签名。合法格式 ≠ 有签名能力。

## 4. E2E 真机测试不成功：契约化改造方案

### 4.1 问题定性

当前 E2E 依赖真机 + 真实账号 + 真实平台响应，失败原因常为：
环境时序、账号态过期、平台侧变更——**都无法在 CI 中稳定复现**。
这类失败的真正代价不是"测试红了"，而是**无法区分"我的代码错了"和"环境又变了"**。

### 4.2 逆向成果在此处的正确定位

逆向成果提供了各平台链路的**真实请求契约**（时序、method、URL、headers、body 字段名）。
这正是构造假服务器所需的**外部真值**——它替代的正是"去真机抓一次才知道"的那个环节。

### 4.3 改造模式

```
真机抓包得到的契约  ──►  127.0.0.1 假服务器（钉死请求序列/头/body）
                                │
                                ├──► CI 可复现的契约测试（每次跑）
                                │
                                └──► 真机验收（仅最终验收时，人触发）
```

具体要求：
- 假服务器必须**钉死完整步骤序列**，步骤缺失/乱序即失败；
- 每步断言 method / URL 前缀 / headers 白名单 / query 串 / body 字段；
- 必须有 **fail-closed 零请求面**：签名材料缺失、文件不存在等 → 断言零网络请求；
- 零外发：测试全离线，不得真连平台。

### 4.4 边界（不许过度声称）

契约测试通过**不证明**平台真实行为未变。它证明的是「我方代码符合已知契约」。
因此：

- 契约测试是**必要条件，不是充分条件**；
- 真机验收仍保留为最终判据，但降为「最终验收」而非「唯一手段」；
- 契约来源（哪份切片、哪个偏移量）必须记录，平台变更时可回溯更新。

## 5. 执行红线（违反任一，立即停止并报告，不得自行判断）

1. **不整份复制竞品代码**。竞品 bundle 是压缩产物，直接搬入无法维护、无法验证、
   会继承其中未知缺陷；应只参考架构、流程、契约，用本项目自己的测试锚定行为。
   `00-vendor-originals/` 用于核对结论，不作为代码来源。
2. **不实现平台风控规避能力**：不把反自动化、验证码、频控、滑块作为功能目标。
   sig3 落地的理由是「正确集成平台签名机制」。
3. **不泄露任何 cookie/token/会话值**。日志、提交信息、文档、PR 正文一律脱敏。
4. **不调用有副作用的端点**（发布/上传/删除）作为验证手段。
   验证只走只读端点；副作用端点只在真实发布意图下由人触发。
5. **不得改门禁让自己过**：不放宽既有断言、不用 `--no-verify`、不为消红删测试。
   改既有断言必须在代码内写明理由与证据。

## 6. 验收标准（Definition of Done）

一个落地项只有同时满足以下才算完成：

- [ ] 全量 `node scripts/run-tests.js` rc=0
- [ ] 新增/更新的断言锚定**外部真值**（不是自己和自己比）
- [ ] 涉及签名则有逐字节对拍 + 自检 + 变异反证
- [ ] 真实服务端验证证据（只读端点，含带签/无签对照）
- [ ] 契约测试覆盖完整步骤序列 + fail-closed 零请求面
- [ ] 执行记录写入 `openspec/records/<分支名>.md`
- [ ] PR 通过完整质量节节拍并合并
- [ ] 未验证的边界已**如实标注**（不许假装闭合）

## 7. 环境约定

- 运行时代码任务必须 worktree 隔离（`scripts/session-init.sh <task-name>`），
  **禁止在共享根直接改 `packages/`**（共享根是 main-only 协调目录，由
  `pre-code-edit-guard.ps1` 与 Write Guard 机械拦截）。
- 本 change 的 proposal/design/tasks 属文档类，按 AGENTS.md「旧载体冻结」后的口径，
  在共享根就地编辑后走 PR 落地。
- 交流与提交信息用简体中文。
- 证据口径：「判据域跟着被测性质走」——断言某段代码会执行，
  就不能只断言「字符串在文件里」。
- 判据取不到读数时按未证实处理，**不得把工具失明读成结论**。
- 文档内零盘符路径、零品牌残留（竞品名写「参考产品」或「竞品」）。
