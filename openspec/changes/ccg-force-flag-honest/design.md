# 设计：把「做不到的承诺」从评审链入口上摘掉

## D1 三条路里选「显式拒绝」

| 方案 | 效果 | 为什么选/不选 |
| --- | --- | --- |
| A 删除 `--force` 旗标 | 变成「未知旗标 rc=2」 | 不选。那两份已合并记录教人去敲它，删掉后新会话敲到的是一句「本入口只认 …」，读起来像**拼错了参数**，而不是"这条命令在这个层做不到"。归因被推给下一个查询者。 |
| B 真实现强制（入口改写判定记录的 `mode`） | 旗标照字面生效 | **禁止**。`mode` 是提交时 decider 的产物，事后改成 `dual` 等于伪造判定产物——本文件 `:871` 附近已有同族口径「新建判定产物等于伪造」。而且它会把「decider 判了什么」与「人想不想审」两件事混进同一个字段。 |
| C 显式拒绝 + 说出真实出路（**选这个**） | `--force` 仍在参数表里，但 `skip` 档下 `rc=2`、文案点名做不到的原因与两条能用的路 | 唯一同时满足「不许假绿」和「不许假装支持过」的形态。下一片要补的是真通道（见 D6 残留）。 |

## D2 取证配方（判据必须能被重取，不能只有本会话的对话记录）

一次性探针，跑在系统临时目录里自造的 git 仓（不碰任何在飞产物、不入仓）：

1. `git init` + 一次带 `-c user.name/-c user.email` 的提交（`commit-tree`/`commit` 在无身份环境下 rc=128，本切片上一刀刚实测过）；
2. 写 `.ccg/reviews/<head>.json` = `{mode:"skip", deepReview:{status:"cleared", tier:"external", performedBy:"claude", evidence:"PR #4204 issuecomment-6323452201", findings:7}}`；
3. `node <引擎绝对路径> --sha <head>`，父环境显式置空 `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE`（切片 D 实测 `GIT_DIR` 会静默压过 `{cwd}`，不排掉就量到别的仓）；
4. 读回那份记录并打印 rc、stdout 末三行、`deepReview` 前后。

2026-10-22 当场读数：`rc=0`、`判定为 S 复杂度低风险，按决策矩阵不做深度审查 —— 退出 0`、`wipe=true`（前值 `cleared/external/PR #4204 …` → 后值 `skipped_by_mode/performedBy:null/findings:null`）。

**行号只作出处，不作判据**：引擎住在仓外技能目录，升级即漂移。本刀的锁一律量**入口自己的可观测产物**（退出码、输出文案、桩驱动是否被 exec、记录字节是否变动），不引用引擎行号，也不 `hasattr` 式地断言引擎源码里出现过某个串。

## D3 早退必须排在依赖体检之前

`skip + --force` 走到今天会落到 `exec`，中间先经过 `:807` 的依赖体检。体检在**没有后端**的环境里会 `exit 2` 并打印「找不到 codeagent-wrapper / 没有可用评审后端」——于是在同一台机器上，同一条 `--force` 的失败文案取决于装了哪些 CLI，而不取决于它做不到的那件事。这是归因错误，不是严格性问题：

- 有后端：`rc=0`，一句"不做深度审查"，记录被覆写；
- 无后端：`rc=2`，理由是"后端缺失"，**把旗标缺陷伪装成环境问题**。

所以新的拒绝点插在 `:798` 那格原地（判定行打印之后、`# ---------- 4. 依赖体检 ----------` 之前）。对应锁不断言 `rc` 单独成立，而是**同时**要求文案命中固定词族 —— 锁里用的判据就是 `/不会强制/`（实现必须原样提供该词，测试与实现同一串，不允许"同族词"各写一份）；否则 `rc=2` 可能被缺失后端那格顶罪（同切片 D 的「同名行顶罪」教训）。

## D4 退出码取 2，并在文件头退出码表里点名

文件头现有原文（`scripts/deep-review.sh` 末行注释，`--help` 会整段打印）：

```
# 退出码：0 无阻断 / 1 有阻断 / 2 环境或配置问题
```

现有码表就是这三档：`0` 无阻断 / `1` 有阻断（判定链 fail-closed，如「该有记录却读不到」，见 `:781` 那段第五轮 i4 的注释）/ `2` 环境或配置问题（未知旗标 `:88`、缺值 `:76`、后端缺失 `:814`/`:825`、回写失败 `:875`）。`--force` 在 `skip` 档做不到属**参数层不可用**，与"未知旗标"同档 ⇒ 取 `2`。不取 `1`：`1` 在本入口的既有语义是"判定链发现阻断"，把一次人为的旗标误用报成门禁阻断会污染它的读数（`1` 是给人去看 PR 的）。

## D5 决策层的 `--force` 也没有对象——初稿结论被实现前实测否证，改设计

本节**推翻本刀设计初稿自己写的结论**，过程如实记在这里（不留"设计对了一半"的模糊版本）：初稿断言「决策层的 `--force` 是真的，因为引擎决策层从命令行取 `mode`、缺省 `dual`」。前半句仍成立，但由它推出的那半句错了。

2026-10-22 实测（同一份 2 行方案，两种路径形状）：

```
node scripts/ccg-review-decider.js --input <临时目录>/tiny.md                          → 判定 [决策层(动手前·方案)]: SINGLE
node scripts/ccg-review-decider.js --input <临时目录>/openspec/changes/probe/design.md  → 判定 [决策层(动手前·方案)]: SINGLE
```

判据本体在 `scripts/ccg-review-decider.js` 的 `isDocsOnly()` 首行 `if (staged.proposal) return false`（方案评审不走 docs-only 快通道），而 `judge()` 里 `mode = "skip"` **只有** `isDocsOnly(staged)` 为真这一条路 ⇒ 决策层**恒不产出 skip**。于是 `plan-review.sh` 那句 `if [ "$MODE" = "SKIP" ] && [ "$FORCE" -eq 0 ]` 与它的 `--force` 旗标构成**第二处装饰性承诺**：那行「跳过跨家族对抗评审（--force 可强制）」永远不会被打印，旗标也没有可作用的对象（S 复杂度的方案今天照样全量跑，只是走 SINGLE）。

两处的病灶同型、后果不同，必须分开写清：

| | 验证层 `deep-review.sh` | 决策层 `plan-review.sh` |
| --- | --- | --- |
| `skip` 档可达吗 | **可达**（`.ccg/reviews/*.json` 的 `mode` 真会是 skip） | **不可达**（decider 对 `--input` 恒不判 skip） |
| 带 `--force` 的真实后果 | 照样把控制权交给驱动 ⇒ 驱动回写 `skipped_by_mode`，**抹掉出处**，rc=0 | 无副作用，但承诺了一个永不成立的分支 |
| 本刀处置 | 拒绝 + `rc=2` + 说出真出路 | 删死码（分支 + 旗标 + 用法行），并锁住"不可达"这一事实 |

决策层**不**改成"支持强制"，也**不**保留旗标以防将来，三条理由：① 今天没有任何一种方案会被跳过，所以不存在"需要被强制"的对象；② 留一个不会生效的旗标正是本刀要消灭的形态；③「让方案评审可按规模跳过」是新增门禁语义（谁被豁免、由谁判），属"谁来守门"，须另立一刀并经人工过目。

因此锁的形态是**反向**的：把「decider 对 `--input` 不产出 skip」与「S 复杂度方案照样交给驱动」两格钉住。将来谁要引入跳过语义，会先让这两把锁变红，必须显式改判据，而不是顺手把旗标加回来。

四格锁矩阵（改后；每格一条断言）：

| 入口 | 带 `--force` | 不带 `--force` |
| --- | --- | --- |
| 验证层（`mode=skip` 记录） | **不**交控制权：答复面 `rc=2`+固定判据串（锁 3.1a），产物面 驱动未起+记录字节不变（锁 3.1b，拆开的理由见 D7 末段） | **不**交控制权，`rc=0`（锁 3.2，既有语义） |
| 决策层（S 复杂度方案） | 旗标已删 ⇒ 走既有的"未知旗标只出声不拦"分支，行为与不带同形（锁 3.5c） | **交**控制权：桩驱动落标记（锁 3.5a）；另加锁 3.5b：decider 对两种路径形状都不输出 skip |

## D6 不改写那两份历史记录；真实控制点是命令自己

`collection-page-ui-ue-refine.md` 与 `film-engineering-user-manual.md` 是历史事实快照（口径：不改写历史，追加最新锚点声明现状）。本刀不编辑它们，也不新建回填 PR。做法是让**下一次执行该命令的会话当场读到真相**（入口文案 + `--help`），并在本 PR 执行记录的 `## learnings` 里记下这条，由聚合器搬运；`01-docs/learnings.md` 不由 PR 直接编辑（AGENTS「参考文件」节 2026-10-21 起的规定）。

**残留（不得读成已闭合）**：

1. 验证层"真强制"仍无通道。合同：下一片要么由 decider 支持「按已提交区间重测并写一条新判定」的显式补跑档（`--base <rev>` 已存在，缺的是"人请求覆盖判定"这一格与它的留痕字段），要么由入口生成 diff 简报走决策层；两者都必须让 `check-pr-exec-record.js` 看得见出处，不得静默。
2. `writeBack` 覆写只在 `mode=skip` 那一格可观测；对 `mode=dual` 的记录本探针**没有**测过，不得外推成"引擎从不覆写别的字段"。
3. `evaluateDeepReviewDebt` 只强制 `mode=dual` 的产物（AGENTS「矩阵口径」节 + 该函数 `continue` 的既有事实），所以记录被抹成 `skipped_by_mode` **不会**让任何门禁变红。这恰恰是本缺陷能藏这么久的原因——本刀修的是承诺，不是给这条链加判定。

## D7 变异反证格子（合同先写，实现后逐条实跑；红集关系如实披露）

驱动只跑两份测试文件（`deep-review-deps.test.js` + `plan-review-deps.test.js`，合并 59 条），每轮断言 `# tests` 等于对照读数；读数不等一律记 **UNREADABLE**，不得计入 CAUGHT/MISSED。替换未命中记 **NO-OP**（变异本身无效），锚点缺失记 DRIVER-ERROR——三档都不算"未被抓住"。

| 编号 | 变异 | 预期红在哪 |
| --- | --- | --- |
| M-E1 | 整块删除验证层的拒绝分支（退回"照样交给驱动"） | 拒绝行为锁 + 位置接线锁（锚串消失 ⇒ 位置锁红在"锚点缺失"，不是空比较） |
| M-E2 | 删掉"不带旗标才跳过"那一档（正常 skip 也吃拒绝） | 默认档锁（取证性锁的可证性就在这格） |
| M-E3 | 只改文案不改退出码（拒绝变 `exit 0`） | 拒绝行为锁的 rc 断言 |
| M-E4 | 把拒绝点挪到依赖体检之后 | **只有**位置接线锁能看见（夹具把后端桩装齐 ⇒ 行为面 rc 与文案照旧） |
| M-E5 | 决策层只恢复 `--force` 的 case 臂 | 「不得复活」结构锁 + 同形锁（臂在 ⇒ 不再走未知旗标分支 ⇒ 「忽略未知旗标」那句消失） |
| M-E6 | 决策层恢复不可达档的早退分支（且不看旗标） | S 方案交给驱动锁 + 「不得复活」结构锁 |
| M-E7 | 摘掉 decider 对方案输入的 docs-only 短路 | 「两种形状都不产出 skip」锁（这正是 D5 声称的 tripwire 语义）；连带 S 方案锁 |

与初稿格子表的对应关系也要如实写：初稿 M-E4 那句"接线锁 + 归因锁两把必须一起红"被设计评审 i2 提出来后**否证**（夹具里后端齐备，挪位置只会红位置锁），现改为"位置锁单独红并说明为什么"；初稿没有 M-E7，它是 D5 被实测推翻之后新增的那一格。红集之间出现子集关系必须点名，不得写成"N 个变异红集互不相同"。

实测补记（同一趟驱动自己抓出来的两格）：第一版跑出 `非CAUGHT=["M-E4:MISSED"]` 与 `同集分组 [["M-E1","M-E3"]]` —— 前者是位置锁锚串不唯一（恒真锁），后者是一条用例混装两种不变式、先抛的断言遮住后面的。两处都按"改判据/拆锁"处理而非放宽变异，改完的终版是 7/7 CAUGHT、红集互不相同=yes。另记一次**并发污染**：被我 TaskStop "停掉"的驱动进程树其实活着，与新一轮同时改同一批文件，于是第一轮终版读数作废重跑；驱动从此自带单实例锁（锁文件 PID 存活即拒绝启动）。
