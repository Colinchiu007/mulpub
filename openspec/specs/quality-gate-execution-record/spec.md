# quality-gate-execution-record Specification

## Purpose
规定「每个 PR 的执行记录」凭什么被判定为已收口：每篇 `openspec/records/<分支名>.md` 必须带一张门禁表与一行 `远程同步`，**行的存在**是结构要求（任何推导档不得豁免），**行的收口**由主干历史现场推导而非人工回填——「哪个带 `(#NNNN)` squash 尾注的已合并提交最近一次把这篇记录带进主干」是 git 的一等事实，合并后可知、合并前必然不可知，因此无法提前伪写。本规格同时锁定推导所用的合并账本与归属映射**只允许一份实现**、不可用时的三档降级（断言通道 / 未证实档 / 整体停用并非零退出），以及净增拦截（合并前预写闭合词、声明 PR 与主干事实不符）。目的是把"补写一次不存在的证据"从交付链上彻底移除，同时让存量旧形态按兼容读原样放行。
## Requirements
### Requirement: 合并账本与记录归属只允许一份实现，取不到读数一律按未证实处理

系统 SHALL 提供唯一实现用于「由 git 现场推导合并事实」，至少导出：合并账本（PR 号 → merge SHA 与时间，只认 squash 尾注 `(#NNNN)$`）与记录归属映射（记录文件路径 → **最近一次**把它加入基线的提交）。取向必须显式：取最近一次而非首次，否则"删除后由另一 PR 重新加回"会被归给一次已不在主干历史里的交付。判据 SHALL 从该实现取值，MUST NOT 在判据内另写 git 解析，也 MUST NOT 自行枚举记录目录（文件集合只接受调用方传入的既有枚举结果，递归扫描会把 `_exempt/` 读进门禁域）。该实现在解析时 MUST 关闭重命名检测并关闭路径转义（`--no-renames`、`core.quotepath=off`）；`--no-renames` 的已知后果必须如实写明：**改名会把归属重指到改名那次提交**，而不是"解析不到"。

**任何取不到读数的分支（基线 ref 不可解析、git 命令失败、账本规模读数为 0）SHALL 使推导档整体停用并出声打印原因，退回断言通道判定（新形态标记那一篇按 2b 落未证实档）；MUST NOT 把"看不见账本"读成"已合并"，也 MUST NOT 把"看不见账本"读成"作者忘了登记"。**

#### Scenario: 归属与账本同源

- **WHEN** 判据需要判断某篇记录是否已随合并进入基线
- **THEN** 结论来自共享实现的同一次遍历，且现场打印账本规模（`MERGE-LEDGER prs=<n>`）作为"这一趟真的测过"的证据

#### Scenario: 账本不可用不得判绿

- **WHEN** 基线 ref 取不到或账本规模读数为 0
- **THEN** 打印推导档停用，并退回"只有状态列写明收口写法才算收口"的口径；未收口记录仍被判为欠账

#### Scenario: 改名会把归属重指到改名那次提交（后果必须如实声明）

- **WHEN** 某篇记录在后续提交中被改名或移动（`--no-renames` 下新路径会作为"新增"出现在改名提交里，实测成立）
- **THEN** 归属解析为**改名那次提交**，系统 MUST NOT 谎称"解析不到"或"检测得到"；收口结论仍成立（该文件确在基线上），但"哪次交付带它进来"已改变
- **AND** 若该记录声明了来源 PR，改名导致的不符 MUST 判红；未声明者只打印重指事实，不做拦截
- **AND** 记录文件名即分支名属本仓约定，改名本身是可禁止操作，MUST NOT 靠"归属会重指"来默认允许

#### Scenario: 派生档的文件集合必须来自同一份枚举

- **WHEN** 合并账本或归属映射自行枚举记录目录（递归遍历、`git ls-tree -r`、另写一份过滤）
- **THEN** 判红：文件集合 MUST 由调用方传入的既有 `listRecordFiles` 结果决定，共享实现内 MUST NOT 出现第二份目录扫描（实测教训：自建过滤会把 `_exempt/` 读进门禁域，使"缺行即红"被绕过）

### Requirement: 记录不得预写尚不存在的合并证据，且声明的归属与 git 事实不符时判红

系统 SHALL 拒绝两类"声明与事实不符"：

1. **预写**——该记录文件是本次变更集新增（基线上尚不存在），而状态列写了闭合词 ⇒ 判红。理由：一篇还没进主干的记录不可能已经"远程同步"，这正是断言通道无法分辨、改造前长期存在的缺口。
2. **归属不符**——该记录显式声明了来源 PR，而 git 推导出的"把它带进基线的 PR"与之不同 ⇒ 判红。该字段缺省时本条不参与判定（存量不动）。

#### Scenario: 合并前预写 PASS 变红

- **WHEN** 一个 PR 新增记录文件并把状态列写成 `PASS`，而该文件在基线上不存在
- **THEN** 判红并指明"该记录尚未进主干，不得预写已合并"

#### Scenario: 本次变更集新增的记录不得判成欠账

- **WHEN** 记录文件由本次变更集新增且状态列未闭合
- **THEN** 判为 byDesign（自己不能证明自己已合并），不拦截；该 PR 合并后同一条记录 SHALL 经派生通道自动收口，无需任何写回

#### Scenario: 声明 PR 与实际带入 PR 不符

- **WHEN** 记录声明来源 PR 为 `#A`，而基线上**最近一次**新增该文件的提交尾注为 `#B`
- **THEN** 判红并打印两个编号；不得静默择一

#### Scenario: 存量零漂移

- **WHEN** 改造合入后在同一条主干上重跑判据
- **THEN** 拦截集合与改造前逐篇相同，且记录文件的字节内容零改动；任何"改前绿→改后红"的新增拦截一律视为回归
