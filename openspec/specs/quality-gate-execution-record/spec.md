# quality-gate-execution-record Specification

## Purpose
规定「每个 PR 的执行记录」凭什么被判定为已收口：每篇 `openspec/records/<分支名>.md` 必须带一张门禁表与一行 `远程同步`，**行的存在**是结构要求（任何推导档不得豁免），**行的收口**由主干历史现场推导而非人工回填——「哪个带 `(#NNNN)` squash 尾注的已合并提交最近一次把这篇记录带进主干」是 git 的一等事实，合并后可知、合并前必然不可知，因此无法提前伪写。本规格同时锁定推导所用的合并账本与归属映射**只允许一份实现**、不可用时的三档降级（断言通道 / 未证实档 / 整体停用并非零退出），以及净增拦截（合并前预写闭合词、声明 PR 与主干事实不符）。目的是把"补写一次不存在的证据"从交付链上彻底移除，同时让存量旧形态按兼容读原样放行。
## Requirements
### Requirement: 合并账本与记录归属只允许一份实现，取不到读数一律按未证实处理

系统 SHALL 提供唯一实现用于「由 git 现场推导合并事实」，至少导出：合并账本（PR 号 → merge SHA 与时间，只认 squash 尾注 `(#NNNN)$`）与记录归属映射（记录文件路径 → **最近一次**把它加入基线的提交）。取向必须显式：取最近一次而非首次，否则"删除后由另一 PR 重新加回"会被归给一次已不在主干历史里的交付。判据 SHALL 从该实现取值，MUST NOT 在判据内另写 git 解析，也 MUST NOT 自行枚举记录目录（文件集合只接受调用方传入的既有枚举结果，递归扫描会把 `_exempt/` 读进门禁域）。该实现在解析时 MUST 关闭重命名检测并关闭路径转义（`--no-renames`、`core.quotepath=off`）；`--no-renames` 的已知后果必须如实写明：**改名会把归属重指到改名那次提交**，而不是"解析不到"。

**任何取不到读数的分支（基线 ref 不可解析、git 命令失败、账本规模读数为 0）SHALL 使推导档整体停用并出声打印原因，退回断言通道判定（新形态标记那一篇按 2b 落未证实档）；MUST NOT 把"看不见账本"读成"已合并"，也 MUST NOT 把"看不见账本"读成"作者忘了登记"。**

#### Scenario: 归属与账本同源

- **WHEN** 判据需要判断某篇记录是否已随合并进入基线
- **THEN** 结论来自共享实现的同一次遍历，且现场打印账本规模（`MERGE-LEDGER prs=<n>`）作为"这一趟真的测过"的证据

#### Scenario: 账本不可用不得判绿

- **WHEN** 基线 ref 取不到或账本规模读数为 0
- **THEN** 打印推导档停用，并退回"只有状态列写明收口写法才算收口"的口径；未收口记录仍被判为欠账

#### Scenario: 改名会把归属重指到改名那次提交（后果必须如实声明）

- **WHEN** 某篇记录在后续提交中被改名或移动（`--no-renames` 下新路径会作为"新增"出现在改名提交里，实测成立）
- **THEN** 归属解析为**改名那次提交**，系统 MUST NOT 谎称"解析不到"或"检测得到"；收口结论仍成立（该文件确在基线上），但"哪次交付带它进来"已改变
- **AND** 若该记录声明了来源 PR，改名导致的不符 MUST 判红；未声明者只打印重指事实，不做拦截
- **AND** 记录文件名即分支名属本仓约定，改名本身是可禁止操作，MUST NOT 靠"归属会重指"来默认允许

#### Scenario: 派生档的文件集合必须来自同一份枚举

- **WHEN** 合并账本或归属映射自行枚举记录目录（递归遍历、`git ls-tree -r`、另写一份过滤）
- **THEN** 判红：文件集合 MUST 由调用方传入的既有 `listRecordFiles` 结果决定，共享实现内 MUST NOT 出现第二份目录扫描（实测教训：自建过滤会把 `_exempt/` 读进门禁域，使"缺行即红"被绕过）

### Requirement: 记录不得预写尚不存在的合并证据，且声明的归属与 git 事实不符时判红

系统 SHALL 拒绝两类"声明与事实不符"：

1. **预写**——该记录文件是本次变更集新增（基线上尚不存在），而状态列写了闭合词 ⇒ 判红。理由：一篇还没进主干的记录不可能已经"远程同步"，这正是断言通道无法分辨、改造前长期存在的缺口。
2. **归属不符**——该记录显式声明了来源 PR，而 git 推导出的"把它带进基线的 PR"与之不同 ⇒ 判红。该字段缺省时本条不参与判定（存量不动）。

#### Scenario: 合并前预写 PASS 变红

- **WHEN** 一个 PR 新增记录文件并把状态列写成 `PASS`，而该文件在基线上不存在
- **THEN** 判红并指明"该记录尚未进主干，不得预写已合并"

#### Scenario: 本次变更集新增的记录不得判成欠账

- **WHEN** 记录文件由本次变更集新增且状态列未闭合
- **THEN** 判为 byDesign（自己不能证明自己已合并），不拦截；该 PR 合并后同一条记录 SHALL 经派生通道自动收口，无需任何写回

#### Scenario: 声明 PR 与实际带入 PR 不符

- **WHEN** 记录声明来源 PR 为 `#A`，而基线上**最近一次**新增该文件的提交尾注为 `#B`
- **THEN** 判红并打印两个编号；不得静默择一

#### Scenario: 存量零漂移

- **WHEN** 改造合入后在同一条主干上重跑判据
- **THEN** 拦截集合与改造前逐篇相同，且记录文件的字节内容零改动；任何"改前绿→改后红"的新增拦截一律视为回归

### Requirement: 收口行被人工改写为闭合词时判红，唯一正解是交给推导

系统 SHALL 强制「`远程同步` 收口不再由人写」这条约束：在本次变更集里，任一篇 `openspec/records/*.md` 的 `| 远程同步 |` 行**从非闭合状态被改成闭合词**（词表 `PASS` / `N/A` / `✅` / `已…` 与既有 Gate 2c 同源，MUST 复用同一份实现）时，判据 MUST 判红并点名该文件。

理由：该行的收口结论已由 `scripts/lib/merge-ledger.js` 按主干历史推导得出，人工改写**不改变判定**，只重新制造"合并后必须再开一次 PR"这个已被取消的结构性成本。实测禁令写入主干后 4 小时内仍有 4 笔此类 PR 合入，成因是并发会话的工作树带着旧口径分支——因此这条 MUST 是机械拦截，MUST NOT 只靠文档与记忆。

三条豁免缺一不可：

1. **迁移方向不拦**：把该行改成派生标记（`由门禁推导`）MUST NOT 判红——那是本机制鼓励的唯一正确改写方向；把锁设在这条路上会逼使用者绕过锁，一条逼绕行的判据比没有判据更糟。
2. **保持不动不拦**：本次 diff 未触碰该行即不参与判定；MUST NOT 因某篇历史记录曾手写闭合词而判红（存量 36 篇原样保留，只能随各自下次自然改动收敛）。
3. **旧载体不在扫描域**：`.quality-gates.md` 与 `scripts/gate-record-debt-ledger.json` 里**已存在**的历史行仍允许就地改写并同次销账——关闭旧账只有这条通道，封掉等于把旧账永远钉红。

判定域 MUST 是「`listRecordFiles` 的结果」∩「本次 diff 触碰的记录文件」，配对 MUST 在**同一文件内**完成，MUST NOT 要求行号对齐。取 diff MUST 用 merge-base 三点式（`base...head`）且 MUST `--no-renames`。

差量行的解析口径 MUST 显式声明，三条各自对应一种"静默漏判"形态：① 每行 MUST 先剥掉 `-` / `+` 前缀再过词表——原始行 `-| 远程同步 | …` 不匹配 `ROW_RE`（该正则锚在 `^\|`），漏剥前缀等于**整档全量漏判且不报错**；② `\ No newline at end of file` 这类以 `\` 开头的 git 元数据行 MUST 不参与配对；③ 「整删／整增」MUST 只由 `+++ /dev/null` 与 `--- /dev/null` 判定——git 对删除也写 `diff --git a/X b/X` 同名头，只看那一行会把"整删一篇记录"误读成普通修改，而删除档之所以存在正是因为配对会被拆到两个文件上。上述①③各有指名用例。

本条 MUST 同时封掉四个会让它退化为装饰的口子（每个都对应一种比被抓形态改动更少的绕法）：

1. **重复行**：单篇记录文件内 `| 远程同步 |` 行数 > 1 ⇒ MUST 判红。否则"追加一行 `PASS`、原 `PENDING` 行不动"同时绕过本判据与其他各档（删除侧无未闭合行 ⇒ 本判据不红；首行未闭合而文件已在基线 ⇒ 派生收口；`hasBlocking` 全空）。MUST NOT 以"既有重复检测会管这事"为由省略——那条检测统计的是旧载体的 `## ` 标题，与记录文件的表格行无关。
2. **围栏内的引用行**：diff 解析 MUST 按旧侧/新侧**各自**跟踪 ``` 围栏状态，围栏内的 `+`/`-` 行 MUST NOT 参与配对。记录文件天然会引用示例行来描述本机制自己，不隔离则正确迁移会被误红。
3. **派生标记的词边界**：`已` 是闭合前缀之一，故「已由门禁推导」这类自然措辞 MUST 被识别为派生标记而非人工闭合；MUST 在**同一份** `DERIVED_MARKER_RE` 实现内放宽，MUST NOT 另立词表。
4. **删除与改名**：非 `_` 前缀的记录文件在本次 diff 中被删除 ⇒ MUST 判红（改名在 `--no-renames` 下即以"删 + 增"呈现，必然落此档）。`_exempt/` 与 `_` 前缀文件不受此条约束——实测 main 上 10 笔记录删除全部属于该豁免路径。

bullet 侧 MUST 与表格行同判：只把 `- 保留门禁：… | 远程同步 <状态>` 从未闭合改成闭合词，同样是一次"为改写收口证据而开的 PR"，MUST 判红；MUST 复用既有 `CLOSED_DECL_RE`/`UNCLOSED_DECL_RE`，MUST NOT 新增第三份词表。

**取不到读数时 MUST 按未证实处理，MUST NOT 读成"没有回填"**：`baseRef`/`headRef` 不可解析、工作树态异常（不在仓库内）、`git diff` 自身失败，三种形态都要出声打印原因；CI 档 MUST 非零退出（判据停用不是通过），本机档 MUST 只出声不拦（浅克隆与无 `origin/main` 的本地克隆是合法使用形态）。两档各配独立用例，使"把不可用做成跳过"与"把不可用做成判红"各自指名变红。

**差量为空不属于"取不到读数"**。本 PR 没碰任何记录文件、以及 main push 上 `base == head`，都是 git **成功取回**的空集；判据初稿曾把"diff 为空"也列进未证实，实测那样会让 CI 在每一个代码 PR 与每一次 main push 上非零退出（当场用 `--base-ref=HEAD --head-ref=HEAD` 复现过该形态，正确读数是 rc=0）。但打印面 MUST 把三档分开，不得同形：`触碰记录=0`（测了，没碰记录）、`触碰记录=N`（测了，碰了 N 篇并逐篇判过）、`触碰记录=n/a`（没测到）。把工具的失明读成清白，是本仓「装饰性门禁」的同型；把仓库常态读成门禁故障，则是逼人给判据加 skip 开关的同型。

#### Scenario: 空差量与取不到不得同形

- **WHEN** 差量为空（本 PR 未触碰 `openspec/records/`）
- **THEN** 判据 MUST 正常判定并以 `触碰记录=0` 出声，MUST NOT 走未证实档；而取源失败时 MUST 打 `触碰记录=n/a`，两者在读数上可区分

红文案 MUST 给出不需要绕行的正解：不动那一行；要清理旧文案就改成派生标记；main push 回读的证据写在 **PR 评论**里而不是写回仓库文件（merge SHA 只在合并后存在，把它的读数要求落进文件会重新造出同一个循环依赖）。当红项可能来自 rebase 吸收的他人行时，文案 MUST 给出自证路径（`git log -p -- <file>`），MUST NOT 默认断言"你就是回填"。

**净 diff 的已知不可见形态**（如实记为边界，不假称已闭合）：三段式「闭合→未闭合→闭合」在 `base...head` 下坍缩为"闭合→闭合"，本条不拦；派生模型下手写闭合词无判定力，唯一例外是账本不可用的回退档仍读状态列。

#### Scenario: 合并后手写 PASS 判红

- **WHEN** 某篇记录的 `| 远程同步 | PENDING |` 在本次 diff 中被改成 `| 远程同步 | PASS | <merge SHA> |`
- **THEN** 判据判红并点名该文件，文案写明该行现由主干历史推导、不需要人工改写

#### Scenario: 改成派生标记不红

- **WHEN** 同一行被改成 `| 远程同步 | 由门禁推导 | …`
- **THEN** MUST NOT 判红；这是本机制鼓励的唯一正确改写方向

#### Scenario: 别人合入的改写不得算到我头上

- **WHEN** merge-base 之后有另一个 PR 把**另一篇**记录的该行改成闭合词，而本 PR 只改自己那篇
- **THEN** 本 PR 的红集 MUST 只含自己那篇（若自己那篇未做该跃迁则为空）；该断言 MUST 由构造出"base 之后另有合入"的夹具证明，MUST NOT 由推理放行

#### Scenario: 旧载体销账通道保持可走

- **WHEN** 一个 PR 就地改写 `.quality-gates.md` 里已存在的历史行并同次删除 ledger 登记项
- **THEN** MUST NOT 因本判据判红；若同一 PR 又顺手把某篇新记录的收口行改成闭合词，则红文案 MUST 点名那一篇，让合法部分可被拆出

#### Scenario: 取不到读数不得判绿

- **WHEN** CI 档下 `baseRef` 或 `headRef` 解析失败、或 `git diff` 报错
- **THEN** MUST 非零退出并打印未证实原因；本机档 MUST 只出声不拦
- **AND** 两档各有一条独立用例，实现把"不可用"做成"跳过检查"时 MUST 指名变红

#### Scenario: 打印且阻断

- **WHEN** 本判据产出红项
- **THEN** 结论 MUST 同时出现在打印面与 `hasBlocking` 出口；只打印不参与判定的形态 MUST 被用例拦下
