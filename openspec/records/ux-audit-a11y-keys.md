## 同 PR 续做：第二把 a11y 棘轮 —— label/legend 未关联（4.3 / audit-50）

放同一分支的理由：两把都是"无障碍维度上肉眼与像素都看不见"的存量棘轮，同一批接线可以少占一轮
required-check 队列（本仓 CI 队列当天已被多会话压满，每轮 25 分钟起）。代价是 PR 标题必须改，
已同步为「两把 a11y 棘轮」。

- **判据取自 HTML 规范而不是风格偏好**：只有两种合法关联 —— ① 显式 `for`/`:for`/`v-bind:for`（
  **空串与纯空白都算失效关联**）；② capturing label：`<label>` 的后代里有**原生** form-associated 元素。
  `<el-input>`、`<UiField>` 这类自定义组件**不算**（解析期不可知它渲染什么），必须补 `for`。
- **第一版就被自家用例抓出的"写宽"**：词表最初写成 `/\b(input|select|…)\b/i`，
  而 `-` 是非词字符 ⇒ `<el-input>` 里的 `input` 命中词边界，被当成原生控件。
  这条判据在真实仓上会从"抓 139 处"退化成"几乎没问题"，而**读起来完全像通过**。
  现按**开标签形态**匹配 `/<(input|select|…)\b/i`，并由用例 ② 与"词表不得含 `el-`"的禁令
  +「词表必须真能匹配 `<input>`」的正向对偶三处钉住。
- **现场读数**：全域 `label/legend=275`，未关联 `139 处 / 25 文件`，标签解析未闭合=0，`违规=0 PASS`。
  与 audit-50 报的「134 个」是同一现象在两个时点的读数（差 5 处来自存续期间新增），
  基线由 `scan()` 自产、`totalLabels` 作为分母一并入基线并被用例 ⑦ 钉住
  （**分母变了说明扫描域或解析式变了**，只比分子会让"域缩水"伪装成"债务下降"）。
- **回归锁 8 例**：显式 for 三写法与两种失效值 / 原生控件隐式关联三形态 / `<el-input>`、`<UiField>` 必须判红 /
  词表形态禁令**加正向对偶** / 属性值里的 `>` 不得截断标签（带 `total=1` 的解析自证与 `unclosed=0`）/
  注释不计数 + 跨行 + 嵌套控件 / `readTag` 引号状态机 / 真实仓对账（分子、分母、文件数、清单陈旧）/
  基线 JSON 形状（含"基线必须自带计数口径说明"，否则下一个会话只能猜 139 怎么来的）。
- **反证 5 条各自指名变红、跑后判据文件 md5 逐字节还原**：
  L1 词表退回宽形态⇒只红②；L2 `forVal.trim()` 退回 `!!forVal`⇒只红①；L3 不剥 HTML 注释⇒只红⑤；

## 刻意没做的事（这是本批最重要的一条诚实记录）

1. **没有把 47 处索引 `:key` 一把改成稳定键。** 逐处改需要判断"这一份列表的稳定身份字段是哪个"
   （`rows` 有 `id`、`titles` 是字符串数组可能有重复、`contextEntries` 只有下标……），
   那是**每页各自的语义裁决**；把 47 处机械改写和"这条判据有没有牙"混成一次变更，
   归因会互相污染，而且 `CreateView.vue`（9 处）/ `Accounts.vue` / `ProductionBoard.vue` 等
   是他人会话正在改的热文件。本批交付的是**类级防线**（存量只可缩小 + 风险档新增即红），
   收敛动作留给按页的后续批次。
2. **风险档 6 个文件（`:key` 用索引 + 同文件有 `.splice/.shift/.pop/.unshift`）不在基线里给豁免通道**：
   `NEW_RISK_FILE` 判红且**不得登记进基线**——这类组合是真会掉数据状态的缺陷面，
   允许登记等于把判据改成"只统计不拦"。要把某文件从这个档里摘掉，唯一路径是**改代码**。
   现存 6 条是**历史存量**（基线生成时一次性登记，随收敛只可缩小）。
3. **没有把对象遍历的第二形参从判据里摘掉**。`v-for="(v, k) in obj"` 的 `k` 是稳定属性名、不是索引，
   但静态解析无法区分"数组的第二位"与"对象的第二位"。判据取**过判**（口径 ③），
   理由是：过判只多花一次人工确认，漏判要靠下一个作者自觉；被误判时的正解是改用更强的键（`v.id`），
   而不是放宽判据。这一条写在文件头注释里而不是藏在实现里。
