### 第一性原因（QM-5 ①）

`check-pr-exec-record.js` 里「合法出路④（纯回填）」的判定是 `AUDIT_ARTIFACT_RE.test(file)`，
而它的**提示文案**另写了一遍「`.ccg/reviews/<40 位小写十六进制>.json`」。
2026-10-16 的 #3755 把判据从「只认 40 位」放宽为「**40 或 64 位**」并新增
`-again-<40sha>-<ISO>` alt 形态，**只改了正则与它上方的代码注释，没改这条用户可见文案**。

于是形成两处独立可漂移的真源：判据说 40|64，文案说 40。
后果是具体的：按提示排障的人会认为「64 位记录不算纯回填」，
从而把**真实满足④**的 PR 判成「未携带执行记录」，转而去加一份本不需要的记录文件。
（这正是我自己在 #3772 上实际遇到的困惑：先按文案排除④，才发现 64 位其实被接受。）

### 修复 + 回归保护（QM-5 ④）

**修复**（`scripts/check-pr-exec-record.js`，文案 3 行）：

**回归保护（1 条派生锁，不是抄数字）**：
`遗留收口：提示文案声称的位宽/形态必须与 AUDIT_ARTIFACT_RE 实际接受的完全一致`

它是**派生**的：从 `AUDIT_ARTIFACT_RE` 的字面量里算出它接受哪些位宽
（`[...RE_SRC.matchAll(/\[0-9a-f\]\{(\d+)\}/g)]`），再从提示文案里抽出它**声称**的位宽，
断言两组**完全相等**（双向：少了会误导，多了会让人以为存在那种形态）；
正则含 `-again-` 时文案也必须提到它。
另含**行为核对**：声明的每个位宽必须真的能过正则、且紧邻位宽必须真的过不了，
专治「声明 64 但正则写成 `{6}4`」这类**字面对、语义错**。

### 防止再次发生（QM-5 ⑤，汇总）

1. **单一真源由构造保证，而不是由锁监督**：文案里的位宽/alt 说明由 `describeAuditWidths()` 与
   `auditAcceptedAltForm().description` 生成，源码里不可能存在第二处手写。锁只兜「有人绕过生成器」。
2. **判据必须从行为派生，不从字面解析**：位宽集合由「在 8..200 位上逐个试 `AUDIT_ARTIFACT_RE`」得出。
   等价改写（`{40,64}`、`.{40}`、`(?:[0-9a-f]{8}){8}`、加 flags）一律免疫 —— 变异 **M33** 是这条的反证。
3. **可复用判据**：凡「判据 + 面向人的说明」两处描述同一组约束，必须由判据**生成**说明；
   若只能交叉核对，就必须把说明的每个可变维度（宽度、后缀、格式）都由探测得出，不得留硬编码字面量。
4. **接线的判据要锁「值被使用」而非「函数存在」**：`+ describeAuditWidths()`（拼接形式）
   而不是 `/describeAuditWidths\(`（后者被函数定义与导出行满足 —— 这是 M32 暴露的真缺陷）。
