## 1. 上一轮的前提被推翻：参考视频不需要公网上传基建

上一轮把「参考视频」设想成必须走**公网素材托管**（OSS PUT）。重新核算后前提不成立：

- 参考视频**时长受限**（官方 2–12 秒）⇒ 短片 base64 后体积可控；
- 单请求上限 50MB ⇒ 一个 ≤20MB 的参考视频（base64 后 ≈27MB）仍有余量；
- 与仓内既有做法一致（`film-engineering` 的「本地图片 → dataURL → provider 参考输入」）。

⇒ **先按 Data URI 交付**，零新基建。若上游拒收，改动点只有 `pushVideos` 的输出形态。

## 2. 能力门控用属性，不写模型名单

参考视频上传位是否出现，由当前模型的 `supportsReferenceVideo` 决定 —— UI 里**没有一行模型名**。非 Flash 一旦被选中就自动出现，Flash 选中就自动不出现。

## 3. 成本可见（这是本 change 里最有产品价值的一条）

官方计费口径是「输出秒数 + **输入视频秒数**」相加。8 秒输出 + 3 秒参考视频 = 11 秒 × ¥0.15 = **¥1.65**，比不带参考视频的 ¥1.20 **多 37%**。

- 现行价 ¥0（Flash 限时免费）⇒ 显示「限时免费」，**不显示 ¥0.00**；
- 有参考视频 ⇒ 追加「其时长另计」。

**为什么不给总额**：参考视频的**时长客户端读不到**（需 ffprobe，主进程才有）。给一个偏小的总额比不给更危险 ⇒ 只给「可确定的输出部分 + 明确的另计说明」。

## 4. 能力与端点解耦

官方标注非 Flash「已在国际站上线」，而本仓 `agnes-multimodal` 的 base_url 是中国站。模型暴露**不绑定端点** —— 端点仍由用户在「模型设置」里配置（既有能力）。这样「模型是否可用」由用户自己的 key/端点组合决定，不在代码里替用户猜。
