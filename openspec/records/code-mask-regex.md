### ① 第一性原因（QM-5 ①）

`scripts/lib/code-mask.js` 的 `maskNonCode` 只识别三种词法形态：**行注释 `//`、块注释 `/* */`、引号字符串**。
它**没有正则字面量（`/.../flags`）的识别**。

于是 `const re = /["']/g` 里的 `"` 被当成字符串起点，扫描器一路扫到下一个引号 ——
**中间整段代码被当作"字符串内容"掩成空白**。

引入点：第三批把 `maskNonCode` 从两批锁里抽成共享库（commit 见 `#3845`）时，
抽取范围是「两批旧实现的并集」，而两批旧实现**都没有**正则识别 —— 缺陷被原样继承，
并在抽成"所有锁的公共底座"后**影响面从 2 条锁扩大到 8 条**。

| 等价性断言 | **等价 ≠ 正确**。两批旧实现都错，抽库后"等价于两个错的东西"当然全绿。这是本次最核心的教训 |

### ④ 修复 + 回归保护（QM-5 ④）

**修复**：`maskNonCode` 增加正则字面量识别，两个新函数：

- `scanRegexEnd(src, open)`：从起始 `/` 扫到结束 `/`，正确处理**转义 `\/`**、
  **字符类 `[/]`（类内 `/` 不结束）**、**flags**；遇未转义换行返回 -1（正则不能跨行）
- `isRegexStart(src, i)`：`/` 是正则还是除号，靠前一个有效 token 判断。
  **白名单是闭集**，默认按**除号**处理（宁可漏判正则 = 回到修复前行为，
  也不要把除法/HTML 片段误判成正则 = 吃掉大段代码）

正则**内容保留**（不掩）：L1 转义表锁依赖字符类原文（`replace(/[&<>"']/g, c => MAP[c])`）；
仅把正则内部的 `{` `}` 掩成空白，避免 `/\d{4}/` 干扰 `matchBrace` 配对。

**两次实测把白名单钉出来**（缺一条就回归）：
