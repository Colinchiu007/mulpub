### 这条 PR 为什么存在

上一轮（#3909）修完正则字面量后，`code-mask.js` 还剩一个系统性缺口：**嵌套模板串**。
它是那轮两次回归的共同根源，所以我按「先量化再动手」先做侦察 —— **结论是不修**。
这个"不做"的结论本身有产出价值：**每轮会话都会想修它**（它写在已知限制里），
不留下量化证据，同一个无用功会被反复做一遍。本 PR 把决策与数据钉进代码注释。

### 侦察 → 量化 → 决定（三步全部实测）

| 步骤 | 读数 |
| --- | --- |
| ① 影响面 | 含嵌套模板串的文件 **25~27 / 3107**（0.8%），嵌套总数 34，可见率中位 0.61（全库 0.69）|
| ② 真实收益 | 与旧实现逐文件 A/B：**可见字符增加 0** —— 没有一个文件因此少看见代码 |
| ③ 精确方案上限 | 全部模板串 `${}` 内可见字符 106,825 = 全库可见 **0.77%**；其中嵌套文件只贡献 **0.077%** |

②的归因：本轮的正则判定**已排除 `<`**（那正是 #3909 为了让 `</p>` 不被误判而做的取舍），
嵌套截断后内层 HTML 片段不再被误跳过；而真实仓的内层模板串恰好不含「撇号 / URL」形态。
只有当内层含撇号（开字符串）或 URL（开行注释）时才会真吃代码 —— 那是构造形态，真实仓为零。

### 实际试修了一版并撤回（记录证据，不是没试）

先实现的方案是「正确找模板串边界 + **整体掩掉**（含 `${}` 表达式）」，保留旧语义。
结果：**0 增益 + 1 回归** —— `packages/ai-autonomous-tester/src/verifier/requirements-verifier.js`
可见字符**减少**（因为整体掩把 `${}` 里的表达式也掩了，而截断原状态偶然让它们可见）。

据此撤回，改为把决策写进注释。若将来真出现被吃掉的文件，A/B 会显示可见字符**下降**，
届时按「精确掩码」（只掩字符串段、保留 `${}` 表达式）重做。

### 顺带产出的一条夹具纪律（已写进注释）

第一版夹具（纯 HTML 片段嵌套 6 例）**全绿** —— 因为 `<` 已被排除，把嵌套的后果掩盖了。
夹具必须先证明「修复前必红」，否则它只是把当前行为拍下来当契约。
能红的形态：内层模板串含撇号或 URL。重写后 **1 例真红**，证明缺陷存在且夹具有效。
