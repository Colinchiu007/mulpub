fix(desktop): rebase 手写冲突解决时把 expandedSegmentId 的 '' 改成了 null，改回 main 语义

## 怎么发现的

CI `QG Desktop Shards (1/2)` 红，`Failed Tests 2`，两条都来自 main 既有的
`ResultSegmentEditor.test.js`（本轮没有改这个测试文件）：

```
AssertionError: expected null to be ''   // Object.is equality
 ❯ src/views/video-creation/ResultSegmentEditor.test.js:91:36
```

## 根因

rebase 到最新 origin/main 时 `ResultSegmentEditor.vue` 有冲突：main 带进了
「分段编辑主体默认收起 + 展开互斥」三个方法（`isSegmentEditorExpanded` /
`toggleSegmentEditor` / `onRemoveSegment`），我方在同一位置新增了 `clearFilters`。
我在手工拼接时**按语义重打了一遍 main 的方法体**，把收起态写成 `null`，
而 main 的 `data()` 默认值与两处赋值用的都是空字符串 `''`。

`''` 与 `null` 在这段代码里不等价：`expandedSegmentId: ''` 是「没有展开项」的哨兵值，
`isSegmentEditorExpanded` 用 `Boolean(segmentId) && ...` 判活，两者在运行时看起来都能工作，
但既有测试直接断言 `expect(w.vm.expandedSegmentId).toBe('')` —— 它是**状态哨兵值的契约锁**，
不是冗余断言。手写重打把契约改了，测试当场抓住。

## 修法

逐字对齐 main：`? '' : segmentId`、`= ''`。不改测试（测试断言的是既有契约，改它等于改契约）。

## 教训（已写进 record 踩坑）

**解决冲突必须逐字复制对方的方法体，不要按语义重打**——重打会静默改掉「默认值/哨兵值/边界字面量」
这类测试看得见、代码跑得动的东西。rebase 后的本地快检必须包含**被改文件的既有测试**，
本轮只跑了 ResultView 相关的那几个文件，漏了同目录的 `ResultSegmentEditor.test.js`。

验证：`ResultSegmentEditor.test.js` + ResultView 两个 + ResultSegmentCard 共 158 passed。
