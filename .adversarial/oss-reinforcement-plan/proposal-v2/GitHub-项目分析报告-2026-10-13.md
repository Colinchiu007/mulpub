## 二、深度项目分析（7 个，源码级）

### 2.1 patchright（Kaliiiiiiiiii-Vinyzu，4.8k⭐，Apache-2.0）— 反检测补丁工程范本

**是什么**：对 Playwright 源码做 ts-morph AST 改写的补丁集（36 个 patch 文件），产出 undetected Playwright。social-auto-upload 的抖音 uploader 直接依赖它。

**核心补丁源码实证**（`driver_patches/`）：

| 补丁文件 | 改什么 | 消除的检测面 |
|---------|--------|------------|
| `chromiumSwitchesPatch.ts` | 从启动参数**删除** `--enable-automation` 等 ~19 个开关（还有 `--disable-popup-blocking`、`--disable-component-update`、`--disable-extensions`、`--disable-client-side-phishing-detection`、`--allow-pre-commit-input`…） | `--enable-automation` 是 CDP 模式下 `navigator.webdriver=true` 的根因；其余开关组合是指纹库常用判据 |
| `javascriptPatch.ts` | `JSHandle.evaluateExpression` 增加 `isolatedContext` 参数：`isolatedContext ? frame.utilityContext() : frame.mainContext()` | 自动化脚本默认在 main world 执行会被页面检测；utility world 是浏览器扩展用的隔离上下文 |
| `crExecutionContextPatch.ts` | 新增 `findFunctions`：先 `Runtime.evaluate('(()=>{})')` 取 literal → `getProperties` 找 `[[Prototype]]` → `queryObjects` 遍历原型链上的函数句柄（仅匹配 `/^f[0-9a-f]{32}$/` 命名） | 替代 `Runtime.callFunctionOn` 这类可被 `Page.addScriptToEvaluateOnNewDocument` 钩子探知的模式 |
| `browserContextPatch.ts` | Playwright 自带的 serviceWorker 注册 init script 替换为 `navigator.serviceWorker.register = async () => {}`；修补 `exposeBinding` | Playwright 注入的 init script 本身是检测指纹（页面可枚举 script 内容 hash） |
| `chromiumPatch.ts` | 强制 `--headless=new`；删除 `--enable-unsafe-swiftshader` | 旧 headless 的 WebGL/渲染特征差异 |
| `networkPatch.ts` | 保存 raw request headers 原始顺序（`_rawRequestHeaders`），不过滤不改序 | header 顺序是 TLS/HTTP2 指纹的一部分 |
| `crPagePatch.ts` | 用 network manager 直接拦截替换 legacy updateRequestInterception；custom script tag id | 拦截链路本身的时序特征 |

**对本项目的精确意义**（F2）：
- 我们的 RPA 通道 = `BrowserWindow`（Chromium，非 Playwright 启动）+ `executeJavaScript`（内部走 CDP `Runtime.callFunctionOn`）+ CDP `DOM.setFileInputFiles`。逐个对照：
  - Electron BrowserWindow 默认**不带** `--enable-automation`（我们的 `navigator.webdriver` 掩盖是双保险，保留）
  - `executeJavaScript` 走 main world → **可移植 isolatedContext 思路**：评估能否改走 `webFrame.executeJavaScriptInIsolatedWorld`（Electron 有该 API！）——与 patchright 的 utilityContext 同解
  - 文件上传 CDP 调用有独立时序特征 → 参考 crPagePatch 的链路思想
- **结论：F2 = Electron 侧 CDP 调用面审计 + isolatedWorld 迁移 + webdriver 双保险，不引入 patchright 依赖**（它是构建期补丁 Playwright 源码的，我们不用 Playwright 驱动发布；playwright-manager.js 已被旁路）

### 2.2 social-auto-upload（dreammis，15.4k⭐，MIT）— 同域产品级参考

**架构**（源码实证）：`uploader/<platform>_uploader/main.py` 12 平台 uploader（douyin/ks/tencent/xhs/xiaohongshu/bilibili/baijiahao/alipay/hupu/tk/weibo/youtube）+ `base_video.py` 基类 + `myUtils/auth.py` + `sau_backend.py` FastAPI + `sau_frontend` Vue + `skills/*/SKILL.md` Agent 分发 + `db/createTable.py`。

**核心实现实证**：

1. **stealth 基线 = puppeteer-extra-plugin-stealth 的提取版**：`utils/stealth.min.js` 180KB，文件头实证「Generated by: berstend/puppeteer-extra/tree/master/packages/extract-stealth-evasions, License: MIT」，经 `set_init_script` 的 `context.add_init_script(path=stealth.min.js)` 注入。**这与本项目 url-collector 用的是同一个 evasion 包**——差别只在：它注入了 RPA 发布 context，我们只注入采集 context。
2. **真人级事件序列**（douyin `_native_click`，源码实证）：`locator.scroll_into_view_if_needed` → `bounding_box()` → `page.mouse.move(x,y)` → `asyncio.sleep(0.15)` → `page.mouse.click` → `sleep(0.2)` → `page.evaluate` 补派 `pointerover/pointerenter/pointerdown/mousedown/pointerup/mouseup/click` 全套（`bubbles/cancelable/composed/clientX/clientY/pointerId/pointerType/isPrimary/button/buttons` 全字段）。注释原文：「抖音身份验证组件（uc_verification_component）只认这整套事件，不认单纯 click」。
3. **cookie 有效性判据**：`context.new_context(storage_state=文件)` → 导航创作者中心 → `wait_for_url(timeout=5000)` → 探「扫码登录」文本（5s 内出现=失效）。与项目 `login-status-monitor` 的 `hasPlatformSessionCookie` 判据互补（它是 URL 判据、我们是 cookie 判据）。
4. **发布参数校验**（`base_video.py`）：视频扩展名白名单 8 种/图片 5 种；`MIN_SCHEDULE_LEAD_TIME = 2 小时`（定时发布最早提前量）。

**对本项目意义**：F1 的 stealth + 行为两层的完整配方（它两层都有）；平台覆盖差距（支付宝生活号、虎扑）。

### 2.3 ddddocr（sml2h3，14.8k⭐，MIT）— 验证码即插即用

**架构**（v1.6.1 源码实证）：`core/` 四引擎分离 —— `OCREngine`（通用文字）、`DetectionEngine`（目标检测）、`SlideEngine`（滑块）、`BaseEngine`；`api/` 是独立 FastAPI 应用（`create_app/run_server`）+ **MCP 模块**（`api/mcp.py`）；`models/` 模型加载；`preprocessing/color_filter`；`utils/`（image_io/validators/exceptions）；`compat/v1` 老 API。

**核心算法**（`slide_engine.py` 实证）：`slide_match(target, background, simple_target)` → cv2 灰度化 → `simple_target ? _simple_template_match : _edge_based_match`（边缘匹配走 Canny 类边缘检测 + 模板匹配）→ 返回缺口坐标 dict。输入支持 bytes/路径/PIL 三种。

**HTTP 端点**（`routes.py` 实证）：POST `/initialize` `/switch_model` `/toggle_feature` `/ocr_recognition` `/object_detection` `/slide_match` `/slide_comparison`，GET `/status` `/health`，全局异常处理器。

**对本项目意义**（F4）：**零改代码集成**——pip 装 `ddddocr`（或直接 clone 其 api/server.py）作为 python-backend 托管进程，RPA 检测到验证码 → 截图经 IPC 送 sidecar → 调 `/slide_match` 得缺口 x → CDP 派发 F1 的真人拖拽。频控与人工兜底按项目铁律自建。

### 2.4 CloakBrowser（CloakHQ，32.1k⭐）— 许可证重大修正 ⚠️

**v1 错误**：只看到 wrapper LICENSE = MIT。**源码复审发现 `BINARY-LICENSE.md`（v1.3, July 2026）**——编译后的 Chromium 二进制是**专有许可**：
- 最新 major 版本下载需**付费订阅**
- **禁止**再分发/修改/反编译/删除声明
- 「OEM/SaaS license required when the Binary is bundled, embedded, exposed through an API, or used to **provide browser functionality to third-party customers**, including as part of a product, hosted service… or customer-facing workflow」
- 唯一豁免：「end users download the Binary directly from official CloakHQ channels」的 dependency listing 不算分发

**对 Multi-Publish 的判定**：产品把隐身浏览器能力作为功能给终端用户 = 命中 OEM/SaaS 条款 → **需商业授权谈判**。技术仍是标杆（87 个 C++ 源级补丁 + `human/` 行为引擎），但落地路径变为「联系 CloakHQ 谈 OEM，或放弃」。

**可无损移植部分**（wrapper 源码 MIT）：`cloakbrowser/human/mouse.py` 的鼠标轨迹算法（源码实证）：三次贝塞尔曲线 `_bezier(p0,p1,p2,p3,t)` + 随机控制点 `_random_control_points`（垂直方向 ±0.3×dist 偏置）+ `_ease_in_out` 缓动 + 步数 `clamp(dist/divisor)` + burst 节奏 + wobble 微颤。**F1 直接移植该算法**（纯数学，无许可问题）。

### 2.5 camofox-browser（jo-inc，11.5k⭐，MIT）— 替代方案，许可干净 ✅

**架构实证**：`@askjo/camofox-browser` 1.18.1，bin 提供 CLI + MCP server；`postinstall.js` 装包时调 `downloadBundledCamoufox()` 把 Camoufox 二进制下到**用户本机缓存**（win32: `%LOCALAPPDATA%\camoufox\camoufox\Cache`）；**失败仅 warn**（受限环境可后补 `npm run fetch-bin`）；`CAMOUFOX_EXECUTABLE*` 三个环境变量可指外部二进制；依赖 `camoufox-js`（MPL-2.0，作未修改依赖可商用）。

**许可链**：wrapper MIT + camoufox-js MPL-2.0（未修改使用OK）+ Camoufox 本体 MPL-2.0（Firefox fork，二进制分发义务在上游）。**无 CloakBrowser 的订阅/OEM 问题**。

**对 Multi-Publish 意义**（F3 改选此）： electron 主进程 spawn `camofox-browser` server → CDP/WebSocket 驱动 Firefox 内核隐身实例 → 仅高风控平台发布走该通道。与 Electron Chromium 生态（WebContentsView/partition）不同内核，必须作为**独立 sidecar 窗口**（不走 rpa-view-manager 池），复用 F1 的行为层。内置代理轮换 + MCP + openapi.json 省事。

### 2.6 SmartSub / 妙幕（buxuku，5.6k⭐，MIT）— 本地媒体管线架构范本

**引擎契约**（`main/helpers/engines/types.ts` 实证）——与我们的 model-provider-manager 可 1:1 对照：
```typescript
interface TranscriptionEngineAdapter {
  id; displayName; requiresRuntime: boolean;
  pyEngineId?: PyEngineId;        // Python sidecar 归属（warmup/切换）
  isAvailable(): Promise<EngineStatus>;
  transcribe(ctx: TranscribeContext): Promise<string>;
  cancelActive(): void;           // builtin=signal no-op / faster=sidecar 取消 / localCli=kill child
  prewarm?(formData): void;       // 预启动，失败仅告警不阻塞
}
```
`registry.ts`：adapters 数组注册（builtin/fasterWhisper/funasr/qwen/fireRed/parakeet/localCli/cloudAsr），`resolveEngineIdForTask` 缺省 builtin。**provider 管理**：`asrProviderManager.ts` + electron-store 持久化 + `assertProviderList` 运行时校验；注释实证「第三方 provider 用户没有配置时不会自动初始化」（懒初始化，与我们的按需 provider 同思路）。

**模型下载器**（`modelDownloader.ts` 实证）：断点续传状态 `model-download-state.json`（含 url/tempPath/downloaded/total/startedAt）+ `downloadFileParallel` 并行分片 + `RangeNotSupportedError` 降级 + **`getHfHost()` HF 镜像配置**（国内可下）+ `decompress` 解压 + `isAppleSilicon` 分支 + 超时三档（INACTIVITY 60s / CONNECT 30s）+ 进度广播 `ModelDownloadProgress{status,progress,downloaded,total,speed,eta,error}`。

**对本项目意义**（F5/F6/F7）：契约直接抄（适配我们的 provider 注册表）；下载器模式抄（抄成 `speech-model-manager.js`）；多引擎 = builtin(whisper.cpp) / faster-whisper sidecar / 云 三档思路。

### 7.2 重点新候选分析

#### 7.2.1 impers / curl_cffi —— TLS 指纹层（v2 完全没覆盖的面）

**背景**：百家号/头条/B站的 HTTP API 风控不只查 cookie/header，还查 **TLS ClientHello 指纹（JA3）**。Node 原生 https 模块的 JA3 与 Chrome 迥异（密码套件顺序、扩展、ALPN），协议轨 API 发布在 B站/百家号上被 403 风控时，JS 层再像也没用。
**impers**（MIT，TS）是 curl_cffi 的 Node 绑定——通过 libcurl-impersonate 在二进制层伪装 Chrome 的 TLS/HTTP2 指纹。**落点**：`packages/api-publish-engine` 的 axios/fetch 出口按平台切换 impersonating client（仅风控平台开启，普通平台走原生，避免新增原生依赖面）。
**风险登记**：原生二进制（libcurl）进生产依赖闭包——按项目「生产依赖闭包」纪律需 `npm pack --dry-run` + 隔离安装验证；体积增大可接受（~10MB）。

#### 7.2.2 whisperX —— 词级时间戳，补 audio-aligner 的精度缺口

BSD-2-Clause。whisper large-v3 + wav2vec2 强制对齐产出**词级时间戳** + pyannote 说话人分离。本项目 `packages/audio-aligner` 目前的对齐精度未经验证——F5 落地时以 whisperX 输出为金标准做 A/B，落后则切。分离能力还能服务 F10（多说话人直播录音分流）。

#### 7.2.3 Kokoro-82M（JS）—— F6 的意外之喜

Apache-2.0 的 **纯 JS/ONNX TTS**（hexgrad/kokoro 仓库 + kokoro-js npm 包，82M 参数，CPU 实时）。这条线的意义：**F6 可以不引任何 Python/二进制 sidecar**——`onnxruntime-node` + Kokoro 模型文件（~350MB）就能在 Electron 主进程直接跑 TTS，安装包和运维复杂度远低于 GPT-SoVITS 路线。另有 `blankarrayy/ttsbro`（Apache-2.0）实证 sherpa-onnx + Kokoro 可以纯 WASM 跑。**修正 F6 分层**：
- 轻档（默认）：Kokoro-82M JS + onnxruntime-node（Apache-2.0/MIT）
- 重档（可选）：GPT-SoVITS（MIT，1 分钟克隆）sidecar
- XTTS-v2：**排除**（权重 CPML 禁商用，代码 MPL 也救不了权重）

#### 7.2.4 yt-dlp / BBDown —— 回流与素材采集的下载底座

yt-dlp 197k⭐ **Unlicense = 公有领域**：可自由打包分发、无署名要求、无 copyleft。用途：①F10 数据回流时下载自己的发布作品做存活/状态自证；②collection-engine 的视频 URL 素材采集（百家号/头条/B站解析）；③story2video 的素材来源。形态：作为 media-tools 同款二进制捆绑（已有 ffmpeg 纪律直接适用，注意 yt-dlp 是 nightly 签名发布，锁定版本+sha256）。BBDown（MIT）作 B站专用备份——B站风控规则变化快时双源切换。node-ytdl-core 停更中，不选。

#### 7.2.5 proxy_pool / BotBrowser —— F3 的两个配套件

- proxy_pool（MIT，23.8k）：camofox 内置代理轮换满足不了的场景（需要大规模 IP 池）自建；注意其抓取源头的合规性自持
- BotBrowser（MIT，2.6k，2026-10-12 活跃）：统一指纹防御的浏览器核心，对 DataDome/Kasada 等企业风控有明确覆盖——**F3 通道选型的第三备选**（camofox 主选、CloakBrowser 授权后升级、BotBrowser 备胎）
- seleniumbase UC mode（MIT）：`undetected-chromedriver` 的成熟封装+验证码点击处理管线——F1/F2 的对照实验组（同一任务在三个栈上跑通过率对比，数据驱动选型）
- douyin_sign（Apache-2.0，77⭐小仓库）：抖音 web 签名算法——api-publish-engine 若未来加抖音协议轨，签名是必需件；**低优先且需风险标注**（签名算法属于灰产边缘，仅用于自己账号的已授权 API）
