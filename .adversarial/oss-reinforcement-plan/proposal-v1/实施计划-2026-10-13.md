## 批次 B1：RPA 反检测与验证码（第 1-2 周）

> worktree：`mp-oss-rpa-hardening`。PRD：`01-docs/PRD-OSS-RPA-HARDENING-2026-10-XX.md`

### F1：RPA 窗口 stealth + 行为拟人（三层）— R1-a/b/c

**F1-c：stealth evasions 注入 RPA 窗口**（social-auto-upload 实证的 180KB evasion 包同源）
- **现状证据**：`url-collector.js` 用 `puppeteer-extra-plugin-stealth`；`rpa-view-session.js` 无任何注入（同仓两份标准）
- **实现**：`electron/stealth-preload.js` 扩展为完整 evasions（从 puppeteer-extra-plugin-stealth 提取 MIT 版，与 social-auto-upload 同法），所有 RPA BrowserWindow 已挂该 preload → **自动全覆盖，零接线成本**（现有 preload 挂载点已覆盖）
- **测试**：行为锁（假 session 断言 preload 路径注入）+ 结构锁（evasion 函数清单 ≥ N 项：webdriver/chrome.runtime/permissions.query/plugins/languages/iframe.contentWindow/hairline/outerDimensions…）

**F1-a：真人事件序列**
- **移植源**：social-auto-upload `_native_click`（源码实证）：scroll_into_view → bounding_box → mouse.move → sleep(150ms) → mouse.click → sleep(200ms) → evaluate 补派 pointerover/enter/down/up + mouse 全套（9 字段）
- **落点**：`stealth-helper.js` 新增 `humanizeClick(page,locator)`；rpa 平台的点击路径（`rpa-view-session.js` `_click`）改调
- **测试**：RED——假 page 断言事件**顺序与间隔±50ms**、字段完整性（bubbles/cancelable/composed/pointerId 等 9 项）、失败降级（无 bounding_box 时回落普通 click）；GREEN

**F1-b：贝塞尔鼠标轨迹**
- **移植源**：CloakBrowser `cloakbrowser/human/mouse.py`（MIT wrapper）：三次贝塞尔 + 垂直随机控制点(±0.3dist) + ease-in-out + 步数 clamp + burst 节奏 + sin wobble
- **落点**：`stealth-helper.js` `humanizeMoveTo(page, x, y)`；拖拽类操作（滑块/上传条）优先接入
- **测试**：RED——确定性 seed 下轨迹断言（起终点命中、单调推进、步数范围、单步位移上限）；GREEN；变异反证：摘 wobble/改线性必须变红

### F2：CDP 边信道收敛 — R2（patchright 思路）

**前置 spike（0.5 天，先做）**：验证 Electron `webFrame.executeJavaScriptInIsolatedWorld`（或 `webContents.executeJavaScript` + isolated world API）语义与 patchright `isolatedContext/utilityContext` 等价性；不等价则本 F 降级为「webdriver 双保险 + CDP 调用时序抖动」
- **主实现**：`rpa-view-session.js` 的 `executeJavaScript` 调用点评估迁移 isolatedWorld；评估 `pageBinding`/`exposeBinding` 是否留痕（patchright browserContextPatch 同点）
- **测试**：RED——结构锁（源码断言无裸 executeJavaScript 主世界调用残留）+ 行为锁（假 webContents 断言走 isolated API）；GREEN；真机取证：发布导航期间 main world 无自动化脚本痕迹
- **风险**：V8——不等价即降级，不硬上

### F3：camofox 隐身浏览器通道 — R3（改选）

- **组件**：`@askjo/camofox-browser`（MIT，v1.18.1）npm 依赖 + postinstall 自动下载 Camoufox 二进制到 `%LOCALAPPDATA%\camoufox\camoufox\Cache`
- **落点**：新增 `electron/services/sidecar-host.js`（通用 sidecar 宿主：spawn/健康检查/端口分配/退出清理/下载 delegating）+ `stealth-channel-camofox.js`（发布任务专用驱动）；rpa-view-manager 增加 `channel:'stealth'` 路由（平台→通道映射表，douyin/xiaohongshu/shipinhao 默认）
- **行为层复用**：F1 的 humanize 系列适配 Firefox CDP（API 同名，预期零改）
- **测试**：RED——sidecar-host 单测（spawn 失败/端口冲突/异常退出清理/下载失败降级）+ 路由单测（映射表+缺省）+ 降级锁（sidecar 不可用 → 回落 Electron 通道并 warn，禁静默）；GREEN
- **验收**：QM-1 打包后二进制就绪；真机 A/B：高风控平台风控拦截率对比（n≥10，记 PRD）；国内网络下载失败演练（V2）
- **红线**：Firefox 内核**不进** rpa-view-manager 池（独立进程+V4）；频控仍走 task-queue

### F4：DDDOCR 验证码 sidecar — R4

- **组件**：ddddocr（MIT）——**直接用其自带 `api/server.py`（FastAPI 8 端点 + MCP）**，python-backend 托管子进程
- **落点**：`electron/services/captcha-solver.js`（检测→截图→HTTP `/slide_match`→轨迹换算→F1-b 拖拽→失败升级）；python-backend `publishers/` 新增 captcha 托管路由
- **测试**：RED——solver 单测（sidecar 不可达 fail 人工；置信度阈值；频控 ≥5min/账号/次；坐标换算精度）；GREEN；夹具图 `electron/tests/fixtures/captcha/`（滑块 5 张+点选 3 张）
- **验收**：夹具识别 ≥95%；人工兜底 E2E；单测全绿
- **红线**（V6）：仅本人账号；无限自动破解禁止；PRD 明示 ToS 边界

### B1 共用产出
- `sidecar-host.js` 契约（B2 的 STT/clone sidecar 复用）：`start(manifest)/health()/stop()/onExit`，manifest 含 hash/url/license/最小体积

### F5：本地 STT provider — R5+R7

- **契约移植**（SmartSub `TranscriptionEngineAdapter` 实证）→ 本项目 provider 适配器：
  ```
  { id:'local-whisper', displayName, requiresRuntime, pyEngineId?,
    isAvailable(): {status, reason}, transcribe(ctx), cancelActive(), prewarm?() }
  ```
- **引擎两档**：`whisper.cpp` 二进制（media-tools 同范式：`media-tools-lock.json` 加条目，sha256+license 原文）/ `faster-whisper` python sidecar（`/api/asr/*`）
- **下载器**：`speech-model-manager.js` 抄 SmartSub 模式——断点续传状态 json、并行分片、HF 镜像 host、inactivity 60s/connect 30s 超时、进度广播、Apple Silicon 分支；**模型按需下载不捆绑**（QM-1）
- **测试**：RED——provider 契约（模型缺失/降级/超时/取消）+ 下载器（断点/分片/镜像/失败重试）+ 打包结构锁（lock 条目存在）；GREEN；**真机**：隔离 userData 转写 30s 中文音频，捆绑 ffprobe 验证输出
- **验收**：与云 STT 统一计费/超时口径；GPU 探测降级链路通

### F6：本地 TTS 与声音克隆 — R6（v3 分层修正）

**轻档（默认，先落）**：**Kokoro-82M JS**（hexgrad/kokoro，Apache-2.0）
- 形态：`onnxruntime-node`（MIT）+ Kokoro onnx 模型（~350MB 按需下载）——**Electron 主进程内直跑，零 Python 依赖**
- 实证：`blankarrayy/ttsbro`（Apache-2.0）证明 sherpa-onnx + Kokoro 可纯 WASM 运行
- 测试：RED——合成单测（长文本分段/多音字不崩/采样率 48k 输出）+ 性能锁（CPU 实时率 ≥1x）+ 模型下载 hash 锁；GREEN
- 验收：30s 中文段落合成 <5s（CPU）；输出 wav 48k 与云 TTS 格式一致

**重档（可选，后落）**：GPT-SoVITS（MIT 确认，权重许可逐文件审计后）+ piper
- 状态机：上传样本(≥60s 有效语音)→校验→推理→音色列表→试听→设默认；UI 设置页
- 测试：RED——状态机（样本校验失败/超时/失败回滚）+ UI 链路；GREEN
- **XTTS-v2 出局**（权重 CPML 禁商用）

**红线**：克隆仅限用户本人语音（隐私声明进 PRD+UI）

### F7：硬字幕烧录 — R7

## 批次 B3+：协议轨与供应链补强（第 6-7 周，v3 新增）

> worktree：`mp-oss-protocol-chain`。与 B3 无代码依赖可并行。PRD：`01-docs/PRD-OSS-PROTOCOL-CHAIN-2026-10-XX.md`

### F11：协议轨 TLS 指纹 impersonation — v3 新增（G2-b）

- **组件**：`impers`（lexiforest，MIT，TS，Node 版 curl-impersonation）主选；`curl_cffi`（MIT，Python）作 python-backend 侧备选
- **背景**：百家号/头条/B站 HTTP API 风控查 JA3 TLS 指纹——Node 原生 https 的 ClientHello 与 Chrome 迥异，协议轨 API 发布被 403 时 JS 层伪装无效
- **落点**：`packages/api-publish-engine` 传输层按平台切换 impersonating client（仅风控平台开启，普通平台走原生，控制新增原生依赖面）
- **测试**：RED——传输层选择锁（平台→client 映射、缺省原生）+ 真实 TLS 指纹断言（本机回显服务抓 ClientHello 特征，按项目「出站行为以线级取证为准」纪律）；GREEN
- **红线**：libcurl 原生二进制进生产依赖闭包——`npm pack --dry-run` + 隔离安装加载验证（项目「生产依赖闭包」纪律）；体积预算写 PRD
- **附注**：`ylcangel/douyin_sign`（Apache-2.0）抖音 web a_bogus/x-bogus/msToken 算法——仅当未来加抖音协议轨时启用，需单独 PRD + 风险标注

### F12：视频下载通道（yt-dlp + BBDown）— v3 新增（G6 配套）

- **组件**：**yt-dlp**（197k⭐，**Unlicense 公有领域**——最宽松档，可放心捆绑）+ **BBDown**（MIT，B站专用备份）
- **落点**：按 media-tools 同范式进 `extraResources`（版本+sha256 锁定，QM-1 媒体工具纪律）；消费方：①collection-engine 视频 URL 素材采集；②F10 回流时下载自有作品做存活自证；③story2video 素材来源
- **测试**：RED——下载器封装（URL 白名单/大小上限/取消）+ 结构锁（lock 文件条目）；GREEN；真机：B站/百家号各下 1 条
- **红线**：仅下载有权限的内容（本人作品/已授权素材），频控遵守既有 RateLimiter；不作批量爬取他用
- **附注**：RSSHub（46.5k AGPL）——hot-topics/content-intelligence 的内容源增强，**仅限未修改独立服务直跑**，改一行即触发开源义务；node-ytdl-core 停更不选

### F13：自建代理池 — v3 新增（G7）

- **组件**：jhao104/proxy_pool（23.8k，MIT）
- **背景**：同 IP 高频发布多账号是平台风控的核心判据（G7）——camofox 内置代理轮换之外，自持代理池应对重度场景
- **落点**：部署层组件（ops-center/docker-compose 或用户自填代理列表），Electron 侧仅消费「代理列表 API」；**不做进安装包**
- **测试**：RED——消费侧（代理列表获取/失效剔除/按任务分配/失败重试）；GREEN
- **红线**：代理来源合规性由用户自持（工具不内置获取渠道，仅对接用户自有或合规供应商）；PRD 明示边界

## 决策结论（2026-10-13，详见《决策点分析与建议-2026-10-13.md》）
