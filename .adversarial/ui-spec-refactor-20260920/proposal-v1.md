# UI 设计规范与组件库建设 - 方案 v1

**提案方**: Anthropic Claude  
**日期**: 2026-09-20  
**版本**: v1.0  

## 方案概述

本方案旨在偿还 Multi-Publish Electron 桌面应用的技术债务，核心目标为：

1. **建立统一的 UI 设计规范文档库**（Design Tokens + 组件规范 + 页面模板 + 动效规范）
2. **抽离可复用的组件库**（基础组件 + 业务组件 + 逻辑封装）
3. **建立 Electron 测试规范**（跨平台 E2E 测试 + 核心功能测试）
4. **性能优化指南**（内存/启动/渲染性能）

## 核心设计决策

### 决策 1: 目录结构设计

```
packages/
├── ui-design-tokens/          # 设计令牌包（npm 发布）
├── ui/                        # 主组件库（@multi-publish/ui）
└── ui-business/               # 业务组件包（@multi-publish/ui-business）
```

**理由**:
- 分离设计令牌与组件实现，便于独立发布
- 主组件库专注于基础 UI，业务组件专注页面级复用
- 符合 Monorepo 最佳实践

### 决策 2: 技术选型

| 工具 | 选择 | 理由 |
|------|------|------|
| 构建 | Vite | 速度快、ESM 原生支持 |
| 文档 | Storybook 7.x | 组件开发标准、生态丰富 |
| 测试 | Vitest + Playwright | 单元测试+E2E 全覆盖 |
| 类型 | TypeScript Strict | 类型安全、IDE 友好 |

**理由**: 均为当前前端领域主流工具链，社区活跃、文档完善。

### 决策 3: 迁移策略

采用**渐进式迁移**而非大爆炸重构：

1. 先实现基础组件（Button/Input/Card...）
2. 新页面直接使用新组件库
3. 旧页面逐步替换（按优先级排序）
4. 视觉回归测试确保无破坏

**理由**: 降低风险、可随时回滚、不影响现有业务。

### 决策 4: 性能优化重点

优先解决**内存泄漏**和**启动速度**：

- 内存：事件监听器清理、WebSocket 断开管理
- 启动：ASAR 分包、Route-based code splitting
- 渲染：Transform 替代 Top/Left、GPU 加速

**理由**: 这两个问题对用户体验影响最大。
